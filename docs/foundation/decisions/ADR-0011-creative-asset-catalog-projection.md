# ADR-0011：统一创作资产目录采用只读投影

状态：Proposed

日期：2026-08-05

决策者：产品、平台架构、内容运营与安全联合评审

关联：[创作资产目录领域与投影规范](../../product/creative-asset-library/02-domain-and-projection.md)

## 背景

现有系统分别拥有 Source、SourceRevision、Asset、RightsRecord、KnowledgeObject、ApprovedSnapshot、Artifact 和 DeliveryPackage。客户需要统一资产库，但这些对象的正文、生命周期、权利、版本和批准规则不同。

若创建一个可写超级 `Asset` 并复制所有对象内容，会形成第二套事实、失效状态和权限模型，且难以保证批准、权利和交付历史同步。

## 决策

采用 `CreativeAssetCatalogItem` 只读投影统一展示和检索现有事实对象。

- 现有 `Asset` 保持“受权利约束的参考素材”语义。
- 目录项保存确定性 ID、显示摘要、受控预览、底层对象引用、版本摘要、权利摘要、派生可复用状态和投影游标。
- 目录项不复制业务正文，不拥有来源、权利、批准、文件和交付状态。
- Runtime 和 WorkTask 使用底层 `subject_ref + version + digest` 作为正式输入，目录 ID 只用于产品追溯。
- 投影可删除和重建，重建不得触发模型、执行者或外部副作用。

## 备选方案

### 扩展现有 Asset 为所有内容的统一聚合

收益是名称直观、查询表面统一。代价是破坏现有参考素材语义，把批准内容、生成文件和交付包强行纳入一个生命周期，并形成大范围迁移和兼容风险。不采用。

### 为每种对象分别建设客户页面

收益是领域边界最直接。代价是客户仍需理解内部对象，跨任务搜索、复用和统一状态无法成立。不采用。

### 只在前端临时聚合多个 API

收益是初期实现快。代价是权限、分页、去重、失效和状态翻译分散到客户端，无法形成稳定契约。不采用。

## 事实所有权与边界

- Source & Knowledge 拥有来源、知识、参考素材和权利。
- Review & Approval 拥有批准快照和决定。
- Artifact & Delivery 拥有生产文件和交付包。
- Experience / Projection 拥有目录读模型和角色适配 DTO，但不拥有正文。
- Work Management 通过版本化 `CreativeAssetRef` 固定任务输入。

## 兼容与迁移

- 先从现有对象旁路构建目录，不改变现有写路径。
- 以 `ProjectProjection` 和 lineage 现有模式作为迁移基础。
- 新客户入口在 Feature Flag 下启用，旧“品牌资料”入口保留兼容路由。
- 目录稳定后，新任务选择器改为读取统一目录；现有对象 API 继续供拥有域使用。

## 安全与运行影响

- 客户 DTO 必须裁剪内部 ID、ObjectKey、敏感路径和 Restricted 预览。
- 危险命令必须回源校验权限、权利和当前版本，不能只信最终一致投影。
- 权利到期和来源失效需要更新投影并产生下游影响查询。
- 投影延迟、重建错误和游标必须可观测。

## 验证

- 相同事实和事件重放产生相同目录摘要。
- 同一底层对象不生成重复目录项。
- 跨租户、权利过期、来源撤回和敏感预览测试通过。
- 投影重建不触发任何外部调用。
- 客户可以完成“资产库 -> 固定引用 -> 新任务”的 E2E。

## 回退

关闭新引用命令和客户资产库入口，恢复旧页面读取；继续保留旁路投影用于对账。已写入 WorkTask 的底层对象引用保持有效，不删除历史目录和审计记录。

## 后果

正面后果：统一客户体验而不破坏事实所有权，目录可重建，可渐进交付。

负面后果：需要投影延迟、重建和回源校验机制；一次查询不能直接依赖单一业务表。

新增约束：任何希望进入资产库的新对象类型都必须先明确事实所有者、版本引用、收录规则、失效规则和权限裁剪。
