# ADR-0013：客户创作资产以生成结果为中心

状态：`Accepted`

日期：2026-08-07

决策者：产品、内容运营、平台工程与设计

关联：

- [ADR-0011：统一创作资产目录采用只读投影](./ADR-0011-creative-asset-catalog-projection.md)
- [ADR-0012：客户资产库信息架构](./ADR-0012-customer-asset-library-information-architecture.md)
- [创作资产库产品需求](../../product/creative-asset-library/README.md)

## 背景

旧设计把来源、灵感、参考素材、知识对象、权利记录和流水线生成结果都称为“资产”。这在后台治理上可以成立，但在客户页面上会产生错误心智：客户无法判断什么是本次创作的输入，什么是已经生成、确认并可以继续使用的成果。

外部产品也没有完全统一“asset”一词，但成熟系统都会把生成结果、上传输入、版本、审批和血缘分开管理。ContentCloud 面向的是具体创作任务，因此客户侧需要更严格、可操作的定义。

## 决策

### 1. 客户术语分为三类

| 客户名称 | 包含内容 | 主要入口 | 是否进入客户创作资产库 |
| --- | --- | --- | --- |
| 创作输入 | 来源资料、搜索结果、灵感、知识、参考素材、权利记录和用户上传文件 | 当前任务、项目参考 | 否 |
| 创作资产 | 流水线生成的人物原型、剧本、分镜、图片和视频结果 | 创作资产库、当前任务结果 | 是 |
| 交付作品 | 已整理、核对并下载的交付包或交付文件 | 交付 | 以交付视图引用，不复制资产事实 |

“草稿”“待确认”“需修改”“已确认”“已交付”“已被替代”“已阻止”是结果状态，不是资产类型。对应契约值为 `draft / pending_confirmation / changes_requested / confirmed / delivered / superseded / blocked`。只有 `confirmed` 和 `delivered` 的结果可以作为新任务的正式复用输入；其他状态可以按权限查看，但不能绕过门禁复用。

### 2. 客户产品面与运营产品面分离

```text
客户任务输入 / 项目参考
          |
          v
   Content Work OS 创作任务
          |
          v
人物原型 / 剧本 / 分镜 / 图片 / 视频
          |
          v
     客户创作资产库
          |
          v
       下一次创作

来源、知识、权利、Runtime 事件和完整血缘
          |
          v
       运营控制台
```

客户 API 不暴露 `Source`、`KnowledgeObject`、`RightsRecord`、`ApprovedSnapshot`、`Artifact` 等治理对象名称。运营人员仍然可以从结果追溯到这些底层事实。

### 3. 目录使用生成结果投影，不创建超级 Asset

客户资产 DTO 至少包含：

```text
ref / result_type / project / task / title / summary
version / status / reusable / blocked_reason
downloads / created_at
```

底层输入引用只保存在服务端，用于加入任务时的版本、摘要、权利和租户校验；它不作为客户列表的分类依据，也不作为客户页面的可见类型。

## 收录规则

- 人物原型、剧本、分镜、图片和视频等流水线结果创建后可以进入目录。
- 草稿、待确认和需修改结果可以在历史中显示，但 `reusable=false`。
- 已确认或已交付结果显示为可复用创作资产。
- 图片或视频 Artifact 没有任何审核记录时默认是 `pending_confirmation`；缺少审核事实不能被解释为已经确认。
- 搜索返回、临时候选、人工灵感和任务输入只保留在任务或项目参考范围。
- 交付包从交付事实生成交付视图，不能复制成另一份资产正文。
- 目录投影重建不得触发模型、执行者或外部服务。

## 影响

- 客户资产页的一级筛选固定为：全部、人物原型、剧本、分镜、图片、视频。
- 状态筛选独立于类型筛选：草稿、待确认、需修改、已确认、已交付、已被替代、已阻止；页面可以将其聚合成“需要处理”等业务视图，但不能改变契约状态。
- 灵感采集页的保存动作改为“保留为项目参考”，不再写入客户创作资产库。
- 资产详情保留来源任务、项目、版本和血缘摘要，但不要求客户理解治理对象。
- 运营控制台继续管理来源、知识、权利、目录收录和失效传播。

## 迁移与回退

- ADR-0012 的客户分类方案保留为历史记录，并由本 ADR 取代客户侧分类决策。
- 旧分类和旧 API 字段在兼容期只做读取映射，不继续产生新的输入型资产目录项。
- 现有输入引用不删除；它们迁移到任务输入或项目参考投影。
- 关闭新资产投影时，历史任务和已写入的底层引用保持可审计，不回退业务事实。

## 验收标准

1. 客户不需要理解来源、知识或权利对象，也能找到一个生成结果并开始新创作。
2. 资产页不出现来源、资料、灵感或治理对象分类；这些内容只在任务输入或项目参考中出现。
3. 生成结果的类型、版本和状态可以独立筛选，状态不能改变结果类型。
4. 只有已确认或已交付结果能被服务端接受为新任务的可复用输入。
5. 运营人员可以从客户结果追溯到输入、执行、批准和交付事实。

## 参考模式

- Camunda 8：Web Modeler、Orchestration Cluster、Job Workers、Tasklist 和 Operate 分离。
- Dify：运营人员编排 Workflow，发布为客户 Web App/API，结果和人工输入由应用层承接。
- Adobe GenStudio：Assets、Experiences、Templates、Create 和 Reviews/Approvals 分层。
- Runway、Frame.io：生成结果血缘、版本堆叠和审核状态分轴管理。
