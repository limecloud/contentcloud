# ADR-0012：客户“品牌资料”演进为“创作资产库”

状态：Proposed

日期：2026-08-05

决策者：产品、设计、内容运营与平台工程联合评审

关联：[创作资产库产品需求](../../product/creative-asset-library/01-product-requirements.md)

## 背景

“品牌资料”可以承载品牌和产品输入，但无法表达人物原型、灵感参考、批准剧本、媒体成果和已交付作品。客户需要在任务之间复用这些内容，同时继续通过独立“交付”入口完成当前任务的完整性核对和下载。

## 决策

客户一级导航中的“品牌资料”演进为“资产库”。

首期分类为：品牌与产品、人物与形象、灵感与参考、剧本与内容、图片音频与视频、已批准成果、已交付作品。

前五项是内容主分类，后两项是可重叠系统集合。一个对象可以出现在主分类和多个集合中，但底层事实和目录项仍然只有一份。

- “资产库”负责跨任务积累、查找和复用。
- “交付”负责当前任务的待确认结果、完整性和交付包。
- 旧“品牌资料”路由在迁移期重定向或映射到资产库的“品牌与产品”分类。
- 客户页面不暴露 Source、Asset、ApprovedSnapshot 和 Artifact 等底层对象名。

## 备选方案

### 保留品牌资料并新增成果库

收益是迁移较小。代价是客户需要在多个入口猜测素材、批准结果和交付作品的位置，复用路径继续碎片化。不采用。

### 资产库同时取代交付

收益是一级导航更少。代价是跨任务复用和当前任务交付两个不同心智被混合，客户难以判断正式交付是否完整。不采用。

### 在每个任务内提供历史选择器

收益是无需新一级入口。代价是客户无法主动整理和理解长期积累，也无法从资产直接开始创作。不采用。

## 事实所有权与边界

信息架构变化只改变客户产品投影和路由，不改变底层事实所有权。资产库读取统一目录投影，交付读取当前任务及 DeliveryPackage 投影。

## 兼容与迁移

- 旧“品牌资料”链接映射到“资产库 / 品牌与产品”。
- 保留现有书签和深链接的兼容期，记录访问量和迁移提示。
- 新资产库先对试点租户启用；没有目录数据时仍可通过现有上传和任务入口工作。
- 对外用户文档只在页面真实可用后更新产品名称和操作步骤。

## 安全与运行影响

- 客户只看到本租户和授权项目范围内的目录项。
- 资产库预览与交付下载使用不同权限和短期授权。
- 客户不能从资产库直接修改权利、批准或交付状态。

## 验证

- 客户在两次主要操作内找到可复用资产或理解无结果原因。
- 客户能区分“用来开始新创作”和“下载当前任务交付包”。
- 旧路由兼容、跨租户负向测试、移动端和无障碍验收通过。
- 试点任务的资产复用率提高，重复上传率下降。

## 回退

关闭资产库导航 Feature Flag，恢复旧“品牌资料”入口；统一目录和已创建引用继续保留，不回滚业务事实。

## 后果

正面后果：客户获得稳定的长期积累心智，每次完成任务都能缩短下一次创作路径。

负面后果：需要明确资产库与交付的文案和路由边界，并迁移旧深链接。

新增约束：任何新增客户资产分类必须对应稳定业务语义和收录规则，不能因某个页面临时需要随意增加一级分类。
