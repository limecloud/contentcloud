# ContentCloud 平台基线重构总计划

状态：`平台基线已建立；Studio、知识库、资产首切片与 Runtime current 主链已落地，生产验证和运营配置持续推进`。

更新时间：2026-08-09。

## 1. 目标

本计划首先解决三个业务问题：客户无法在不理解内部概念的情况下完成一条真实创作流水线；完成任务后无法把历史来源、批准内容和成果直接复用到下一次创作；平台运营人员也无法用可预测的成本持续发布、维护和治理更多创作场景。架构重构是解决这些问题的手段，不是独立目标。

ContentCloud 将从“功能持续叠加的内容工作台”收敛为一套可以长期演进的内容创作平台基线。完成后，未来新增人物原型、剧本、分镜、营销视频、公众号文章或其他创作流水线，应主要增加业务包、契约和客户体验模板；Runtime 核心仍允许通过兼容版本演进，但不得因每个新场景复制任务状态或重做整套页面。

本轮已完成平台分层、业务边界、Runtime 接入和资产入口的工程基线，并落地了首个客户资产纵向切片；Runtime 执行事实已接管，运营流水线配置、真实 Provider、在线宿主演练、生产故障与容量验证仍属于后续工作。任何现状判断以代码、迁移和测试为准，本文中的目标模块、目录、API 或页面不得被理解为全部已经实现。

## 2. 当前落地对账

- 客户 Web Studio 已作为默认客户入口，任务、连接、交付和资产页面使用独立客户读模型。
- 客户资产首切片已提供“我的资产 / 创作结果 / 最近使用”三个视图；工作区资料与生成结果保持两个专用投影，不创建万能 `Asset` 写模型。
- Memory Store、PostgreSQL Store、客户 BFF 和迁移 `00017_workspace_materials.sql` 已覆盖文件夹、工作区资料、受控预览、资料引用和结果复用门禁。
- Runtime 的 JobRun、NodeRun、RuntimeAttempt、ContextView、AgentInstance、状态 CAS、Effect、受限动态图、Codex CLI JSONL/thread resume Harness 和 Runtime Explorer 已有内核实现；V7 执行表、命令链和零消费者 session 镜像已删除，真实 Provider、在线 Codex/Claude 与生产级故障、隔离、容量验证仍按 V8 路线推进。
- 运营控制台的流水线发布、执行能力绑定、租户覆盖和运行诊断仍是目标架构与迁移工作，不向客户面板暴露内部配置对象。

## 3. 已确认前提

1. 客户创作台、平台运营控制台和运行诊断台是不同产品面，使用独立 Shell、路由、权限和信息架构。
2. ContentCloud Agentic Job Runtime 是唯一执行事实源，但不是业务超级聚合。来源、知识、提交、审批、产物和交付事实仍由各自业务域拥有，Runtime 只保存版本化引用和执行结果。
3. Codex、Claude Code、ContentCloud Worker、外部服务商和人工都是可治理的执行者，不是平台本身。
4. 创作流水线声明业务阶段、输入输出、能力和门禁；具体执行者由版本化策略绑定。
5. 客户只理解目标、资料、进度、结果、确认和交付，不理解 Runtime 内部术语。
6. 现有业务领域对象、SOP、Gate、RuntimeAttempt、来源、证据、提交、批准快照、产物和交付能力按当前所有权优先复用；已删除的 V7 RunAttempt 不得恢复。
7. 本轮采用渐进迁移，不进行停机式大重写，也不提前拆成分布式微服务。
8. 客户创作台是默认客户入口；Codex、Claude Code 等本地客户端是高级执行面和可选执行者，不再承担客户必须理解的主产品导航。
9. 客户“资产”是统一入口而不是统一写模型：我的资产投影客户明确上传/导入的工作区资料，创作结果投影人物原型、剧本、分镜、图片和视频；任务参考与交付保持独立。正式引用固定底层对象版本和摘要，不创建超级 `Asset` 聚合。

## 4. 方案比较

| 方案 | 内容 | 完整度 | 主要风险 | 结论 |
| --- | --- | --- | --- | --- |
| A. 只补客户创作台 | 在现有工作台上增加简单页面和几个场景接口 | 3/10 | 很快再次复制状态、权限和流程逻辑 | 不采用 |
| B. 产品层适配 | 增加客户 BFF、体验模板和少量 Runtime 适配 | 7/10 | 可交付首个场景，但代码和领域边界仍可能继续漂移 | 作为迁移阶段，不作为终态 |
| C. 平台基线重构 | 同时冻结产品平面、业务域、Runtime、代码边界、契约、质量和迁移规范 | 10/10 | 前期设计和迁移治理成本较高 | 采用 |

最终策略不是一次性选择一个方案，而是分层采用：

```text
长期架构宪法：C 平台基线重构
生产迁移路径：B 产品层适配，客户 Web 旧入口已清理
客户价值验证：A 简单客户创作台的真实纵向切片
```

实施方式保持渐进式：先建立事实地图和契约，使用现有线性能力交付客户切片；新 Runtime 通过旁路比较和契约测试演进。客户 Web 路由不再保留旧 Shell 兼容层，服务端 BFF 仅为仍有真实 CLI/Agent 调用的契约保留。

## 6. 产品定位迁移

当前 README 将产品描述为本地优先、主要在 Codex 或 Claude Code 中创作。目标基线调整为 `Studio-first`：

- 客户默认在简单的 Web 创作台选择场景、提交资料、查看进度、确认结果和取得交付。
- 客户对外叙事中心统一为 Content Work OS 创作任务，而不是 ContentCloud Agent 或某个第三方执行者。
- 客户通过一个资产入口管理上传/导入的工作区资料，并查找、复用人物原型、剧本、分镜、图片和视频结果；搜索候选、灵感与来源证据保留在任务输入或项目参考，正式交付包通过“交付”入口核对和下载。
- 本地 Codex、Claude Code 和 MCP 保留为处理本地资料、复杂研究、策略和创意修订的高级执行面。
- 本地客户端不能保存云端任务权威状态，也不能成为客户理解产品的前置条件；当前首切片可以把“项目已连接受支持的创作电脑”作为创建新任务的技术准入条件，并在客户页面用一个简单连接动作表达。
- 现有本地优先流程在迁移期继续可用，通过同一任务契约和 Runtime Adapter 接入，不另建平行产品。
- 面向用户的定位、README、文档和导航只有在对应能力真实可用后才分阶段更新，不提前宣称目标功能已经上线。

该定位属于长期产品决策，必须进入 ADR，并给出旧入口的 `保持 / 兼容 / 废弃 / 退场` 策略。

## 7. 价值指标和停止条件

### 6.1 客户价值

- 从创建任务到首个可确认结果的时间。
- 不阅读帮助文档完成首个场景的比例。
- 每个客户阶段的完成率、退回率和人工求助率。
- 客户可以识别当前状态和唯一下一动作的任务比例。
- 新任务资产复用率、资产查找时间和重复上传下降比例。

### 6.2 运营经济

- 从已批准业务包到发布一个 ExperienceTemplate 的时间。
- 新增第二条结构不同的流水线需要修改的 Runtime 核心文件数量，目标为零。
- 模板复用率、每租户覆盖项数量、运营人工介入率和单任务成本。
- 流水线 Canary、回退和故障定位所需时间。
- 资产目录投影延迟、失效传播时间和每百个目录项的人工治理量。

### 6.3 停止条件

- 首个纵向切片未改善客户完成率或首个结果时间时，不扩大 Runtime 通用性范围，先修正产品体验。
- 第二条流水线仍需要新增内容类型专用调度状态时，停止扩展业务包，重新评审 Runtime 契约。
- 兼容层没有明确退场条件或新旧状态无法对账时，禁止继续迁移下一阶段。
- 运营发布成本随模板数量线性失控时，停止增加租户定制，收敛体验原语和覆盖策略。
- 资产目录随原始候选无限增长、复用率没有改善或治理量线性失控时，停止扩分类和智能检索，先收紧收录规则。

## 9. 实施原则

1. **先事实地图，后目标目录。** 先证明现有对象和调用链，再决定搬迁或拆分。
2. **先契约，后实现。** 先冻结跨边界输入输出、状态和错误，再并行开发模块。
3. **单一事实源。** 禁止客户侧、运营侧、Agent 会话或本地文件维护第二套任务状态。
4. **兼容层必须有退场条件。** 每个 Adapter 都要记录来源、目标、删除门槛和最晚清理阶段。
5. **模块化单体优先。** 先通过包、接口、数据库权限和 API 边界获得隔离，只有指标证明需要时才拆服务。
6. **一个真实纵向切片验证抽象。** 首个切片为“灵感采集 → 客户选择 → 固定下游输入”。
7. **第二种不同业务流验证通用性。** 至少再用一种结构不同的内容流程证明 Runtime 没有业务硬编码。
8. **发布能力按事实声明。** 目标架构、预览、已实现和已投产必须明确区分。
9. **先客户切片，再扩大通用性。** 不允许把客户价值推迟到大部分 Runtime 完成之后。
10. **事实所有权不可越界。** Runtime 协调执行，业务域拥有业务事实；投影只读，执行者只提交候选或节点结果。
11. **限制运营配置空间。** 运营人员组合已批准的体验原语、业务包和能力，不维护任意脚本或不可测试的自由工作流。
12. **每次创作形成平台复利。** 流水线生成结果进入可重建目录，确认状态决定能否复用；项目参考和交付包保持独立投影，新任务引用已有事实，不复制正文或绕过治理。

## 10. 退出条件

- 文档给出稳定产品平面、业务域、系统组件、代码模块和依赖方向。
- 每个核心对象有唯一所有者、生命周期、权威状态和版本规则。
- 新流水线扩展有固定的 Schema、能力、执行绑定、门禁和发布流程。
- 目标目录与现有目录有逐项迁移映射，不要求一次性移动全部代码。
- 客户、运营、Runtime 和执行者的 API 与权限边界可以编写契约测试。
- 测试、可观测性、安全、迁移、Canary 和回退规则具有可执行门槛。
- 客户创作台与灵感采集需求引用同一基线，不再定义平行模型。
- 客户资产需求明确工作区资料、创作结果、固定引用、失效传播和运营治理，不把目标能力写成已上线。
- 所有未决策项被记录为 ADR 候选，不隐藏在实现细节中。
- 现有对象与模块处置矩阵覆盖所有核心对象、Store 接口、应用服务、BFF、Web Shell、契约和本地客户端路径。
- 首个客户切片和第二条不同业务流均有业务指标、运营成本指标和停止条件。

## 11. 明确不做

- 本轮不直接重写生产代码或数据库。
- 不因架构分层立即拆分微服务、仓库或独立数据库。
- 不创建通用低代码工作流市场。
- 不创建企业级 DAM、全盘同步网盘、三维资产画布或任意关系图；最小文件夹、上传/导入、预览和加入创作不在本条排除范围。
- 不允许客户或运营人员上传任意执行代码。
- 不把所有内容类型合并成万能 Schema。
- 不让智能体自动批准事实、权利、费用或正式交付。
- 不把外部交付包描述为外部平台已经发布成功。

## 12. 审查收口与决策记录

本轮基线从产品价值、产品面、领域所有权、Runtime 边界、代码依赖、安全质量、迁移和开发者体验八个角度完成了第一轮收口。当前结论是：该方案可以作为后续实现的目标规范，但仍需通过 ADR、首个客户纵向切片和第二条结构不同的业务流验证，不能直接视为生产设计已经完成。

| 视角 | 已收口结论 | 实现前仍需证明 |
| --- | --- | --- |
| 产品 | Studio-first；客户、租户管理、平台运营和 Runtime Explorer 分面 | 客户无需培训完成灵感采集闭环 |
| 资产 | 结果只读目录引用现有事实；输入和交付保持独立投影，已确认结果供下一任务固定引用 | 跨任务复用降低重复生成和审核，且不污染结果目录 |
| 业务 | Runtime 只拥有执行事实，业务域各自拥有来源、审批、产物和交付 | 聚合与事务边界可由现有对象渐进承接 |
| 工程 | 模块化单体、窄端口、依赖向内，不扩大 Store/Service/types | 架构检查可阻止新越界依赖 |
| 扩展 | 新流水线主要增加 CreativePack、Schema、SOP、能力和体验模板 | 第二业务流不修改 Runtime 核心 |
| 安全 | 执行者、外部内容和回调均不可信，最小披露和 Effect 治理 | RLS、SSRF、Prompt 注入与 unknown 对账通过测试 |
| 迁移 | Strangler、Shadow Compare、Canary、独立权威开关和延后清理 | 新旧摘要一致且可以逐维回退 |
| 体验 | 客户只看到目标、资料、进度、结果、决定和交付 | 各状态、响应式与无障碍通过验收 |
| DX | 统一入口、确定性 Fixture、契约测试和 TTHW 门禁 | 首个业务包验证 30/60 分钟目标 |

已冻结的战略选择：

```text
长期架构宪法：C 平台基线重构
生产迁移路径：B 产品层适配与兼容切流
客户价值验证：A 简单客户创作台纵向切片
```
