# 产品平面与使用边界

状态：`目标规范`。

更新时间：2026-08-05。

## 1. 基本结论

ContentCloud 必须为不同角色提供不同产品面，而不是让所有人进入同一个后台再依靠菜单隐藏复杂度。

```text
客户创作者 / 客户审批人             平台内容运营 / 运行运营
             |                                  |
             v                                  v
      客户创作台                          平台运营控制台
      /studio/*                            /admin/*
             |                                  |
             v                                  v
      Studio BFF                         Operations BFF
             \                                  /
              \                                /
               +------ 领域服务与 Runtime -----+
                              |
                              v
                   Worker / Agent / Provider / Human
```

路由为目标命名空间。现有 `/workspace/*`、`/projects/*` 和相关 BFF 在迁移期通过兼容路由工作，不能在没有迁移记录的情况下直接删除。

### 1.1 客户叙事与平台架构分离

客户对外首先看到：

```text
任务输入与项目参考 -> Content Work OS 创作任务 -> 创作资产、交付和专业工具
```

本文件其余架构图用于说明职责、权限和系统边界，不直接作为官网或客户首图。外部叙事不能把中心写成“ContentCloud Agent”，也不能把 Codex、Claude Code 或某个服务商描述为开始创作的必选前提。完整规则见[产品叙事规范](../product/00-product-narrative.md)。

## 2. 客户创作台

### 2.1 目的

让客户围绕“我要完成什么”工作，而不是围绕 ContentCloud 的内部领域、配置和运行对象工作。

客户只需要理解：

- 可以制作什么。
- 需要提供什么。
- 当前做到哪一步。
- 系统现在需要什么决定。
- 已经得到什么以及如何交付。

### 2.2 一级信息架构

```text
客户创作台
├── 今天
│   ├── 开始新的创作
│   ├── 等待我确认
│   └── 继续上次任务
├── 创作任务
│   ├── 进行中
│   ├── 等待资料或确认
│   └── 已完成
├── 资产
│   ├── 我的资产：文件夹、文档、图片、视频、音频、表格
│   ├── 创作结果：人物原型、剧本、分镜、图片、视频
│   └── 最近使用
└── 交付
    ├── 待确认结果
    └── 已生成交付包
```

客户一级导航不得包含 SOP、运行记录、执行图、Agent、能力、服务商、租户配置、费用对账或系统审计。

资产入口组合“我的资产”和“创作结果”两个专用投影：前者管理客户明确上传/导入的工作区资料，后者跨任务积累和复用生成结果；最近使用只是组合查询。当前任务输入和项目参考由任务页面管理，交付负责当前任务的完整性、确认和下载。详细需求见 [`docs/product/creative-asset-library`](../product/creative-asset-library/README.md)。

### 2.3 客户页面契约

每个客户页面必须由服务端返回：

- `title`：业务标题。
- `outcome`：完成后得到什么。
- `status`：有限的客户状态集合。
- `progress`：业务进度摘要。
- `required_inputs`：当前缺少资料。
- `result_summaries`：当前固定结果版本。
- `primary_action`：唯一主要动作。
- `secondary_actions`：不超过必要数量的次要动作。
- `blocking_reason`：客户可理解的原因和恢复方法。
- `support_reference`：不敏感的支持编号。

前端不得根据文案或底层状态猜测批准、重试、取消和进入下游是否允许。

### 2.4 客户状态

| 状态 | 客户含义 | 主要体验 |
| --- | --- | --- |
| `not_started` | 尚未开始 | 提供开始所需输入 |
| `ready` | 可以开始 | 一个明确主要动作 |
| `working` | 正在处理 | 显示业务进度，不显示底层日志 |
| `needs_input` | 需要补充资料 | 列出缺少内容和允许格式 |
| `needs_decision` | 等待确认 | 固定版本、差异、风险和决定影响 |
| `changes_requested` | 已要求修改 | 说明保留内容和预计下一结果 |
| `blocked` | 当前无法继续 | 说明原因、已保存进度和恢复动作 |
| `completed` | 本步骤已确认 | 展示结果和下游入口 |
| `superseded` | 已被新版本替代 | 默认展示当前有效版本 |

这些状态是客户投影，不取代 Runtime 或业务对象状态机。

## 3. 租户管理面

租户管理员管理自己的组织，不管理 ContentCloud 平台基座。其能力可以位于客户应用的设置区域，但必须与创作任务导航分离。

允许：

- 成员、角色和项目访问。
- 资产访问范围、默认审批人和通知设置。
- 查看本租户已启用的场景和用量摘要。
- 在平台允许范围内选择数据披露和本地执行策略。

禁止：

- 修改平台 SOP、执行图、服务商凭据和能力定义。
- 查看其他租户、完整 Runtime 事件或平台级费用。
- 启用未由平台发布和批准的执行模式。

## 4. 平台运营控制台

### 4.1 内容运营区

- 体验模板的草稿、预览、验证、Canary、发布、回退和停用。
- 客户步骤、表单、文案、结果呈现和动作映射。
- SOP、Schema、业务包、能力和 Gate 的批准组合。
- 租户启用、版本固定和有限覆盖项。
- 创作资产的收录规则、分类、权利待办、失效、重复组和使用影响。

### 4.2 运行运营区

- 执行者、连接器、模型、服务商、区域、预算和健康状态。
- Job、Node、Attempt、Lease、Effect、费用和事件诊断。
- 结果不明对账、人工恢复、暂停、取消和执行分支。
- 指标、告警、审计和运行手册入口。
- 资产目录投影游标、延迟、重建、失败重试和对账。

### 4.3 强制限制

- 控制台不能直接改数据库或“强制成功”。
- 运营动作必须转换为经过授权、幂等和审计的领域命令。
- 不能在页面粘贴任意脚本注册能力。
- 对进行中任务的修复必须保留历史，并创建显式的新决定、Attempt 或 JobRun 分支。
- 平台运营通过管理员角色进入诊断，不通过客户角色取得额外权限。

## 5. Runtime Explorer

Runtime Explorer 是运营控制台中的诊断产品，不是客户功能。它可以与运营控制台使用同一管理员 Shell，但必须拥有独立信息架构和权限检查。

```text
执行实例
├── 业务关联：租户 / 项目 / WorkTask / 体验版本
├── 执行计划：JobPlanRevision / 能力绑定摘要
├── 节点：状态 / 依赖 / 输入输出引用
├── 尝试：执行者 / 租约 / 心跳 / 错误 / 用量
├── 外部操作：请求 / 结果 / 对账 / 补偿
├── 人工门禁：等待者 / 固定版本 / 决定
└── 事件和审计：游标 / 时间 / 关联 ID
```

Explorer 只通过运行读模型查询。任何操作按钮由服务端按当前状态和权限返回，不能成为绕过领域命令的通用控制台。

## 6. 本地 Agent 和开发者执行面

Codex、Claude Code、CLI、Plugin、Skill 和 MCP 为执行与集成表面，不是客户必须使用的主界面。

它们可以：

- 在用户明确授权下读取本地资料。
- 执行当前节点允许的 MCP 工具。
- 生成候选来源、洞察、策略、人物原型、剧本和修订。
- 通过稳定 CLI / MCP 契约提交节点结果和心跳。

它们不能：

- 保存 WorkTask 或 JobRun 权威状态。
- 根据聊天历史推断批准结果。
- 自动提升权限、预算、工具或数据披露等级。
- 直接访问 ContentCloud 数据库和服务商密钥。
- 提交隐藏推理、完整本地路径或完整聊天记录作为正式业务事实。

## 7. 同一状态的两种语言

| 底层事实 | 客户创作台 | 运营控制台 |
| --- | --- | --- |
| 等待执行资源 | 正在等待可用处理能力 | Provider 配额耗尽，资源预留等待 |
| 等待人工 Gate | 有一项结果等待你确认 | `persona_approval` 等待指定审批人 |
| 权利检查失败 | 参考素材缺少使用授权 | `rights.references` 检查失败 |
| 本地执行者离线 | 需要连接本地创作工具 | Workspace binding 心跳过期 |
| 外部结果不明 | 正在核对处理结果，请勿重复提交 | Effect 状态 `unknown`，等待对账 |
| 部分节点成功 | 已保留完成结果，部分内容仍在处理 | N/M Node 完成，失败节点可独立恢复 |

## 8. 交互状态覆盖

| 功能 | 加载 | 空 | 错误 | 成功 | 部分完成 |
| --- | --- | --- | --- | --- | --- |
| 场景列表 | 保持布局稳定 | 说明当前租户未启用场景 | 重试并显示支持编号 | 展示已发布场景 | 预览场景明确标记不可开始 |
| 任务列表 | 骨架保持筛选位置 | 提供开始创作入口 | 保留筛选并可重试 | 显示业务状态 | 已完成和阻断分别计数 |
| 客户步骤 | 说明正在读取的结果 | 说明缺少资料或尚未产出 | 显示已保存进度和恢复动作 | 展示固定版本 | 展示已完成数和剩余数 |
| 结果确认 | 锁定提交动作 | 不显示虚假确认按钮 | 保留输入并解释失败 | 显示决定和生效版本 | 明确哪些内容尚未完成 |
| 资产 | 保持视图、筛选和文件夹位置稳定 | 分别说明如何上传资料或产生创作结果 | 保留条件并提供重试 | 显示资料处理或结果可用状态 | 单个投影失败不伪装为全部资产不可用 |
| 交付 | 核对完整性 | 说明尚无批准结果 | 不把失败写成已发布 | 提供交付包 | 显示可用文件和缺失项 |

## 9. 响应式与无障碍

- 遵循根目录 `DESIGN.md` 的颜色、排版、间距和对象分类色。
- 工作面保持安静、紧凑、可扫描，不使用营销 Hero 或卡片瀑布。
- 桌面支持 `1440 x 1000`，移动端支持 `390 x 844` 和最低 `320px`。
- 主要触控目标不小于 `44 x 44px`；键盘焦点顺序与视觉顺序一致。
- 侧栏在移动端变为可关闭导航，打开后锁定背景滚动并提供可访问名称。
- 状态不能只靠颜色表达；图标按钮提供 `aria-label` 或 tooltip。
- 长标题、支持编号和来源地址不得造成横向页面溢出。
- 异步刷新不得抢走焦点，状态变化使用适度的可访问提示。

## 10. 产品面验收

1. 新客户无需理解 SOP、Agent 或 Runtime，可以从首屏开始真实场景。
2. 客户最多两次主要操作找到当前阻断或待确认结果。
3. 客户无法通过路由、API 或 ID 操作访问平台配置和其他租户数据。
4. 运营人员可以从客户步骤追溯到固定体验、SOP、Job、Node、Gate 和结果。
5. 客户和运营看到的语言不同，但来自同一权威状态和版本。
6. 平台配置发布、回退和停用不会改写进行中的任务。
7. 客户可以在资产入口管理工作区资料并复用已有成果，但不能绕过来源、权利、批准和交付门禁。
