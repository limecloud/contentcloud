# 安全、质量、可观测性与发布门禁

状态：`目标规范`。

更新时间：2026-08-05。

## 1. 信任模型

以下输入一律不可信：

- 客户表单、文件、URL 和手动摘录。
- 网页、搜索摘要、爬虫内容和企业连接器响应。
- Codex、Claude Code、MCP、模型和 Agent 输出。
- 外部服务商回调、状态和媒体文件。
- 本地 Daemon、CLI 和 Workspace 上报。
- 客户端提交的权限、费用、状态和摘要声明。

只有服务端认证、授权、Schema、摘要、范围、版本和业务门禁全部通过后，输入才可以推进。

## 2. 信任边界

```text
Internet / Customer Device / Provider
        |
        v untrusted
Transport validation
        |
        v authenticated actor + tenant scope
Application command
        |
        v domain authorization + version + idempotency
Business / Runtime state
        |
        v minimum ContextView + short-lived lease
Executor
        |
        v untrusted result, validate again
Candidate / Artifact / Gate
```

每跨越一次边界都重新验证，不能因为请求来自 ContentCloud CLI 或受信 Agent 就跳过。

## 3. 身份、租户和权限

- 用户会话、设备凭据、Workspace 凭据、执行租约和服务商凭据相互独立。
- 所有业务对象包含 tenant scope；项目和任务范围在服务层与 RLS 双重检查。
- 平台管理员不自动取得客户私有正文访问权，诊断读取仍受数据分类和审计限制。
- 执行者权限是租户策略、父任务权限、节点能力和运行配置的交集。
- 客户审批人只能决定配置允许的 Gate，不能修改 SOP 或 Runtime 状态。
- 支持人员使用支持编号关联诊断，不通过猜测内部 ID 访问对象。
- 敏感操作要求最近认证、固定摘要和不可重放的授权上下文。

## 4. 数据分类与披露

| 分类 | 示例 | 默认规则 |
| --- | --- | --- |
| Public | 公开网页、公开产品信息 | 可由批准连接器处理，仍需权利和来源判断 |
| Tenant | 品牌与产品资料、普通项目内容 | 仅本租户和批准执行者访问 |
| Confidential | 未发布策略、客户名单、私有来源 | 默认本地或受控区域，禁止通用服务商 |
| Restricted | 凭据、Cookie、个人敏感信息、合同原文 | 不进入普通 ContextView、日志或模型输入 |

执行绑定不能自动把数据切换到披露等级更宽的实现。任何升级披露必须由明确策略或人工批准。

## 5. Agent 与提示词安全

- 网页、文件和 MCP 返回内容只作为数据，不能覆盖系统策略和工具权限。
- 工具列表、参数 Schema、网络出口和写入范围由 Runtime 发放，Agent 无法自增。
- Prompt 中不注入服务端密钥、数据库凭据、租户令牌和完整本地路径。
- 输出必须通过结构化 Schema、大小、引用、摘要和业务校验。
- 模型拒绝、空输出、截断、无效 JSON 和工具超范围分别记录失败类。
- 不保存隐藏推理；必要诊断只保存安全摘要、工具事件和结果引用。
- Agent 会话丢失时从固定 ContextView 恢复，不依赖聊天历史重建权威状态。

## 6. 搜索、爬虫和文件安全

### 6.1 URL 与网络

- 只允许批准协议和端口。
- 每次跳转重新检查域名、DNS 和最终 IP。
- 阻止私网、链路本地、云元数据、Unix socket 和非 HTTP 协议。
- 防御 DNS 重绑定，连接目标与校验结果一致。
- 限制跳转次数、页面数、深度、频率和总时间。
- 不绕过验证码、付费墙、访问控制和平台反自动化措施。

### 6.2 内容

- 限制响应大小、内容类型、压缩展开比例和解析时间。
- 文件检测 MIME 与声明 MIME 不一致时拒绝或隔离。
- 不可信文件进入 Blob 隔离区，通过允许的处理链后才成为 Artifact。
- HTML、Markdown、字幕和富文本输出按展示上下文转义。
- 来源删除或权利撤回后保留必要审计，但停止用于新任务。
- 资产库缩略图和预览继承底层对象分类；Confidential 和 Restricted 内容不得进入公开索引或无权限缓存。
- 目录显示“可用”不能替代命令时的权利、版本和用途回源校验。

## 7. 外部副作用安全

- 所有计费、生成、发布、发送和删除操作先登记 Effect。
- 使用稳定幂等键；Provider 不支持幂等时，Runtime 仍保持本地请求身份和对账。
- 网络超时进入 `unknown`，禁止直接重复提交。
- 回调校验签名、时间窗口、重放 nonce 和租户/请求关联。
- 费用预留、实际用量和账单差异可对账。
- 补偿动作是新的受审计 Effect，不删除原历史。
- 外部发布成功必须包含平台回执；仅生成交付包不能映射为发布成功。

## 8. 威胁模型摘要

| 威胁 | 可能性 | 影响 | 强制缓解 |
| --- | --- | --- | --- |
| 跨租户 IDOR | 中 | 高 | RLS、范围 Repository、服务层授权、负向测试 |
| Prompt 注入扩大工具 | 高 | 高 | 不可信数据隔离、固定工具清单、输出重验 |
| SSRF / 内网探测 | 高 | 高 | DNS/IP/跳转检查、出口代理、网络测试 |
| Agent 或客户端伪造成功 | 中 | 高 | 服务端租约、Schema、摘要和业务持久化后转移状态 |
| 外部请求重复扣费 | 中 | 高 | Effect 台账、幂等、unknown 对账、费用预留 |
| 本地敏感文件误上传 | 中 | 高 | 默认本地、显式选择、摘要提交、路径脱敏 |
| 服务商回调伪造或乱序 | 中 | 高 | 签名、nonce、请求状态机和顺序容忍 |
| 巨型上下文或媒体耗尽资源 | 高 | 中 | 大小/时间/并发/预算硬限制、流式处理 |
| 运营误配置全租户 | 中 | 高 | 草稿、lint、预览、Canary、双人批准、回退 |
| 投影延迟导致重复决定 | 中 | 中 | 决定摘要 CAS、服务端允许动作、延迟标记 |

## 9. 测试策略

### 9.1 测试层次

```text
                    少量 E2E / 受控真实服务商
                 Studio -> Runtime -> Gate -> Delivery
                /                                  \
          模块集成测试                          安全/故障注入
      Repository / BFF / Worker              RLS / SSRF / Effect
             /                                      \
     大量领域与契约单元测试                 确定性 Fixture / Fake
```

- 单元测试覆盖聚合状态机、Schema、摘要、能力绑定和状态翻译。
- Repository 契约测试同时运行 Memory 和 PostgreSQL 实现。
- 集成测试覆盖命令、事务、RLS、队列、Worker、投影和幂等。
- E2E 只覆盖高价值跨边界流程，避免把所有细节压在浏览器测试上。
- 外部服务使用 Fake、录制 Fixture 和受控测试环境三级验证。
- LLM 输出使用固定 Fixture 和质量 eval，不要求文字完全一致。

### 9.2 必测路径图

```text
客户启动场景
├── happy: 有效输入 -> WorkTask -> JobRun -> 首步骤
├── nil/empty: 缺少必要资料 -> 不创建执行
├── invalid: Schema/租户/模板无效 -> 可操作错误
├── duplicate: 同幂等键 -> 返回原任务或摘要冲突
└── unavailable: 无能力/预算 -> 明确阻断

节点执行
├── Worker 成功
├── Agent 离线 -> 租约过期 -> 新 Attempt
├── 输出无效/空/拒绝 -> 有限重试或阻断
├── 一个分支失败 -> 其他结果保留
└── 两执行者竞争 -> 只有一个租约成功

人工决定
├── 批准固定摘要
├── 请求修改并失效下游
├── 双标签页冲突
├── 权限不足
└── 决定过期或任务已取消

外部副作用
├── 同步成功
├── 429 / 5xx 退避
├── 超时 unknown -> 对账成功
├── 回调重复/乱序
└── 账单差异 / 补偿失败

迁移
├── 旧路径与新投影摘要一致
├── 双写任一失败触发告警
├── Feature Flag 回退
├── 历史版本保持可读
└── 重放不产生外部调用

创作资产复用
├── 保存/批准/交付 -> 目录出现，临时候选不出现
├── 同一 subject 重放 -> 不重复
├── 权利到期/来源撤回 -> 阻止新任务并定位影响
├── 跨租户/Restricted preview -> 拒绝
├── 陈旧页面提交 -> 回源冲突并刷新
└── 投影重建 -> 摘要一致且无外部调用
```

## 10. 发布质量门禁

### 10.1 契约门禁

- 所有 Schema 示例通过校验。
- 新旧 major 兼容策略和迁移 Fixture 存在。
- OpenAPI、Go 类型、前端类型和错误码一致。
- Runtime 不包含内容类型专用分支。

### 10.2 安全门禁

- RLS 和跨租户负向测试通过。
- SSRF、重定向、DNS 重绑定、超大响应和压缩炸弹测试通过。
- Prompt 注入无法扩大工具、数据和输出 Schema。
- 日志、事件、Artifact 元数据和错误中无密钥与受限数据。
- 资产目录跨租户、跨项目、敏感预览、预签名 URL 和搜索索引负向测试通过。

### 10.3 可靠性门禁

- 租约过期、进程终止、重复提交和并发竞争测试通过。
- Effect unknown、对账、补偿和回调乱序测试通过。
- 重放和投影重建不触发执行者或外部副作用。
- 进行中任务在新版本发布后继续使用固定旧版本。
- 权利到期、来源失效和目录延迟不会允许新任务继续使用陈旧资产状态。

### 10.4 体验门禁

- 加载、空、错误、成功、部分完成和权限不足状态完整。
- 客户页面不出现内部术语、原始错误或不可执行按钮。
- 客户可以区分任务输入/项目参考与创作资产；在创作资产内可以区分待确认、可复用、已被替代、已阻止和已交付状态。
- `1440 x 1000`、`390 x 844` 和 `320px` 无横向溢出或动作遮挡。
- 键盘、焦点、读屏名称、对比度和触控目标通过。

## 11. 可观测性

### 11.1 关联

所有日志、指标和事件至少关联：

- `request_id`
- `tenant_id`
- `work_task_id`
- `job_run_id`
- `node_run_id`
- `attempt_id`
- `effect_id`，如适用
- `catalog_item_id` 和底层 `subject_ref`，如涉及资产复用
- `support_reference`

日志中不记录凭据、完整 ContextView、完整外部响应和本地绝对路径。

### 11.2 指标

| 类别 | 指标 |
| --- | --- |
| 客户 | 首结果时间、步骤停留、完成率、阻断率、恢复率 |
| 调度 | ready 数、等待时长、租约过期、执行者利用率、公平性 |
| Agent | 启动/恢复成功、输出校验失败、工具拒绝、会话丢失 |
| Provider | p50/p95、429/5xx、unknown、对账时间、费用差异 |
| 数据 | 投影延迟、CAS 冲突、重放差异、兼容摘要差异 |
| 运营 | 模板发布耗时、Canary 失败、回退时间、人工介入率 |
| 资产 | 复用率、重复上传、目录延迟、重建失败、权利待办、失效传播时间 |

### 11.3 告警

- 跨租户授权或 RLS 测试失败：阻断发布。
- Effect `unknown` 超过服务商对账窗口。
- 投影延迟超过客户动作安全阈值。
- 租约过期率、输出校验失败率或 Provider 错误率突增。
- 兼容双读/双写摘要差异非零。
- 单租户费用、节点数或外部请求异常增长。
- 资产权利或来源失效后仍有新引用创建，或目录游标超过复用安全阈值。

## 12. 运行手册要求

每个 P0/P1 失败模式必须有运行手册，包含：

1. 用户看到什么。
2. 告警和诊断查询。
3. 是否存在外部副作用未知。
4. 可以执行的安全动作。
5. 禁止执行的动作。
6. 何时升级人工、供应商或安全响应。
7. 恢复后如何验证和通知客户。

运营工具不得提供无审计的“直接改状态”捷径。

## 13. 发布与回退

```text
contracts/migrations first
  -> deploy code compatible with old + new
  -> enable shadow read / compile
  -> compare metrics and digests
  -> Canary tenants
  -> expand cohort
  -> switch authority
  -> observe full window
  -> deprecate old writes
  -> retire compatibility later
```

回退优先通过 Feature Flag 和权威路径切换完成。数据库破坏性清理不与功能切流同一发布，确保旧代码在兼容窗口内仍可运行。
