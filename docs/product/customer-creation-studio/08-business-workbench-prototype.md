# 业务工作台 UI 原型说明

状态：`可评审原型；不连接 API。生产页面已落地对应四类首方 feature，但本文件不作为运行时能力证据`。

更新时间：2026-08-23。

原型入口：[business-workbench-prototype.html](./prototypes/business-workbench-prototype.html)。

关联规范：[业务工作台层 UI 设计](./07-business-workbench-ui-design.md)、[设计系统](../../../DESIGN.md)、[产品分层架构](../../../diagrams/contentcloud-product-layered-architecture.svg)、[代码组织与插件层](../../foundation/04-code-organization.md)。

## 1. 原型目的

这个原型先回答产品决策，而不是提前解决 React 路由、API schema 或数据加载：

- 平台是否只提供安全进入、租户、项目、资产、审核、版本和交付等公共契约。
- 视频、文章、电商、连载小说是否真的拥有不同的导航、阶段、画布、对象语言、信息密度和主操作。
- 使用者能否在不理解 Runtime、Worker、Provider 或执行租约的情况下判断当前工作和下一步。
- 移动端缩窄后，当前阶段、主要结果、阻断原因和唯一主操作是否仍然可见。

原型中的数据都是用于评审的真实业务样例，所有按钮只改变原型状态，不会创建任务、上传资料或调用服务端。生产事实以 `apps/web/src/workbenches`、Customer BFF、统一业务主链测试和 Registry 状态为准。

## 2. 进入方式

直接打开 HTML 文件即可；也可以在仓库根目录运行：

```bash
python3 -m http.server 4173 --directory docs/product/customer-creation-studio/prototypes
```

然后打开 `http://127.0.0.1:4173/business-workbench-prototype.html`。

原型顶部的工作台选择器可以切换四个业务。切换时只保留平台公共身份区和项目上下文，以下内容必须发生变化：

| 维度 | 视频生产 | 文章创作 | 电商内容 | 连载小说 |
| --- | --- | --- | --- | --- |
| 导航语言 | 视频首页、视频任务、视频素材、视频交付 | 文章首页、文章任务、资料与引用、文章交付 | 商品首页、商品任务、商品资料、渠道交付 | 小说首页、章节任务、Canon 与资料、章节交付 |
| 阶段模型 | 目标与资料、剧本、分镜、候选视频、确认成片、交付 | 选题、资料与引用、文章草稿、校对与确认、交付 | 商品信息、卖点策略、内容变体、渠道预览、交付 | Canon、卷章规划、章节候选、连续性校验、编辑确认、章节交付 |
| 主画布 | 镜头网格、画面描述、时长和候选比较 | 目录、正文编辑器、标题候选和引用侧栏 | 商品事实、卖点矩阵、渠道变体和渠道预览 | Canon 台账、章节正文、连续性摘要和章节治理 |
| 右侧上下文 | 脚本来源、镜头检查、版本与下一步 | 引用来源、文章状态、校对检查 | 商品事实、渠道规格、版本和下一步 | 章节提交、审核门禁、批准快照和交付限制 |
| 首要动作 | 确认分镜或选择成片 | 保存草稿或提交校对 | 生成渠道变体或确认渠道包 | 提交章节审核或生成章节交付包 |

如果切换工作台后仍出现“分镜”“候选成片”“镜头”等视频对象，视为原型不通过。

## 3. 公共框架与可定制区域

原型把公共和定制边界画成两层：

```text
平台公共框架
  Content Work OS · 当前客户 · 当前项目 · 账号 · 帮助 · 状态提示

业务工作台
  自有导航 · 自有阶段 · 自有主画布 · 自有上下文 · 自有主操作
```

公共框架只保证：

- 会话、租户和权限边界清楚。
- 当前项目和资料引用有一致的入口。
- 状态同时有文字、图标和颜色表达，并可被屏幕阅读器读取。
- 失败、保存和返回路径稳定，工作台切换不会丢失当前编辑内容。

公共框架不规定：

- 侧栏必须存在，或所有工作台必须使用相同宽度。
- 工作台必须使用同一套四块卡片。
- 文章必须显示人物、分镜，或电商必须显示视频候选。
- 每个工作台的主操作、颜色强调和信息密度必须相同。

## 4. 四个原型画面

### 4.1 视频生产：阶段轨道 + 镜头画布

视频原型强调连续生产和候选比较。主画布是固定比例的镜头网格，右侧只显示脚本来源、检查结果、版本和下一动作；不显示 JobRun 或服务商信息。阶段轨道允许快速回到目标、剧本、分镜、候选、确认和交付。

### 4.2 文章创作：目录 + 编辑器 + 引用

文章原型把主画布换成编辑器。左侧是标题和段落目录，中间是可编辑正文，右侧是引用来源、事实检查和校对状态。它不沿用视频的媒体网格，也不把“镜头”换个名字继续使用。

### 4.3 电商内容：商品上下文 + 变体矩阵 + 渠道预览

电商原型把商品事实固定在工作区左上，主画布展示不同渠道的标题、卖点、短视频口播和图文组合，右侧展示渠道规格、预览状态和交付检查。它优先支持横向比较，不采用文章的长文阅读密度。

### 4.4 连载小说：Canon 台账 + 章节编辑 + 连续性治理

小说原型把 Canon、角色状态、时间线和伏笔台账固定在左侧，中间保持长篇章节编辑密度，右侧只展示统一 Submission、审核门禁、批准快照和章节交付的客户安全投影。它不复用文章的选题/校对模型，也不允许编辑器直接把正文标记为批准或已交付。

## 5. 评审任务

按以下顺序点击原型，每一步都应能在 3 秒内找到当前动作：

1. 在视频工作台切换到“分镜”，确认主画布变成镜头网格，并能看到“确认分镜”。
2. 切换到文章工作台，确认导航、阶段、主画布和对象语言全部改为文章语义。
3. 切换到电商工作台，确认主画布变成商品变体与渠道预览，而不是文章或视频卡片。
4. 切换到连载小说工作台，确认 Canon、卷章、章节和连续性语言完整出现，且章节交付明确引用批准快照。
5. 点击阶段按钮，确认当前阶段高亮、状态摘要和主操作同步变化。
6. 点击正文标题或任务摘要进行编辑，确认页面不会因为文字变长而遮挡其他内容。
7. 缩到 `390px` 和 `320px`，确认没有横向滚动，主操作变成可触控的满宽按钮。

## 6. 通过门槛

### 产品门槛

- 四个工作台至少有两处可感知的结构差异，不能只替换标题。
- 每个工作台的阶段名称、对象名词和主操作与业务目标一致。
- 工作台切换不泄漏另一业务的专有对象或无关底层术语。
- 一个页面只保留一个当前阶段的主操作，并提供明确的回退或查看路径。

### 视觉门槛

- 使用 `DESIGN.md` 的冷白页面、白色工作面、近黑命令和清亮蓝焦点。
- 视频、文章、电商、连载小说允许使用不同的对象色和密度，但不能变成互不相干的品牌。
- 不使用紫色渐变、装饰球、大面积深蓝、卡片套卡片或营销 Hero。
- 文字允许换行；固定媒体比例、按钮高度和导航轨道不能因内容改变而跳动。

### 可访问性门槛

- 所有阶段选择器和工作台切换器都有可见焦点和可读名称。
- 状态不能只由颜色表达，当前状态必须有文字。
- 键盘可以在工作台选择、阶段选择和编辑控件之间移动。
- `prefers-reduced-motion` 开启时不依赖位移动画表达状态变化。

## 7. 进入生产实现前的冻结内容

原型评审通过后，才冻结以下实现输入：

- 每个 `ExperienceTemplate` 的工作台 key、导航项和阶段 id。
- 阶段到任务 `current_step_id` 的映射，以及状态/动作语义。
- 主画布需要的业务投影字段和右侧上下文字段。
- 工作台主题 token、响应式断点和可访问性测试用例。

插件化实现边界见 `contracts/workbench-plugins/1.0.0`：第一版只允许声明式 manifest 和平台批准的渲染原语，不允许插件上传任意前端 bundle 或自带后端 API。

在此之前，生产 `/studio` 不应为了追求“统一”而继续扩展视频式面板，也不应把原型中的展示文案误当成服务端能力承诺。
