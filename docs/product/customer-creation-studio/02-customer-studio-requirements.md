# 客户创作台产品需求

状态：`下一阶段产品需求草案`。

更新时间：2026-08-05。

上位规范：[ContentCloud 平台基线](../../foundation/README.md)。本需求只定义客户体验和验收，不建立独立执行状态。

## 1. 产品目标

客户创作台让客户在不理解 ContentCloud 内部模型的情况下完成一项真实创作任务。页面以客户目标、必要输入、当前结果和下一动作组织，不把项目治理、流水线配置和运行诊断暴露为主要导航。

首个目标场景是 `IP 人设营销视频`：客户可以从灵感采集开始，依次确认人物原型、剧本、分镜、候选成片和交付包。

## 2. 目标用户

### 2.1 客户创作者

- 提交品牌、产品、目标受众和素材。
- 选择或补充灵感方向。
- 查看并修订候选内容。
- 在需要时连接本地创作工具。

### 2.2 客户审批人

- 确认人物方向、剧本、分镜、费用和最终结果。
- 查看固定版本、差异、来源和风险摘要。
- 批准、退回或要求补充资料。

### 2.3 平台运营人员

平台运营人员不使用客户创作台维护流水线。他们在独立运营控制台中配置模板、SOP、能力和租户开关，并处理运行异常。

## 3. 客户心智模型

客户只需要回答五个问题：

1. 我今天想制作什么？
2. 系统还需要我提供什么？
3. 当前已经得到什么结果？
4. 我现在应该做什么？
5. 我们已经有哪些内容可以直接用于这次创作？

页面不得要求客户先理解以下内部概念：

- 来源版本和知识对象类型。
- SOP、StageRun、JobRun 和 NodeRun。
- Gate mode、执行模式和能力 ID。
- SubmissionRevision、ApprovedSnapshot 和摘要算法。
- 本地 Daemon、租约、心跳和 MCP 配置。

这些概念可以支撑可追溯性，但必须被翻译为客户任务、材料、结果、确认和交付。

## 4. 信息架构

第一阶段客户创作台只包含四个一级区域：

```text
客户创作台
├── 今天
│   ├── 开始新的创作
│   ├── 等待我确认
│   └── 最近结果
├── 创作任务
│   ├── 进行中
│   ├── 等待资料或确认
│   └── 已完成
├── 资产库
│   ├── 品牌与产品
│   ├── 人物与形象
│   ├── 灵感与参考
│   ├── 剧本与内容
│   ├── 图片、音频与视频
│   ├── 已批准成果
│   └── 已交付作品
└── 交付
    ├── 待确认结果
    └── 已生成交付包
```

以下内容不作为客户一级导航：

- SOP 和流程规范。
- 运行记录、执行图、智能体和事件。
- 平台租户、能力和环境配置。
- 完整知识治理工作台。
- 服务商、费用对账和系统审计。

需要展示来源或权利时，从具体结果局部展开，不要求客户进入一个通用治理后台寻找。

资产库用于跨任务积累和复用，交付用于完成当前任务和下载正式交付包。资产库详细需求见[创作资产库](../creative-asset-library/README.md)。

## 5. 首屏要求

客户登录后的第一屏必须提供真实可用入口，而不是产品介绍页：

```text
今天想创作什么？

[IP 人设短视频]
从灵感、人物原型到剧本、分镜和成片交付

[营销视频]
从受众策略和创作简报生成营销内容

等待你确认
人物原型 1 项 · 剧本 2 项

继续上次任务
夏季新品 IP 短视频 · 当前：剧本确认
```

场景入口必须来自当前租户已经启用且已发布的 ExperienceTemplate。未实现、预览或无可用执行能力的场景不能伪装为可开始。

## 6. IP 人设营销视频客户流程

```text
1. 灵感采集
   输入主题、平台、受众和时间范围
   选择值得继续的来源和灵感

2. 人物原型
   查看人物定位、受众关系、表达边界和参考素材
   确认、退回或补充资料

3. 营销剧本
   查看剧本方向、引用、风险和版本差异
   选择方向并提出修改

4. 视频分镜
   查看镜头、画面、素材、连续性和生成要求
   批准进入视频生成

5. 候选成片
   查看候选、费用和内容检查结果
   选择、退回或批准最终处理

6. 交付准备
   下载正式交付包和操作说明
   外部平台发布后登记实际结果
```

“发布抖音”只有在 ContentCloud 取得真实平台回执时才能显示为成功。首版没有平台代理发布能力时，应显示“生成发布包”或“等待人工发布”。

## 7. 通用客户步骤契约

每个客户步骤至少需要以下字段：

```text
CustomerStep
├── id
├── title
├── outcome_description
├── status
├── progress_summary
├── required_inputs[]
├── result_summaries[]
├── primary_action
├── secondary_actions[]
├── blocking_reason
└── support_reference
```

客户步骤状态建议保持有限集合：

| 状态 | 客户含义 |
| --- | --- |
| `not_started` | 尚未开始 |
| `ready` | 可以开始 |
| `working` | 正在处理 |
| `needs_input` | 需要补充资料 |
| `needs_decision` | 等待客户确认 |
| `changes_requested` | 已要求修改 |
| `blocked` | 当前无法继续，并有明确原因 |
| `completed` | 本步骤结果已经确认 |
| `superseded` | 已有更新版本替代 |

这些状态是客户投影，不取代 Runtime 状态机。

## 8. 客户动作规则

每个页面只突出一个当前主要动作，例如：

- 开始采集。
- 从资产库选择已有资料。
- 补充缺少的品牌或产品资料。
- 确认人物原型。
- 查看修改后的剧本。
- 批准进入视频生成。
- 下载交付包。

动作必须由服务端根据权限、当前版本和 Runtime 状态返回。前端不能根据显示文案自行猜测是否允许批准、重试或进入下游。

高风险动作必须说明影响：

- 批准的具体版本和摘要。
- 预计费用和可能产生的外部请求。
- 退回后哪些下游结果会失效。
- 取消是否会停止已经发给外部服务商的任务。

## 9. 页面状态要求

每个客户步骤必须覆盖：

| 状态 | 页面要求 |
| --- | --- |
| 加载 | 保持布局稳定，说明正在读取什么 |
| 空数据 | 说明为什么为空，并提供唯一下一动作 |
| 部分完成 | 显示已完成数量、剩余数量和可继续部分 |
| 需要输入 | 列出缺少的具体资料和可接受格式 |
| 需要决定 | 显示固定结果版本、关键差异和批准影响 |
| 执行中 | 显示业务进度，不暴露无意义的底层日志 |
| 失败 | 使用业务语言说明原因、是否已保存进度和如何恢复 |
| 权限不足 | 说明需要哪个角色处理，不显示不可执行按钮 |
| 本地工具离线 | 提供明确连接动作和不依赖旧聊天记录的恢复说明 |
| 外部结果不明 | 显示“正在核对”，禁止客户重复提交 |

## 10. 客户语言翻译

| 内部对象或状态 | 客户文案 |
| --- | --- |
| `Source` / `EvidenceSpan` | 来源与引用 |
| `KnowledgeGap` | 还缺少的资料 |
| `Gate waiting_human` | 等待你确认 |
| `SubmissionRevision` | 提交版本 |
| `ApprovedSnapshot` | 已确认版本 |
| `Artifact` | 结果文件 |
| `DeliveryPackage` | 交付包 |
| `CreativeAssetCatalogItem` | 资产库中的可复用内容 |
| `CreativeAssetRef` | 已加入本次创作的内容 |
| `waiting(resource)` | 正在等待可用处理能力 |
| `retryable_failed` | 处理暂时失败，系统可以恢复 |
| `external effect unknown` | 正在核对外部处理结果 |

客户页面不得直接输出原始错误码、内部对象 ID、执行器命令或完整模型响应。需要支持排查时提供不敏感的支持编号，由运营人员在诊断台关联底层记录。

## 11. 权限边界

- 客户创作者可以提交资料、启动允许的场景、查看结果和请求修改。
- 客户审批人可以批准配置允许的客户 Gate，但不能修改 SOP 或运行时状态。
- 客户只读成员只能查看已经授权的业务结果。
- 平台运营人员通过运营控制台进入诊断，不通过客户角色获得额外数据。
- 所有客户动作继续校验租户、项目、任务、固定版本和摘要。

## 12. 第一阶段需求范围

### 必须完成

- 独立客户创作台 Shell、导航和权限边界。
- 已发布 ExperienceTemplate 的客户场景列表。
- IP 人设营销视频的六步客户流程。
- 客户步骤投影、阻断翻译和服务端动作。
- 灵感采集首个真实阶段。
- 资产库入口、分类、列表、详情和任务资产选择器。
- 保存的灵感和已批准结果自动沉淀，固定引用进入新任务。
- 固定模板、SOP、执行计划和输入版本。
- 客户确认、退回和交付包下载。
- 运营人员可以关联查看底层诊断。
- 桌面和移动端的加载、空、错误、部分完成和权限状态。

### 延后

- 客户自由组合或修改流水线。
- 通用拖拽工作流编辑器。
- 自动代登录并发布到抖音或公众号。
- 客户查看完整 Runtime Explorer。
- 同时上线大量创作场景。
- 未经验证的服务商自动回退。
- 通用 DAM、全盘同步、任意关系图和智能自动分类。

## 13. 产品指标

第一阶段至少记录：

- 场景入口到创建任务的完成率。
- 创建任务到第一个可确认结果的时间。
- 每个客户步骤的完成率和平均停留时间。
- `needs_input`、`blocked` 和运营人工介入比例。
- 客户能否在不阅读帮助文档的情况下找到下一动作。
- 灵感采集候选的保留率、来源覆盖和重复率。
- 客户退回后恢复到新版本的成功率。
- 交付包生成成功率及其与外部发布结果的分离准确率。
- 新任务复用已有资产的比例、资产查找时间和重复上传率。

## 14. 验收标准

1. 新客户无需理解内部术语，可以在首屏开始 IP 人设营销视频任务。
2. 客户最多经过两次主要操作即可找到当前阻断或需要确认的结果。
3. 客户无法访问 SOP、执行图、智能体、完整事件、平台配置和其他租户数据。
4. 所有主要动作来自服务端，刷新、返回和两标签页操作不会产生重复决定。
5. 任务中断后，客户仍能看到已经确认的结果和明确恢复动作。
6. 每个客户步骤都能被运营人员追溯到固定的 SOP、JobPlan、节点、Gate 和结果。
7. 模板发布或回退不改变进行中的任务。
8. 在 `1440 x 1000`、`390 x 844` 和最低 `320px` 宽度下，不出现横向页面溢出或关键动作遮挡。
9. 客户可以把一个保存或批准结果加入新任务；权利过期、来源撤回和跨租户资产会被服务端阻止。
