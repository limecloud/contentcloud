# 业务工作台层 UI 设计

状态：`四类工作台原型、首方业务 feature 和服务端固定契约已实现；当前 `/studio` 路由容器仍在分阶段拆分`。

更新时间：2026-08-23。

上位规范：[设计系统](../../../DESIGN.md)、[产品分层架构](../../../diagrams/contentcloud-product-layered-architecture.svg)、[客户创作台产品平面](./01-product-planes-and-architecture.md)。

## 1. 设计目标

业务工作台层是具体使用者每天工作的产品表面。它必须让使用者在第一次进入时直接回答三件事：

1. 我现在制作什么。
2. 当前进行到哪一步。
3. 下一步需要我做什么。

工作台不展示 Runtime、JobRun、NodeRun、Attempt、Effect、Provider 配额或执行租约。系统可以在后台使用这些对象，但客户只看到业务阶段、结果版本、阻断原因和可执行动作。

工作台不是一个大而全的后台，也不是把所有内容类型压缩成同一套表单。视频、文章、电商和连载小说可以拥有完全不同的导航、阶段、画布和工作密度。它们只通过平台契约共享身份、权限、项目引用、资产引用、审核、版本、状态、交付和可访问性；界面基础模块按需组合，而不是强制套用同一套壳。

设计边界可以概括为：

```text
平台契约与基础能力：统一
  身份 · 租户 · 权限 · 项目引用 · 资产引用 · 版本 · 审核 · 交付 · 状态语义 · 可访问性

业务工作台体验：可定制
  导航 · 页面结构 · 阶段模型 · 画布 · 对象语言 · 信息密度 · 主题 · 主操作 · 动效
```

## 2. 信息架构

```text
Content Work OS
├── 工作台选择器
│   ├── 视频生产
│   ├── 文章创作
│   ├── 电商内容
│   └── 连载小说
├── 今天
│   ├── 继续进行中的任务
│   ├── 等待我确认
│   └── 最近交付
├── 当前工作台
│   ├── 项目
│   ├── 创作任务
│   ├── 我的资料
│   ├── 创作结果
│   └── 交付
└── 工作台设置
    ├── 团队成员
    └── 连接工作电脑
```

平台运营和超级管理员从独立的“运营与管理”入口进入 `/admin/*`，不在客户工作台侧栏中混入能力目录、服务商、费用和运行诊断。

## 3. 平台公共框架与业务自有界面

这里的“公共框架”只负责让业务工作台安全地进入 Content Work OS，不规定客户如何完成业务。它提供会话、租户边界、权限检查、项目引用、通知、帮助、错误边界、可访问性和响应式基础；业务工作台决定客户看到的导航、页面结构、阶段轨道、画布和动作。

| 能统一的部分 | 必须由业务工作台定制的部分 |
| --- | --- |
| 登录、会话、租户和权限 | 一级导航和信息架构 |
| 项目/任务/资产引用协议 | 阶段模型和进度表达 |
| 版本、审核、交付和状态语义 | 主画布、编辑器和媒体布局 |
| 通知、帮助、错误边界和焦点规则 | 对象命名、文案、信息密度 |
| API、事件、审计和安全边界 | 主题、动效、主要动作和工作节奏 |

因此 `PlatformFrame` 不是客户工作台本身。它更接近一个受权限保护的宿主区域；视频工作台可以使用左侧阶段导航，文章工作台可以使用编辑器目录，电商工作台可以使用商品上下文工作区，连载小说可以使用 Canon 台账、章节编辑和连续性治理布局。

### 3.1 视频工作台的一种桌面布局

以下是视频生产工作台的一个推荐布局示例，不是所有业务工作台都必须采用的固定骨架。文章、电商和连载小说工作台可以选择完全不同的页面结构，只要满足平台契约和可访问性要求。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ Content Work OS   [视频生产⌄]              当前项目：品牌短视频⌄   用户⌄    │ 64px
├──────────────┬───────────────────────────────────────────────┬──────────────┤
│ 工作台导航    │ 页面标题 + 状态摘要                           │ 任务上下文   │
│              │                                               │              │
│ 今天          │ 业务主画布                                     │ 当前输入      │
│ 我的任务      │ 阶段进度 / 结果 / 比较 / 编辑                  │ 项目资料      │
│ 我的资料      │                                               │ 版本与来源    │
│ 创作结果      │                                               │ 下一动作      │
│ 交付          │                                               │              │
│              │                                               │              │
│ 运营与管理    │                                               │              │
└──────────────┴───────────────────────────────────────────────┴──────────────┘
   224px                  minmax(0, 1fr)                  280px
```

- 顶栏高度 `64px`，左侧固定品牌和工作台选择器，右侧显示项目切换、通知和账号菜单。
- 平台公共区域使用白色表面、冷白背景和清晰焦点；具体侧栏宽度、位置和是否存在由工作台自行决定。
- 主画布不规定固定列数；视频工作台可以采用“阶段 + 画布 + 上下文”，文章工作台可以采用“目录 + 编辑器”，电商工作台可以采用“商品信息 + 内容变体 + 渠道预览”，连载小说可以采用“Canon + 章节编辑 + 连续性摘要”。
- 上下文信息必须以业务语言呈现，不显示底层执行日志；它可以是右栏、抽屉、顶部摘要或画布内的检视区。
- 页面区块不使用装饰性浮卡；卡片只用于重复对象、候选结果和确实需要边界的工具。
- 任务详情在业务画布之前放置平台公共的“流程、产物与效果”摘要。它只显示阶段完成、批准版本、产物、交付和效果观察的业务计数，保证使用者能理解完整闭环；视频、文章、电商和连载小说仍可以用自己的画布解释这些对象，不能复制或改写底层状态。

### 3.2 工作台选择器

工作台选择器是业务入口，不是普通下拉框里的技术配置。打开后展示已发布且当前租户可用的业务模板：

| 工作台 | 入口副文案 | 主要阶段 |
| --- | --- | --- |
| 视频生产 | 从素材完成一条可交付视频 | 目标、剧本、分镜、生成、确认、交付 |
| 文章创作 | 从资料完成一篇可发布文章 | 选题、资料、草稿、校对、交付 |
| 电商内容 | 从商品信息完成转化内容 | 商品、卖点、脚本、素材、渠道包 |
| 连载小说 | 从 Canon 推进一章可交付内容 | Canon、卷章、章节、连续性、确认、交付 |

选择工作台后，项目列表、创建任务表单、阶段导航、结果预览和整体页面结构全部由 `ExperienceTemplate` 提供；平台公共框架只负责加载、鉴权、错误隔离和契约校验。

## 4. 视频生产工作台首屏

### 4.1 今天页

今天页不是数据仪表盘，而是一个可恢复的工作入口。首屏结构固定为：

```text
┌───────────────────────────────────────────────────────────┐
│ 视频生产                                      [新建视频任务] │
│ 继续上次工作，或从一个明确的创作目标开始。                  │
├───────────────────────────────────────────────────────────┤
│ 继续处理                                                   │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 品牌春季短视频       分镜确认       等待你的决定   →     │ │
│ │ 上次更新 12 分钟前    4 / 6 阶段        2 个候选版本     │ │
│ └─────────────────────────────────────────────────────────┘ │
├────────────────────────────┬──────────────────────────────┤
│ 等待我确认                  │ 最近交付                     │
│ 剧本版本 v3                 │ 品牌春季短视频包             │
│ 2 个差异 · 预计 3 分钟      │ 剪辑草稿 · 12 个素材         │
│ [查看并确认]                │ [打开交付]                   │
└────────────────────────────┴──────────────────────────────┘
```

主要动作每个区域只有一个：继续任务、查看并确认、新建任务或打开交付。不要在同一行堆叠“重试、取消、重新生成、下载、发布”等互相竞争的按钮。

### 4.2 任务详情页

任务详情页是视频业务的核心工作面，使用阶段轨道 + 业务画布 + 上下文栏：

```text
┌────────────────────────────────────────────────────────────────────┐
│ ← 我的任务   品牌春季短视频                         [更多]          │
│ 已保存 · 2026-08-23 14:32                                           │
├────────────────────────────────────────────────────────────────────┤
│ ①目标 ── ②剧本 ── ③分镜 ── ④候选视频 ── ⑤确认成片 ── ⑥交付      │
│                  当前：③分镜 · 需要你的确认                         │
├───────────────────────────────┬────────────────────────────────────┤
│                               │ 当前阶段                           │
│ 业务主画布                     │ 分镜版本 v2                        │
│                               │ 6 个镜头 · 已通过基础检查            │
│ [镜头 01] [镜头 02] [镜头 03] │                                    │
│                               │ 使用的资料                         │
│ 镜头预览 / 文案 / 时长 / 画面   │ 品牌手册 · 产品图 · 人物设定          │
│                               │                                    │
│ [退回修改]          [确认分镜] │ 下一步                             │
│                               │ 确认后进入候选视频生成               │
└───────────────────────────────┴────────────────────────────────────┘
```

阶段轨道只使用客户语言。每个阶段显示名称、状态和是否需要动作；不显示内部节点数量、执行器名称或服务商名称。

### 4.3 阶段画布

视频阶段的主画布按业务对象切换：

| 阶段 | 主画布 | 右栏 | 主要动作 |
| --- | --- | --- | --- |
| 目标 | 受众、主题、品牌约束和参考资料 | 已选输入、缺少资料 | 保存目标、补充资料 |
| 剧本 | 可编辑脚本、段落和旁白 | 资料依据、版本历史 | 保存草稿、提交确认 |
| 分镜 | 镜头列表、画面描述、时长和参考图 | 脚本来源、镜头检查 | 确认分镜、退回修改 |
| 候选视频 | 固定尺寸候选网格、播放和比较 | 生成参数摘要、费用提示 | 选为成片、退回生成 |
| 确认成片 | 主预览、差异和审核信息 | 审核记录、交付要求 | 确认成片、要求修改 |
| 交付 | 交付包内容、素材清单和导出检查 | 交付目标、文件状态 | 生成交付包、打开专业工具 |

候选视频使用稳定的 `16:9` 或 `9:16` 容器，预览加载、失败、无权限和不支持格式都不能改变网格尺寸。比较模式允许最多同时对比 3 个候选，移动端改为水平滚动。

## 5. 组件与交互规则

### 5.1 组件层级

| 组件 | 设计要求 | 禁止做法 |
| --- | --- | --- |
| `PlatformFrame` | 会话、租户、权限、错误边界、焦点和契约上下文 | 规定业务导航和阶段结构 |
| `ExperienceLauncher` | 展示租户可用工作台并安全进入模板 | 把 Provider、模型或执行器当成选项 |
| `WorkbenchNavigation` | 由业务模板定义，可为侧栏、目录、时间线或画布内导航 | 强制所有工作台使用同一套菜单 |
| `StageView` | 由业务模板定义阶段和进度表达，平台只校验状态契约 | 只用颜色表示进度 |
| `BusinessCanvas` | 由模板提供业务主画布和工作密度 | 把 JobRun 详情塞入客户画布 |
| `BusinessContext` | 输入、来源、版本、下一动作的业务化呈现 | 变成第二个复杂后台 |
| `CandidateGrid` | 固定媒体比例、比较、选择和失败状态 | 自动替用户发布外部渠道 |
| `DecisionBar` | 只保留当前阶段的一个主要动作和一个回退动作 | 同时出现多个高权重 CTA |
| `AssetPicker` | 区分“我的资料”“任务参考”“创作结果” | 三类对象混为一个通用文件列表 |

### 5.2 状态表达

状态使用文字、图标和颜色三重表达：

- `working`：处理中，显示阶段进度和最后更新时间。
- `needs_input`：需要补资料，显示具体缺少内容和支持格式。
- `needs_decision`：等待确认，显示固定版本、差异和确认后的下一步。
- `changes_requested`：已要求修改，保留已确认部分并显示修改范围。
- `blocked`：受阻，显示原因、已保存进度和恢复动作。
- `completed`：已完成，显示结果版本和可复用入口。
- `delivered`：已交付，显示交付包和外部操作状态。

错误信息不展示原始日志、绝对路径、提示词、令牌或服务商响应正文；支持排障使用不敏感的支持编号跳转到运营侧。

## 6. 视觉基线

严格复用 `DESIGN.md`，工作台专用值如下：

| 维度 | 规则 |
| --- | --- |
| 页面底色 | `#f8faff`，主面板 `#ffffff`，浅层 `#fbfdff` |
| 主要命令 | `#172033` 近黑色，悬停 `#263149` |
| 选中与焦点 | `#4c91ff`、`#3f83ef`、焦点环 `#76b4ff` |
| 边框 | `#e3eaf3`，分隔线使用更浅的 `#edf1f6` |
| 对象分类 | 来源冰蓝、知识绿、策略蓝灰、生产陶红、审核玫红 |
| 字体 | Avenir Next / Segoe UI Variable / 苹方 / 微软雅黑；数据列启用等宽数字 |
| 圆角 | 小元素 `6px`，控件与卡片 `8px`，弹层 `12px`，状态 pill 全圆角 |
| 动效 | `150-200ms`，只过渡颜色、透明度和 transform；支持减少动效 |

工作台不使用紫色渐变、整面深蓝、漂浮圆球、装饰性大插画、卡片套卡片或大字号营销 Hero。

## 7. 响应式规则

| 视口 | 布局变化 |
| --- | --- |
| `>= 1200px` | 224px 侧栏 + 主画布 + 280px 上下文栏 |
| `761-1199px` | 侧栏保留，右栏降为可折叠抽屉；主画布至少 640px |
| `<= 760px` | 侧栏变为顶部导航，阶段轨道水平滚动，右栏变为底部“当前任务”抽屉 |
| `320-390px` | 单列画布，按钮满宽，候选横向滚动；任何长标题允许换行，不产生横向滚动 |

移动端优先保留：当前阶段、主要结果、一个主要动作和阻断原因。项目资料、版本历史和审计摘要放入抽屉，不删除入口。

## 8. 实现拆分

在进入生产实现前，先使用[业务工作台可点击原型](./prototypes/business-workbench-prototype.html)评审视频、文章、电商和连载小说四种业务的差异。原型不是 API mock，也不是统一壳的最终实现；它只验证客户是否能看出“我正在做什么、做到哪里、下一步是什么”。对应的评审记录、布局说明和通过门槛见[业务工作台原型说明](./08-business-workbench-prototype.md)。

当前生产代码按以下边界落地：

1. `apps/web/src/workbench/host|registry|contract|renderer` 只承载宿主、版本固定、受限动作和批准渲染器，不集中保存某个业务的对象语言。
2. `apps/web/src/workbenches/marketing-video|article|commerce|serialized-novel` 分别拥有定义、业务简报字段和任务主画布；它们可以使用完全不同的信息架构。
3. Customer BFF 返回已发布或任务已固定的 `plugin_id + version + digest`，未知布局和安全撤销版本失败关闭，不按浏览器端 `latest` 漂移。
4. 四类工作台只创建统一 `WorkTask`，共享 SOP 编译、Runtime、Submission、Review、ApprovedSnapshot、Artifact、Delivery 和 Performance 事实；任务页的 `PipelineSummary` 是这些底层事实的只读摘要。
5. 当前剩余 UI 门槛是持续在 `1440 x 1000`、`390 x 844` 和 `320px` 宽度运行视觉验收，确认无溢出、无重叠、主要动作明确，并继续把迁移期路由容器中的业务代码下沉到对应 feature。

完成条件：客户可以从四类工作台入口进入各自业务场景，使用各自的导航、简报字段和画布完成任务；移除任一工作台后，任务、流程、审批、产物、交付和效果事实仍可独立查询和推进。运营配置、Runtime 诊断和执行者信息继续留在 `/admin/*` 与工程投影。
