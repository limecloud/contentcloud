# Content Work OS 产品叙事规范

状态：`目标产品叙事；不代表图中集成或能力已经上线`。

更新时间：2026-08-07。

上位规范：[平台基线](../foundation/README.md)与[设计系统](../../DESIGN.md)。

## 1. 目的

Content Work OS 需要同时向客户解释“它能帮我完成什么”，向运营解释“怎样发布和治理创作流水线”，向工程解释“系统怎样可靠执行”。这三个问题不能塞进同一张图。

统一叙事采用两张图：

1. **客户叙事图：** 客户资料、任务参考和已有结果怎样进入一次创作，并变成可确认、可交付、可继续使用的新结果。
2. **平台架构图：** 客户创作台、运营控制台、业务域、Runtime 和执行者怎样分工。

客户叙事图用于建立理解，平台架构图用于建立信任。两者共享事实，但不共享信息密度。

## 2. 一句话叙事

> 把已有资料和创作目标带进 Content Work OS，它会组织合适的创作流水线、工具和确认节点，产出可继续使用和持续积累的内容结果。

更短的图示标题：

> 从任务输入，到可交付创作结果。

不使用“一个 Agent 连接所有工具”作为一级叙事。Content Work OS 是创作任务和流水线产品，不是万能智能体外壳。

命名边界：

- **Content Work OS：** 客户可见的一级产品品牌，用于官网、客户创作台、产品叙事图和对外材料。
- **ContentCloud：** 迁移期保留的技术标识，用于 CLI、API、Workspace、包名和 `ContentCloud Agentic Job Runtime`。
- 客户叙事图不把技术兼容名称放在视觉中心；工程架构图可以准确使用 ContentCloud 模块名。

## 3. 客户叙事图

```text
我的资产与任务参考                  Content Work OS                 创作结果与专业工具

文档、图片、视频与音频          ┌────────────────────┐          人物原型 / 剧本 / 分镜
品牌资料与已导入文件            │     创作任务        │          图片 / 视频
公开搜索与受控来源       -----> │  流水线与人工确认   │ ----->   交付包与可复用成果
本地文件与授权工作区            │  进度、版本与追溯   │          剪辑、设计与发布工具
人工观察与业务要求              └────────────────────┘          后续创作任务
```

客户只需理解：

- 左边是“我已经有什么，以及这次还要提供什么”。
- 中间是“这次创作做到哪里，现在需要我做什么决定”。
- 右边是“我得到了什么，以及可以在哪里继续完成工作”。

图中不出现 JobRun、NodeRun、MCP 参数、模型版本、租约、Effect、投影游标和服务商配额。

## 4. 中心对象的三种语言

同一个中心必须按受众翻译，不能统一叫“Agent”：

| 受众 | 中心名称 | 主要含义 |
| --- | --- | --- |
| 客户 | Content Work OS 创作任务 | 输入、进度、结果、确认和交付 |
| 平台运营 | 已发布创作流水线 | 体验模板、SOP、能力、门禁、租户启用和回退 |
| 工程与运行运营 | WorkTask + Agentic Job Runtime | 固定计划、调度、执行引用、恢复、费用和审计 |

客户图的中心使用 Content Work OS 品牌标识与“创作任务”文字，不使用机器人头像或“ContentCloud Agent”。机器人图形会错误暗示一个自主 Agent 拥有任务状态和所有集成。

## 5. 平台架构图

```text
客户创作者 / 客户审批人                 平台内容运营 / 运行运营
            |                                      |
            v                                      v
      客户创作台与资产入口                     平台运营控制台
            |                                      |
            v                                      v
 Customer Journey + Customer Asset Surface       Operations Projection
            \                                      /
             +------ 业务域与版本化契约 -----------+
                               |
                               v
                 ContentCloud Agentic Job Runtime
                               |
          +--------------------+--------------------+
          |                    |                    |
          v                    v                    v
  ContentCloud Worker    Codex / Claude Code    外部服务商与工具
          \                    |                    /
           +-------------------+-------------------+
                               |
                               v
                   候选结果 -> 人工门禁 -> 正式事实
```

这张图表达责任和信任边界，不承担营销任务。它必须继续显示：

- 客户面和运营面完全分离。
- Runtime 只拥有执行事实，不拥有来源、批准、资产正文和交付正文。
- Codex、Claude Code、确定性 Worker、外部服务商和人工都是执行者或参与者。
- 候选、人工决定和正式事实之间存在明确门禁。

## 6. 输入与工具分类

图中首先使用能力类别，再按需要列举工具示例：

| 图中类别 | 可包含的示例 | 表达规则 |
| --- | --- | --- |
| 协作与知识来源 | 飞书、Notion、企业知识库 | 表达资料来源，不暗示平台拥有其正文 |
| 搜索与采集 | 搜索 API、受控爬虫、本地 MCP | 表达采集方式，不要求客户选择执行器 |
| 本地智能体 | Codex、Claude Code | 表达可选执行者，不作为客户前置条件 |
| 生成服务 | 图片、视频、语音服务商 | 表达能力类别，具体绑定由版本化策略决定 |
| 专业制作工具 | 剪映、Premiere Pro、设计工具 | 表达后续编辑或交付去向，不等于已经完成双向集成 |
| 发布平台 | 抖音、公众号及其他渠道 | 只有真实回执时才表达为已发布成功 |

供应商名称和 Logo 只能出现在以下条件全部满足时：

1. 集成状态已由代码、契约、测试或发布记录验证。
2. 商标和品牌使用方式允许。
3. 图旁明确区分“当前可用”“预览”“计划中”或“可通过标准接口接入”。
4. 去掉该供应商后，产品叙事仍然成立。

正式架构图只使用能力类型，不使用供应商 Logo。

## 7. 资产在叙事中的位置

资产入口同时承接客户带入平台的资料和平台生成的结果：

```text
我的资产 -----------+
                     +-> 新创作任务 -> 已确认结果 -> 创作结果
任务输入与项目参考 --+                         |
                                               v
                                          下一次创作
```

- “我的资产”展示客户明确上传或导入的文件夹、文档、图片、视频、音频和表格。
- 任务输入和项目参考展示本次创作选用的搜索候选、来源证据和灵感，不会自动变成客户资产。
- “创作结果”展示人物原型、剧本、分镜、图片和视频，确认状态决定能否正式复用。
- “最近使用”只组合前两类投影；交付包仍由独立交付视图核对和下载。

因此资产入口既不是孤立网盘，也不是只显示生成结果的历史页。它是 Content Work OS “整理已有资料，完成一次创作，复用到下一次”的工作区。

## 8. 四层表达深度

| 层级 | 使用位置 | 必须回答 | 不应出现 |
| --- | --- | --- | --- |
| 十秒叙事 | 官网、销售首图、产品总览 | 输入什么、得到什么 | Runtime 术语和完整工具清单 |
| 产品说明 | 客户文档、演示、场景介绍 | 怎样开始、确认和交付 | 租约、事件、内部错误码 |
| 平台说明 | 运营手册、方案评审 | 怎样配置、治理、诊断和回退 | 客户不需要理解的实现细节 |
| 工程规范 | Foundation、V8、代码文档 | 所有权、契约、状态、故障和测试 | 未验证的营销承诺 |

同一个概念逐层展开，不允许不同层级改变事实。例如客户图可以省略 Runtime，但不能把 Codex 描述成权威状态拥有者。

## 9. 图形表达规则

所有正式视觉稿遵循根目录 `DESIGN.md`：

- 客户叙事图使用冷白工作面、稳定三段式网格和 Content Work OS 品牌标识。
- 官网首屏保留自然光创作空间作为底层品牌背景，客户叙事图作为独立信息层叠加；摄影只负责氛围，不能承担产品能力说明。
- 中心强调“创作任务”，不使用机器人吉祥物、对话气泡或自主 Agent 头像。
- 输入、生产、审核等对象可以使用设计系统分类色，但状态不能只靠颜色表达。
- 工具节点保持克制，不做卡片套卡片、漂浮装饰和品牌 Logo 墙。
- 桌面与移动端分别重排，不把桌面横向图等比缩小到不可阅读。
- 图中的文字必须在 `390 x 844` 与最低 `320px` 宽度下保持可读，不依赖悬停解释。

## 10. 文案规则

优先使用：

- “选择创作场景”而不是“启动 Agent”。
- “系统正在组织处理”而不是“Agent 正在思考”。
- “连接本地创作工具”而不是“必须打开 Codex”。
- “生成交付包”而不是“已发布”，除非存在真实平台回执。
- “导入到我的资产”“加入本次创作”“保留为项目参考”或“保存到创作结果”而不是“写入向量库”。

禁止使用：

- “一个 AI 自动完成所有工作”。
- “连接任意工具”或“支持所有平台”。
- “无需审核即可自动发布”。
- 把计划中的供应商 Logo 当作当前集成证据。
- 把 Runtime、Agent 或资产目录描述为所有业务事实的唯一拥有者。

## 11. 验收标准

1. 第一次看到客户叙事图的人能在十秒内回答“输入什么、系统做什么、得到什么”。
2. 客户不会认为必须使用 Codex、Claude Code 或某个指定服务商才能开始。
3. 客户图、运营图和工程图对同一能力的当前状态与所有权没有矛盾。
4. 供应商 Logo 和名称均能追溯到真实集成状态与商标使用依据。
5. 资产入口清楚区分客户工作区资料、任务参考和创作结果，并被表达为创作闭环，而不是孤立网盘。
6. 平台架构图继续清楚显示客户面、运营面、Runtime 和执行者边界。

## 12. 非目标

- 首页可以直接实现本规范的客户叙事图与平台架构图，但不得把工程图完整塞进 Hero，或让技术术语压过一级产品品牌与客户价值。
- 不要求在一张图中展示所有模块、对象、工具和内容类型。
- 不创建固定供应商清单或承诺所有第三方工具均有原生集成。
- 不使用客户叙事图替代工程架构、威胁模型和运行数据流。
