# 客户资产

状态：`“我的资产”上传首切片、客户结果目录、独立资产详情页与类型化查看工作面已实现；连接器导入、结果持久化 Projector、客户修订编辑器、运营治理与发布验证待完成`。

更新时间：2026-08-07。

上位规范：[ContentCloud 平台基线](../../foundation/README.md)。客户任务体验参见[客户创作台](../customer-creation-studio/README.md)，对外表达遵循[产品叙事规范](../00-product-narrative.md)。

当前实现通过 Customer Studio 组合两个专用投影：`WorkspaceMaterialProjection` 已支持文件夹、客户上传、受控预览、固定资料引用、加入任务和最近使用；`CreativeResultAssetProjection` 从已有任务事实动态生成五类结果，并保持独立状态筛选、可复用门禁和任务引用。资产卡片进入独立详情页后，工作区资料按文档、图片、视频、音频、CSV 和其他文件渲染，创作结果按人物原型、剧本、分镜、图片和视频渲染；Word/PPTX/XLSX 在当前浏览器能力不足时降级为文件信息与下载。详情页固定版本只读，编辑动作必须回到来源任务并创建新修订版本。连接器导入、外链登记、移动/删除、AI 理解和创作结果持久化 Projector 尚未实现；现有 `StudioAssetItem` 仍只表达生成结果。

## 1. 产品结论

ContentCloud 已经拥有来源、知识、受权利约束的参考素材、批准快照、生产文件、交付包和追溯关系，但客户还缺少一个符合直觉的长期资产工作区。客户既要整理自己上传或导入的资料，也要找到平台生成并确认的结果。

资产功能要让客户回答四个问题：

1. 我们已经上传、导入和整理了哪些资料？
2. 我们已经生成并确认了什么？
3. 哪些资料和结果现在可以安全用于新的创作？
4. 怎样让系统理解一个资料，并把它直接带入本次创作？

核心叙事是：

> 自己带进来的资料和每次创作得到的结果，都能被整理、理解并继续使用。

在统一客户叙事中，资产入口同时位于起点和终点：

```text
我的资产 -----------+
                     +-> Content Work OS 创作任务 -> 创作结果 -> 下一次创作
项目参考与任务输入 --+
```

## 2. 产品边界

“资产”是一个客户入口，不是新的业务事实拥有者，也不是把所有内容复制到同一张表的通用 DAM。

```text
客户上传 / 导入 / 登记的资料       流水线生成结果
              |                         |
              v                         v
 WorkspaceMaterialProjection   CreativeResultAssetProjection
              \                         /
               +---- Customer Asset Surface ----+
                           |
                 我的资产 / 创作结果 / 最近使用

搜索候选 / 来源证据 / 权利记录 / Runtime 事件
                           |
                           v
                   任务参考或运营投影
```

- `WorkspaceMaterialProjection` 只投影客户明确拥有或管理的上传、导入和链接资料，并独立展示文件夹与处理状态。
- `CreativeResultAssetProjection` 继续使用现有 `CreativeAssetCatalogItem` 表达五类生成结果及确认门禁。
- 客户 BFF 组合两个专用投影；不创建超级 `Asset`，不让普通文件进入结果状态机。
- 新任务通过固定版本和摘要引用资料或已确认结果；搜索候选和来源证据不会因被使用过就自动进入“我的资产”。
- 权利到期、来源失效和版本替代会改变“是否可用于新任务”，但不会删除历史交付和审计。

## 3. 客户术语边界

| 类别 | 客户看到的名称 | 示例 | 入口与边界 |
| --- | --- | --- | --- |
| 工作区资料 | 我的资产 | 文件夹、文档、图片、视频、音频、表格和其他导入文件 | 资产；必须由客户上传、导入或明确登记 |
| 创作结果 | 创作结果 | 人物原型、剧本、分镜、图片、视频 | 资产；由流水线结果投影产生 |
| 任务参考 | 任务输入 / 项目参考 | 搜索候选、灵感、来源证据、知识和权利摘要 | 当前任务、灵感采集；不自动进入资产 |
| 交付 | 交付作品 | 交付包、下载文件和交付清单 | 交付 |

`document / image / video / audio / table / other` 是工作区资料类型；`persona / script / storyboard / image / video` 是结果类型；`draft / pending_confirmation / changes_requested / confirmed / delivered / superseded / blocked` 只属于结果状态。只有 `confirmed` 和 `delivered` 的生成结果可被服务端接受为正式复用输入。

## 5. 第一阶段结果

当前已经落地的是生成结果复用首切片：

```text
生成并确认人物、剧本、分镜或媒体结果
  -> 自动进入统一目录
  -> 客户按结果类型搜索、筛选和预览
  -> 查看来源任务、版本和可复用状态
  -> 引用到新任务
  -> 新结果继续沉淀
```

下一工作包补齐“我的资产”的最小可用闭环：创建文件夹、上传/导入、搜索、预览、处理状态、加入创作和最近使用。它不扩张为企业网盘替代品，不建设全盘同步、任意关系图或低代码资产编排器。

独立详情页已经作为客户资产入口的一部分交付：目录页负责查找和筛选，详情页负责理解固定版本，来源任务负责可写修订。三者不共享一个万能编辑面板，避免客户把文件整理、结果确认、流水线配置和版本治理混在一起。

## 6. 固定原则

1. 客户只看到一个“资产”入口，但“我的资产”和“创作结果”读取不同专用投影。
2. 目录项不是权威正文，投影损坏后可以从事实对象重建。
3. 客户明确上传或导入的资料进入“我的资产”；搜索结果、灵感和来源证据仍留在任务参考，除非客户执行明确导入动作。
4. 普通文件使用文件处理状态，生成结果使用结果确认状态，两套状态不能混用。
5. 正式引用必须固定底层对象版本和摘要，不能引用“当前最新”。
6. 失效和权利变化默认阻止新的受限使用，并能定位受影响下游。
7. 文件夹只负责组织，客户不能通过资产入口绕过来源、权利、事实、审批和交付门禁。
8. 类型决定渲染器，版本决定是否可写；不能渲染的文件提供明确下载降级，不能保存的编辑动作不显示为可用按钮。
