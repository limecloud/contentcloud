# 创作资产库

状态：`客户结果目录首切片已实现；持久化投影、运营治理与发布验证待完成`。

更新时间：2026-08-07。

上位规范：[ContentCloud 平台基线](../../foundation/README.md)。客户任务体验参见[客户创作台](../customer-creation-studio/README.md)，对外表达遵循[产品叙事规范](../00-product-narrative.md)。

当前实现通过 Customer Studio 从已有任务事实动态生成结果目录，已经验证五类结果、独立状态筛选、可复用门禁和任务引用。它不是最终的持久化 `CreativeResultAssetProjection`；目录游标、重建、失效传播、运营治理和 Canary 仍按交付计划推进。

## 1. 产品结论

ContentCloud 已经拥有来源、知识、受权利约束的参考素材、批准快照、生产文件、交付包和追溯关系，但客户还缺少一个统一、简单、可跨任务复用生成结果的入口。

创作资产库解决的不是“把文件放进一个网盘”，而是让客户能够回答三个问题：

1. 我们已经生成并确认了什么？
2. 哪些人物、剧本、分镜、图片和视频现在可以安全复用？
3. 怎样把一个已有结果直接带入下一次创作？

核心叙事是：

> 每完成一次创作，都在积累下一次可以直接使用的内容结果。

在统一客户叙事中，资产库同时位于起点和终点：

```text
任务输入与项目参考 -> Content Work OS 创作任务 -> 创作结果 -> 资产库 -> 下一次创作
```

## 2. 产品边界

创作资产库是客户侧结果入口，不是新的业务事实拥有者，也不是任务输入资料库。

```text
生成结果事实：Persona / Script / Storyboard / Image / Video
                                  |
                                  v
                    CreativeResultAssetProjection
                                  |
                     +------------+------------+
                     |                         |
                     v                         v
              客户创作资产库              运营结果治理
              浏览、搜索、复用            版本、权利、失效、追溯

来源 / 知识 / 权利 / 参考素材
                                  |
                                  v
                    任务输入与项目参考投影
```

- 现有 `Asset`、`SourceRevision`、`KnowledgeObject` 和 `RightsRecord` 保持输入与治理语义，不作为客户创作资产类型。
- `CreativeResultAssetProjection` 是客户产品语义；迁移期继续使用现有 `CreativeAssetCatalogItem` 作为可重建的只读行契约。它只引用生成结果事实，不复制正文，也不引入平行目录类型。
- 新任务通过固定版本和摘要引用已确认结果；任务输入仍由任务域固定，不把输入复制进结果资产目录。
- 权利到期、来源失效和版本替代会改变“是否可用于新任务”，但不会删除历史交付和审计。

## 3. 客户术语边界

| 类别 | 客户看到的名称 | 示例 | 入口 |
| --- | --- | --- | --- |
| 创作输入 | 任务输入 / 项目参考 | 来源资料、灵感、知识、参考素材、权利记录 | 当前任务、灵感采集 |
| 创作资产 | 创作资产 | 人物原型、剧本、分镜、图片、视频 | 资产库 |
| 交付 | 交付作品 | 交付包、下载文件和交付清单 | 交付 |

`draft`、`pending_confirmation`、`changes_requested`、`confirmed` 和 `delivered` 是资产状态，不是资产分类。只有 `confirmed` 和 `delivered` 可被服务端接受为新任务的正式复用输入。

## 5. 第一阶段结果

第一阶段只建立生成结果的完整复用闭环：

```text
生成并确认人物、剧本、分镜或媒体结果
  -> 自动进入统一目录
  -> 客户按结果类型搜索、筛选和预览
  -> 查看来源任务、版本和可复用状态
  -> 引用到新任务
  -> 新结果继续沉淀
```

第一阶段不建设通用数字资产管理系统、三维画布、任意关系图、全盘文件扫描或低代码资产编排器。

## 6. 固定原则

1. 客户看到生成结果语义，运营看到输入、权利和治理语义，二者读取同一事实体系的不同投影。
2. 目录项不是权威正文，投影损坏后可以从事实对象重建。
3. 搜索结果、灵感和任务输入不进入客户创作资产库；只有流水线生成的结果才沉淀，是否可复用由确认状态决定。
4. 正式复用必须固定底层对象版本和摘要，不能引用“当前最新”。
5. 失效和权利变化默认阻止新任务继续使用，并能定位受影响下游。
6. 客户不能通过资产库绕过来源、权利、事实、审批和交付门禁。
