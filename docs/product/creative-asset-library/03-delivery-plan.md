# 创作资产库交付计划

状态：`目标实施计划，排期和接口待 ADR 与 POC 冻结`。

更新时间：2026-08-05。

## 1. 交付策略

资产库不等待新 Runtime 全部完成，也不先建设一个独立 DAM。首期使用现有事实对象和 `ProjectProjection` 模式，交付一个可验证的跨任务复用闭环。

```text
事实对象与 lineage
        |
        v
统一目录投影 -> 客户资产库 -> 加入 WorkTask -> 新结果沉淀
        |
        v
运营治理与失效影响
```

## 2. 纵向切片

首个切片选择“灵感保存到下一任务复用”：

```text
灵感采集结果
  -> 客户选择并保存一个来源
  -> 资产库出现“灵感与参考”目录项
  -> 客户从目录项开始 IP 人设营销视频任务
  -> WorkTask 固定 SourceRevisionRef + digest
  -> 人物或剧本批准后自动沉淀新目录项
```

这个切片同时验证收录策略、投影、搜索、引用、版本固定、权利状态、任务集成和平台复利。

## 3. 实施阶段

### A0：契约和事实冻结

- 接受或修订 ADR-0011 与 ADR-0012。
- 核对 Source、Asset、Rights、ApprovedSnapshot、Artifact、Delivery 和 lineage 的当前 API 与存储事实。
- 冻结 `CreativeAssetCatalogItem`、`CreativeAssetRef`、分类和有限状态集合。
- 冻结各事实对象的版本/摘要映射，并补齐 DeliveryPackage 规范化 Manifest 摘要契约。
- 明确目录投影游标、重建和延迟阈值。

退出条件：目录不是新事实所有者；每类收录对象和失效来源都有唯一拥有域。

### A1：只读目录投影

- 从保存的 SourceRevision、Asset、ApprovedSnapshot、Artifact 和 DeliveryPackage 构建目录。
- 实现对象身份去重、版本指向、权利摘要和可复用状态。
- 提供客户列表、详情和选择器查询。
- 提供运营重建、延迟和错误诊断。

退出条件：相同事实重放结果一致；临时候选不进入目录；投影重建不产生外部副作用。

### A2：客户复用闭环

- 客户资产库导航、分类、搜索、筛选、列表、详情和空错误状态。
- 从资产加入现有任务或开始新任务。
- WorkTask 输入固定底层对象版本和摘要。
- 资产详情展示最近使用和来源追溯。

退出条件：试点客户无需理解底层对象即可完成一次跨任务复用。

### A3：自动沉淀和治理

- 灵感保存、ApprovedSnapshot、Artifact 和 DeliveryPackage 自动进入目录。
- 权利过期和来源失效更新目录状态并阻止新使用。
- 运营侧提供待审核、即将到期、重复组和影响范围。
- 客户与运营使用独立 DTO 和权限测试。

退出条件：完成一次创作后，批准结果可在下一任务中直接使用；失效传播满足安全门禁。

### A4：Canary 和指标验证

- 对内部项目和少量试点租户启用。
- 建立复用率、查找时间、重复上传、失效阻止率和投影延迟指标。
- 演练关闭客户入口、切回旧“品牌资料”入口和重建目录。
- 根据真实使用决定是否扩展效果与学习资产。

退出条件：客户复用价值成立，运营成本可控，未形成第二套正文或状态。

## 5. 代码落点建议

目标模块遵循平台代码组织，不为资产库新增超级业务域：

```text
internal/experience/studio/creativeassets/      客户目录 Query 与 DTO
internal/experience/operations/creativeassets/  运营目录 Query 与治理协调
internal/experience/projection/creativeassets/  Projector、游标和重建
contracts/business/creative-asset-catalog/      CatalogItem 与 CreativeAssetRef Schema
web/src/studio/assets/                           客户资产库 feature
web/src/admin/assets/                            运营治理 feature
```

实际迁移期可以在现有 `internal/app`、`internal/domain/projection.go` 和 Web Shell 中以窄接口实现，不要求先创建完整目标目录。新代码不得继续扩大全局 `Store` 和 `Service`；若暂时使用兼容接口，必须登记退场条件。

## 6. 测试路径

```text
CODE PATHS                                      USER FLOWS
目录收录                                        客户查找并复用
├── 保存来源 -> 出现                             ├── 搜索 -> 详情 -> 加入任务 [E2E]
├── 批准快照 -> 出现                             ├── 陈旧页面 -> 服务端拒绝并刷新 [E2E]
├── 临时候选 -> 不出现                           └── 无结果/预览失败 -> 可恢复
└── 重放事件 -> 不重复

权利与失效                                      运营治理
├── 可用渠道/地区/期限                           ├── 权利到期 -> 影响清单 [integration]
├── expired/revoked -> 阻止                       ├── 修复底层记录 -> 目录恢复
├── 跨租户 -> 拒绝                               └── 全量重建 -> 摘要一致
└── Restricted preview -> 拒绝
```

发布前至少覆盖：领域单元测试、Memory/PostgreSQL 投影契约测试、BFF 权限与冲突集成测试，以及一条“保存灵感 -> 资产库 -> 新任务”的 E2E。

## 7. Feature Flag 和回退

至少拆分三个开关：

- 目录投影是否旁路构建。
- 客户资产库是否可见。
- 新任务是否允许从目录引用输入。

回退时先关闭新引用命令，再隐藏客户入口；目录投影可以继续旁路对账。已创建的 WorkTask 引用和历史目录审计必须保留，不能通过回退删除。

## 8. 指标门槛

首批试点需要记录基线并在 POC 后冻结具体阈值：

- 新任务资产复用率。
- 资产查找成功率和 P95 查找时间。
- 重复上传下降比例。
- 投影 P95 延迟和重建成功率。
- 权利失效到阻止新使用的最大时间。
- 运营每百个目录项的人工处理量。

若客户仍主要重复上传、资产查找时间没有改善或运营处理量随目录项线性增长，应停止扩分类和智能检索，先修正收录策略、命名与筛选体验。

## 9. 风险和缓解

| 风险 | 级别 | 缓解 |
| --- | --- | --- |
| 目录成为第二套正文 | P0 | 只保存引用和摘要，重建测试阻断发布 |
| 现有 `Asset` 语义被扩大 | P0 | ADR 冻结其参考素材语义 |
| 所有搜索结果污染资产库 | P1 | 只收录保存、选择、批准和交付内容 |
| 权利状态陈旧仍被使用 | P0 | 危险命令回源校验，投影延迟超阈值禁用动作 |
| 相似内容被错误合并 | P1 | 首期只提示重复，不自动合并事实对象 |
| 客户仍不知道从哪里开始 | P1 | 资产详情只保留一个主要动作并可直接启动场景 |
| 大列表拖慢 Studio | P1 | 专用投影、游标分页、缩略图和容量测试 |

## 10. NOT in scope

- 通用企业 DAM 或网盘替代品：不阻断跨任务创作复用闭环。
- 全盘同步和桌面文件监听：数据权限和冲突成本过高。
- 向量数据库和自动语义聚类：先用确定性字段验证查找价值。
- 任意关系图和资产编排画布：现有 lineage 查询足够支撑追溯与影响。
- 跨租户资产市场：与首期租户内复用目标无关。
- 效果数据自动修改资产或 SOP：违反人工批准和学习治理边界。

## 11. 完成定义

1. 客户可以浏览、理解并复用来源、批准成果和交付作品。
2. 每个正式引用固定底层对象版本和摘要，并能追溯使用历史。
3. 已批准结果自动沉淀，临时候选不会污染全局目录。
4. 权利、来源、租户和敏感性变化能阻止不安全的新使用。
5. 投影可重建、可对账、无外部副作用，客户与运营读取独立契约。
6. 真实试点证明资产复用降低重复采集、生成或审核成本。
