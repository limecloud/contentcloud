# 客户资产产品需求

状态：`“我的资产”上传首切片、客户结果目录与任务复用首切片已实现；连接器导入、结果持久化 Projector、运营治理与发布验证待完成`。

更新时间：2026-08-07。

## 1. 问题与目标

客户今天可能在任务、来源、审核结果和交付页面中分别看到同一项目的内容，却无法形成稳定的“我手上有哪些资料、平台已经生成了什么、下一步能用什么”心智。客户上传的文件没有长期工作区，平台生成的结果又和输入资料混在概念里，导致每条新流水线都重新找资料、重新确认人物和品牌表达。

客户资产功能的目标是：

- 让客户在一个入口中找到跨任务可复用的人物原型、剧本、分镜、图片和视频结果。
- 让客户在同一个入口中管理自己上传或导入的文件夹、文档、图片、视频、音频和表格。
- 让客户在开始新任务时直接选择已有创作结果，而不是重复生成和重复确认。
- 让客户可以对资料执行预览、摘要、转写、OCR、标签建议和加入本次创作等受控动作。
- 让每个结果清楚显示来源任务、项目、版本、状态、可复用状态和使用历史。
- 让运营人员治理失效、重复、敏感预览和权利风险，不把这些复杂度暴露给客户。

当前代码已经提供“我的资产 / 创作结果 / 最近使用”三视图、文件夹创建、客户上传、受控预览、固定资料引用、资料或结果加入同项目任务，以及灵感保留为项目参考的客户闭环。连接器导入、外链登记、文件移动/删除、AI 理解、详情页历史版本、创作结果持久化 Projector、目录重建、运营治理、完整权利失效传播和发布指标仍属于本需求的未完成范围。

## 2. 目标用户

| 角色 | 核心任务 | 看到的语言 |
| --- | --- | --- |
| 客户创作者 | 查找、比较、预览并加入新任务 | 可用、需确认、不可使用、来自哪里 |
| 客户审批人 | 确认正式版本、表达边界和复用影响 | 已批准版本、变更、权利和使用范围 |
| 租户管理员 | 管理本租户可见范围和成员访问 | 项目范围、敏感级别和共享策略 |
| 平台内容运营 | 处理分类、重复、失效和资产沉淀规则 | 底层对象、目录策略、来源和影响范围 |
| 平台运行运营 | 诊断索引、投影延迟和重建失败 | 游标、重建任务、错误码和追溯链 |

## 3. 客户信息架构

客户一级导航中的“品牌资料”演进为“资产”，但“交付”仍保留为任务交付入口。资产页面内部使用简单的视图切换，不按文件类型增加大量一级导航：

```text
客户创作台
├── 今天
├── 创作任务
├── 资产
│   ├── 我的资产
│   │   ├── 文件夹与最近导入
│   │   ├── 文档 / 图片 / 视频
│   │   └── 音频 / 表格 / 其他文件
│   ├── 创作结果
│   │   ├── 人物原型 / 剧本 / 分镜
│   │   └── 图片 / 视频
│   └── 最近使用
└── 交付
    ├── 待确认结果
    └── 当前任务交付包
```

各入口的区别：

- **我的资产：** 管理客户明确上传、导入或登记的工作区资料。
- **创作结果：** 跨任务积累、查找和复用流水线结果。
- **最近使用：** 对前两者的只读时间排序，不产生第三套事实。
- **交付：** 完成当前任务、核对完整性和下载正式交付包。

文件类型只在“我的资产”中筛选；五项结果类型和结果状态只在“创作结果”中筛选。搜索候选、灵感、知识、来源证据和权利记录仍属于当前任务输入、项目参考或运营治理，不会自动变成客户资产。交付页面引用当前任务的交付事实，不为导航视图复制资产正文。

## 4. 收录策略

资产入口不能把每一次搜索返回和每一个临时候选全部展示给客户，否则很快退化为不可管理的结果堆积。工作区资料与创作结果使用不同收录规则：

首期收录规则：

| 来源对象 | 收录条件 | 客户视图 |
| --- | --- | --- |
| 本地文件 | 客户明确上传并完成登记 | 我的资产 |
| 连接器文件 | 客户从已授权连接器明确导入 | 我的资产 |
| 外部文件链接 | 客户明确登记，且协议、权限和摘要校验通过 | 我的资产 |
| `KnowledgeSnapshot` / `TaskRevision` | 流水线生成结果创建成功 | 人物原型、剧本 |
| `ApprovedSnapshot` | 分镜或其他可确认结果创建成功 | 分镜 |
| `Artifact` | 图片或视频等结果创建成功且允许预览 | 图片、视频 |
| 搜索候选 / `SourceRevision` / `KnowledgeObject` / `RightsRecord` | 保留为任务输入、项目参考或运营治理 | 不自动进入资产 |
| `DeliveryPackage` | 正式交付包创建成功 | 由交付页面引用，不复制为新资产类型 |

原始搜索结果、人工灵感和未确认输入继续属于任务或项目参考。客户需要长期保存一个文件时，必须执行“导入到我的资产”，由服务端创建稳定版本、摘要和权限引用。流水线结果进入“创作结果”，可以先以草稿或待确认状态出现，只有 `confirmed` 和 `delivered` 可以正式复用。

## 5. 客户核心流程

### 5.1 浏览和查找

客户可以：

- 在“我的资产”按文件类型、文件夹、项目、来源和更新时间筛选。
- 在“创作结果”按结果类型、项目、来源任务、确认状态和更新时间筛选。
- 使用名称、标签和安全摘要搜索，不对受限正文建立不受控全文索引。
- 在列表中看到缩略预览、类型、更新时间，以及适用于当前视图的处理或可复用状态。
- 查看空、加载、错误、部分结果和投影更新中的明确状态。

### 5.2 管理我的资产

客户可以：

- 创建、重命名和进入文件夹；文件夹只改变组织关系，不改变文件事实。
- 上传本地文件，或从已授权连接器导入文件；导入必须显示来源、版本和处理状态。
- 预览文件、查看大小和更新时间，等待 OCR、转写、缩略图或摘要处理完成。
- 将资料加入当前创作或保存为项目参考；提交时服务端重新校验权限、版本、权利和用途。

搜索候选、来源证据和临时执行文件不能通过列表刷新自动出现。只有客户明确执行导入或上传动作，才会建立工作区资料引用。

### 5.3 查看创作结果详情

详情页至少展示：

- 名称、类型、预览和业务摘要。
- 当前有效版本及历史版本入口。
- 来自哪个项目和任务，以及必要的输入与批准摘要。
- 复用状态、版本和限制摘要；完整权利记录只在运营面治理。
- `可以使用`、`需要确认`、`不可用于新任务` 或 `仅供参考`。
- 最近使用任务和下游影响摘要。
- 一个主要动作：加入当前任务或以此开始新创作。

客户不看到数据库 ID、ObjectKey、完整 Runtime 事件、服务商密钥和敏感本地路径。

### 5.4 加入新任务

```text
客户选择工作区资料或创作结果
  -> 服务端重新校验租户、版本、权利和用途
  -> 固定 subject ref + version + digest
  -> 写入 WorkTask 输入快照
  -> 记录 reuse lineage
  -> 返回任务中的业务名称和预览
```

加入任务使用引用，不复制正文。资产在页面打开后若已失效，提交时必须返回当前状态和恢复方法，不能按过期页面继续创建任务。

### 5.5 AI 理解资料

客户可以对“我的资产”中的资料发起受控理解动作：

- 文档提取、OCR、视频/音频转写、摘要和标签建议。
- 将理解结果作为本次任务的输入摘要或项目参考，而不是覆盖原文件。
- 从资料直接开始已发布的创作场景；系统按场景契约选择需要的字段和预览。

AI 理解任务必须绑定 `material_ref + version/digest`，输出继承原资料的数据分类。模型不能自动认定资料真实、拥有权利或已经批准，也不能因为理解成功就把资料变成创作结果。

### 5.6 自动沉淀

- 客户保存的灵感保留为当前任务或项目参考。
- 流水线生成的人物、剧本、分镜和内容版本自动进入相应结果分类。
- 从确认结果生成的图片和视频自动进入媒体结果分类。
- 正式交付包由交付页面引用，不复制成另一类资产。
- 同一底层对象不会因为被多个任务引用而复制成多个目录项。
- 普通工作区资料只在客户明确上传或导入后进入“我的资产”；生成结果只进入“创作结果”投影。

## 6. 客户状态

| 状态 | 客户含义 | 允许动作 |
| --- | --- | --- |
| `draft` | 结果仍在编辑或生成 | 查看，不可复用 |
| `pending_confirmation` | 等待客户确认 | 查看、确认或提出修改 |
| `changes_requested` | 已要求修改 | 查看新版本，不可复用旧结果 |
| `confirmed` | 结果已确认，可以复用 | 加入任务、开始新创作、查看来源任务 |
| `delivered` | 结果已进入交付 | 加入任务、下载交付引用、查看来源任务 |
| `superseded` | 已有更新版本 | 打开当前版本，历史只读 |
| `blocked` | 输入权利、批准或可见性不满足 | 查看原因和替代结果 |

这些状态由结果目录投影根据底层事实确定，不新增可被客户直接修改的结果状态机。普通工作区资料使用独立的 `processing_state`：`uploading / processing / ready / failed`。只有 `confirmed` 和 `delivered` 的生成结果 `reusable` 为真。

## 7. 运营资产治理

运营侧需要同时查看工作区资料、结果资产和它们引用的输入治理对象。底层对象可以出现在运营面，但不能因此改变客户资产入口的两个投影边界。

运营侧需要：

- 按租户、项目、对象类型、权利状态、失效原因和投影游标筛选。
- 查看底层事实对象、来源、批准决定、生成任务、交付和使用影响。
- 处理权利审核、来源失效、重复分组、敏感预览和错误分类。
- 处理导入失败、预览失败、超大文件、恶意文件和连接器授权过期。
- 触发可审计的目录重建或单项重投影，但不能直接修改业务正文。
- 从失效对象查看哪些新任务输入、待批准成果和未完成交付受到影响。

运营修复必须调用事实拥有域的命令。例如权利问题由 `RightsRecord` 的命令修复，目录随后重投影；不能在目录项上写一个“强制可用”状态覆盖底层事实。

## 8. 权限和隔离

- 查询和详情均按 tenant、project、membership 和对象可见性校验。
- 跨项目资产默认不可见，只有租户策略允许且对象范围允许时才能复用。
- Confidential 和 Restricted 内容不得生成公开缩略图或被普通搜索索引泄露。
- 已生成预签名预览地址必须短期有效、绑定权限并进入审计。
- 客户分享、公开审核和资产库访问使用不同授权上下文，不能复用 URL 权限。

## 9. 指标

### 客户价值

- 新任务使用已有资产的比例。
- 找到目标资产的 P50 / P95 时间。
- 从资产库开始新任务到首个可确认结果的时间。
- 资产搜索无结果率、筛选放弃率和重复上传率。

### 平台复利

- 每个完成任务沉淀的可复用资产数量。
- 已确认结果的后续复用次数。
- 因复用减少的重复采集、重复生成和重复审核次数。
- 失效资产在新任务创建前被阻止的比例。

### 运营质量

- 权利待审核和即将到期队列规模。
- 重复目录项率和投影延迟。
- 从失效发现到阻止新使用的时间。
- 目录重建成功率和追溯完整率。

## 10. 第一阶段范围

### 必须完成

- 客户资产入口、我的资产/创作结果/最近使用视图和清晰的空状态。
- 我的资产最小工作区契约：文件夹、上传/导入、文件类型筛选、预览和处理状态；不扩张结果资产 DTO。
- 统一客户查询入口的搜索、筛选和详情预览，但两个投影使用独立契约。
- 五类结果类型与七项有限状态集合，类型和状态独立筛选。
- 来源、版本、权利和追溯摘要。
- 从资产库加入已有或新建任务的引用闭环。
- KnowledgeSnapshot、TaskRevision、ApprovedSnapshot 和合法 Artifact 等生成结果的自动沉淀；输入型对象不进入目录，DeliveryPackage 只进入交付视图。
- 摘要去重、使用历史和失效传播。
- 客户与运营独立 DTO、权限和错误语言。

### 延后

- 复杂批量编辑、批量标签和自动分类训练。
- 任意关系图、三维资产画布和自由编排。
- 全盘文件扫描、桌面同步盘、通用网盘同步和复杂连接器市场。
- 跨租户资产市场或公共模板交易。
- 自动根据效果数据修改资产或批准策略。

## 11. 验收标准

1. 客户无需理解 `SourceRevision`、`ApprovedSnapshot` 或 `Artifact`，可以在“我的资产”管理资料，并在“创作结果”找到并复用已有成果。
2. 同一底层对象只在其所属投影中生成一个稳定条目；重建投影不会产生重复正文或外部调用。
3. 上传/导入资料和创作结果使用独立契约与状态轴，文件处理失败不会伪装成结果阻断。
4. 加入任务时固定版本和摘要，后续更新不会静默改写进行中的任务。
5. 权利过期、来源撤回或跨租户引用会在服务端被阻止，并返回可操作原因。
6. 搜索候选和灵感只有在客户明确导入或保存为项目参考后才留下稳定引用。
7. 已确认的生成结果自动沉淀，完成一次任务后能直接成为下一次任务输入。
