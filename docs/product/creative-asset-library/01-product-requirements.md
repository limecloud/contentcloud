# 创作资产库产品需求

状态：`需求边界已冻结；客户结果目录与任务复用首切片已实现，其余能力实施中`。

更新时间：2026-08-07。

## 1. 问题与目标

客户今天可能在任务、来源、审核结果和交付页面中分别看到同一项目的内容，却无法形成稳定的“我们已经拥有并且可以再次使用什么”心智。结果是每条新流水线都重新找资料、重新确认人物和品牌表达、重新定位已批准脚本与媒体，平台的历史产出没有形成复利。

创作资产库的目标是：

- 让客户在一个入口中找到跨任务可复用的人物原型、剧本、分镜、图片和视频结果。
- 让客户在开始新任务时直接选择已有创作结果，而不是重复生成和重复确认。
- 让每个结果清楚显示来源任务、项目、版本、状态、可复用状态和使用历史。
- 让运营人员治理失效、重复、敏感预览和权利风险，不把这些复杂度暴露给客户。

当前代码已经提供五类结果目录、类型与状态筛选、可复用结果加入同项目任务，以及灵感保留为项目参考的客户闭环。详情页历史版本、专用持久化投影、目录重建、运营治理、完整权利失效传播和发布指标仍属于本需求的未完成范围。

## 2. 目标用户

| 角色 | 核心任务 | 看到的语言 |
| --- | --- | --- |
| 客户创作者 | 查找、比较、预览并加入新任务 | 可用、需确认、不可使用、来自哪里 |
| 客户审批人 | 确认正式版本、表达边界和复用影响 | 已批准版本、变更、权利和使用范围 |
| 租户管理员 | 管理本租户可见范围和成员访问 | 项目范围、敏感级别和共享策略 |
| 平台内容运营 | 处理分类、重复、失效和资产沉淀规则 | 底层对象、目录策略、来源和影响范围 |
| 平台运行运营 | 诊断索引、投影延迟和重建失败 | 游标、重建任务、错误码和追溯链 |

## 3. 客户信息架构

客户一级导航中的“品牌资料”演进为“资产库”，但“交付”仍保留为任务交付入口。来源资料、灵感、知识、参考素材和权利记录属于任务输入或项目参考，不进入客户创作资产库：

```text
客户创作台
├── 今天
├── 创作任务
├── 资产库
│   ├── 人物原型
│   ├── 剧本
│   ├── 分镜
│   ├── 图片
│   └── 视频
└── 交付
    ├── 待确认结果
    └── 当前任务交付包
```

二者的区别：

- **资产库：** 跨任务积累、查找和复用。
- **交付：** 完成当前任务、核对完整性和下载正式交付包。

五项是结果类型。结果状态通过另一组筛选表达：草稿、待确认、需修改、已确认、已交付、已被替代、已阻止；产品页面可以按“需要处理”等业务视图聚合，但类型字段与状态字段不能混用。交付页面引用当前任务的交付事实，不为导航视图复制资产正文。

## 4. 目录收录策略

资产库不能把每一次搜索返回和每一个临时候选全部展示给客户，否则很快退化为不可管理的结果堆积。

首期收录规则：

| 来源对象 | 自动收录条件 | 默认分类 |
| --- | --- | --- |
| `KnowledgeSnapshot` / `TaskRevision` | 流水线生成结果创建成功 | 人物原型、剧本 |
| `ApprovedSnapshot` | 分镜或其他可确认结果创建成功 | 分镜 |
| `Artifact` | 图片或视频等结果创建成功且允许预览 | 图片、视频 |
| `SourceRevision` / `Asset` / `KnowledgeObject` / `RightsRecord` | 保留为任务输入或项目参考 | 不进入客户创作资产库 |
| `DeliveryPackage` | 正式交付包创建成功 | 由交付页面引用，不复制为新资产类型 |

原始搜索结果、人工灵感和未确认输入继续属于任务或项目参考；只有流水线生成的结果才进入客户创作资产库。结果可以先以草稿或待确认状态出现，只有 `confirmed` 和 `delivered` 可以复用。

## 5. 客户核心流程

### 5.1 浏览和查找

客户可以：

- 按结果类型、项目、来源任务、状态和更新时间筛选。
- 使用名称、标签和安全摘要搜索，不对受限正文建立不受控全文索引。
- 在列表中看到缩略预览、资产类型、更新时间和可复用状态。
- 查看空、加载、错误、部分结果和投影更新中的明确状态。

### 5.2 查看详情

详情页至少展示：

- 名称、类型、预览和业务摘要。
- 当前有效版本及历史版本入口。
- 来自哪个项目和任务，以及必要的输入与批准摘要。
- 复用状态、版本和限制摘要；完整权利记录只在运营面治理。
- `可以使用`、`需要确认`、`不可用于新任务` 或 `仅供参考`。
- 最近使用任务和下游影响摘要。
- 一个主要动作：加入当前任务或以此开始新创作。

客户不看到数据库 ID、ObjectKey、完整 Runtime 事件、服务商密钥和敏感本地路径。

### 5.3 加入新任务

```text
客户选择资产
  -> 服务端重新校验租户、版本、权利和用途
  -> 固定 subject ref + version + digest
  -> 写入 WorkTask 输入快照
  -> 记录 reuse lineage
  -> 返回任务中的业务名称和预览
```

加入任务使用引用，不复制正文。资产在页面打开后若已失效，提交时必须返回当前状态和恢复方法，不能按过期页面继续创建任务。

### 5.4 自动沉淀

- 客户保存的灵感保留为当前任务或项目参考。
- 流水线生成的人物、剧本、分镜和内容版本自动进入相应结果分类。
- 从确认结果生成的图片和视频自动进入媒体结果分类。
- 正式交付包由交付页面引用，不复制成另一类资产。
- 同一底层对象不会因为被多个任务引用而复制成多个目录项。

## 6. 客户状态

| 状态 | 客户含义 | 允许动作 |
| --- | --- | --- |
| `draft` | 结果仍在编辑或生成 | 查看，不可复用 |
| `pending_confirmation` | 等待客户确认 | 查看、确认或提出修改 |
| `changes_requested` | 已要求修改 | 查看新版本，不可复用旧结果 |
| `confirmed` | 结果已确认，可以复用 | 加入任务、开始新创作、查看来源任务 |
| `delivered` | 结果已进入交付 | 加入任务、下载交付引用、查看来源任务 |
| `superseded` | 已有更新版本 | 打开当前版本，历史只读 |
| `blocked` | 输入权利、批准或可见性不满足 | 查看原因和替代结果 |

这些状态由结果目录投影根据底层事实确定，不新增可被客户直接修改的资产状态机。只有 `confirmed` 和 `delivered` 的 `reusable` 为真。

## 7. 运营资产治理

运营侧需要同时查看结果资产和它们引用的输入治理对象。底层对象可以出现在运营面，但不能因此成为客户资产类型。

运营侧需要：

- 按租户、项目、对象类型、权利状态、失效原因和投影游标筛选。
- 查看底层事实对象、来源、批准决定、生成任务、交付和使用影响。
- 处理权利审核、来源失效、重复分组、敏感预览和错误分类。
- 触发可审计的目录重建或单项重投影，但不能直接修改业务正文。
- 从失效对象查看哪些新任务输入、待批准成果和未完成交付受到影响。

运营修复必须调用事实拥有域的命令。例如权利问题由 `RightsRecord` 的命令修复，目录随后重投影；不能在目录项上写一个“强制可用”状态覆盖底层事实。

## 8. 权限和隔离

- 查询和详情均按 tenant、project、membership 和对象可见性校验。
- 跨项目资产默认不可见，只有租户策略允许且对象范围允许时才能复用。
- Confidential 和 Restricted 内容不得生成公开缩略图或被普通搜索索引泄露。
- 已生成预签名预览地址必须短期有效、绑定权限并进入审计。
- 客户分享、公开审核和资产库访问使用不同授权上下文，不能复用 URL 权限。

## 9. 指标

### 客户价值

- 新任务使用已有资产的比例。
- 找到目标资产的 P50 / P95 时间。
- 从资产库开始新任务到首个可确认结果的时间。
- 资产搜索无结果率、筛选放弃率和重复上传率。

### 平台复利

- 每个完成任务沉淀的可复用资产数量。
- 已确认结果的后续复用次数。
- 因复用减少的重复采集、重复生成和重复审核次数。
- 失效资产在新任务创建前被阻止的比例。

### 运营质量

- 权利待审核和即将到期队列规模。
- 重复目录项率和投影延迟。
- 从失效发现到阻止新使用的时间。
- 目录重建成功率和追溯完整率。

## 10. 第一阶段范围

### 必须完成

- 统一目录列表、搜索、筛选和详情预览。
- 五类结果类型与七项有限状态集合，类型和状态独立筛选。
- 来源、版本、权利和追溯摘要。
- 从资产库加入已有或新建任务的引用闭环。
- KnowledgeSnapshot、TaskRevision、ApprovedSnapshot 和合法 Artifact 等生成结果的自动沉淀；输入型对象不进入目录，DeliveryPackage 只进入交付视图。
- 摘要去重、使用历史和失效传播。
- 客户与运营独立 DTO、权限和错误语言。

### 延后

- 复杂批量编辑、批量标签和自动分类训练。
- 任意关系图、三维资产画布和自由编排。
- 全盘文件扫描、桌面同步盘和通用网盘能力。
- 跨租户资产市场或公共模板交易。
- 自动根据效果数据修改资产或批准策略。

## 11. 验收标准

1. 客户无需理解 `SourceRevision`、`ApprovedSnapshot` 或 `Artifact`，可以找到并复用一个已有成果。
2. 同一底层对象只生成一个稳定目录项，重建投影不会产生重复正文或外部调用。
3. 加入任务时固定版本和摘要，后续更新不会静默改写进行中的任务。
4. 权利过期、来源撤回或跨租户引用会在服务端被阻止，并返回可操作原因。
5. 客户可从资产详情理解来源和可用范围；运营可继续追溯到完整事实链。
6. 已确认的生成结果自动沉淀，完成一次任务后能直接成为下一次任务输入。
