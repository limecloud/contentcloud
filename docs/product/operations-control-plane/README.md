## 2. 定位

运营后台不是“客户后台加几个高级菜单”，也不是把数据库表搬到网页上。它是平台运营人员用来设计、发布、维护和排查创作产品的工作台。

```text
客户 Studio
  只完成创作目标、资料、确认和交付

平台运营后台
  发布创作产品、管理能力和执行方式、处理运行和创作结果风险

任务运行底层
  记录任务如何执行、哪里失败、外部服务是否真正完成
```

简单说：运营后台负责“怎么运营”，任务运行底层负责“实际发生了什么”，业务系统负责“资料、审批、结果和交付是什么”。三者互相引用，但不能互相改写。

## 3. 设计目标

运营人员最终可以在不改代码的情况下：

1. 预览、验证、小范围试跑、发布和回退一套创作产品。
2. 管理平台提供的能力、执行方式、技能包、资料连接和外部服务。
3. 根据客户、资料敏感程度、地区、预算和健康情况选择合适的执行方式。
4. 从客户当前步骤找到对应的任务、失败位置、执行方式和外部请求。
5. 处理失败、结果不明、权利失效、目录延迟、重复结果和费用异常。
6. 对每个高风险动作给出影响摘要、版本差异和可审计回退路径。

运营后台不允许：

- 在页面粘贴任意脚本，把它冒充成平台能力。
- 直接修改数据库、任务历史、客户审批或交付结果。
- 把客户产品写死到某个 Codex、Claude Code 或服务商。
- 用“强制成功”“删除记录”“再次提交”掩盖没有核对清楚的问题。
- 把 SOP、技能包、服务商、租约和底层事件展示给客户。

## 4. 一眼看懂的分层

```text
创作产品版本
  ├── 客户要完成的步骤
  ├── 平台内部的流程和确认点
  ├── 需要哪些能力
  ├── 结果如何呈现、是否进入创作结果目录
  └── 哪些客户可以使用

能力目录
  ├── 需要什么资料、产出什么结果
  ├── 能处理什么敏感程度的资料
  ├── 是否会调用外部服务
  ├── 时间、费用和数量限制
  └── 已经批准的做法

执行方式与技能包
  ├── 执行方式：云端程序 / Codex / Claude Code / 外部服务 / 人工
  ├── 技能包：某种能力的具体做法和版本
  ├── 资料连接和外部服务
  └── 健康、证据和权限

绑定规则
  ├── 客户 / 项目 / 地区 / 资料策略
  ├── 优先顺序和安全回退
  ├── 预算和并发
  └── 是否需要审批

运行快照
  └── 任务开始时固定本次使用的能力、执行方式、技能包和规则

运行诊断
  └── 任务、步骤、尝试、连接状态、外部请求和事件
```

## 6. 当前交付边界

- 创作产品、版本、发布结果和客户开通复用现有服务端写契约，页面提供真实创建、编辑、校验、发布、回退和开通流程。
- 能力目录来自 `work-os` 事实；执行端和技能包分别使用独立 Operations BFF，不再由客户环境或本地夹具补数。
- 任务记录直接使用 `/api/bff/runtime/*`；异常处理、客户管理、操作审计和任务用量只展示服务端已有事实。
- 可选目录请求失败不会拖垮产品运营页，各目录在自己的工作面显示局部错误和重试动作。
- 未交付领域不出现在导航和路由中；未知及已删除后台 URL 统一进入后台通配路由并返回运营总览。

目标页面、中文改名和删除条件见 [《运营后台页面蓝图与中文语言规范》](./04-page-blueprints-and-language.md) 第 20 节。

## 7. 必须守住的规则

1. 客户产品只说需要什么能力，不写死某个工具或服务商。
2. 技能包只是某种能力的具体做法，必须有版本和负责人。
3. 任务一旦开始，就固定本次实际使用的执行方式；后台不能悄悄替换。
4. 自动回退不能扩大资料、权限、外部影响或预算。
5. 所有运营操作都要有权限、原因、版本检查和审计记录。
6. 运行诊断只提供安全的处理动作，不提供“强制成功”或“删除记录”。
7. 创作结果治理只能处理目录和待办，不能改写资料、审批、交付等原始事实。
8. 页面要显示数据更新时间和延迟，不能把旧数据装成实时状态。

当前页面只使用已有 BFF 真实数据；执行端不再由客户 Environment 记录代替，技能包只投影服务端启动时已经完成签名校验的 `skill_pack` Registry 条目。Registry 未配置时返回明确的未配置状态和空数组；已发布的 Registry 条目也不自动等同于业务审批完成或已经被客户任务使用。没有后端契约的对象和指标不注册页面，不填充演示数量。

执行端状态采用三轴投影：Presence（连接存在性）、Environment（环境就绪度）和 Runtime（执行可用性）。WSS 只负责低延迟 current-state、`runtime.available` 唤醒和断线重连；HTTPS 负责命令、租约、事件、终态提交和 Attempt-scoped MCP Gateway。Daemon 在启动及每 5 分钟探测完整 Runtime inventory，运营详情显示版本、健康、选中态和稳定错误码；选中 Runtime 不健康时只阻断新 Attempt。在线不等于环境 ready，环境/Plugin/Skill/MCP generation 漂移时必须新建 Agent 会话。

当前协议安全边界：WSS 首帧为 `control.sync_state`，`control.ready` 之后才发送 `runtime.available`；同一 DaemonInstance 使用 `connection_epoch + report_seq` 做乱序和旧连接 fencing，45 秒 `last_seen_at` 之外视为 stale。新进程连接时旧 live 实例停止，旧实例不能再覆盖新实例的 Presence。Runtime Gateway 返回相对同源路径，Agent 只接收 Attempt 短期 `rtg_` token，不接触设备 `dt_`、Workspace 或 Run token；`prepared` token 只用于等待 activate，不能调用 MCP 工具。
