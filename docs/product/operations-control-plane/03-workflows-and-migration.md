# 运营后台工作流、上线与清理计划

状态：`目标实施计划；用于拆分产品、工程和运营工作`。

更新时间：2026-08-08。

## 1. 工作流总原则

运营后台所有事情都围绕五个问题：

1. 客户现在能使用哪个创作产品？
2. 这个产品需要哪些能力？
3. 每种能力当前由谁、用什么方式完成？
4. 任务出了问题，能不能找到原因并安全恢复？
5. 生成结果是否可复用、可交付、权利清楚？

任何页面动作都必须落到其中一个问题，不能增加“看起来能配、实际上没人负责”的设置项。

## 2. 发布一个创作产品

以“IP 人设视频”为例，运营人员按以下顺序工作：

```text
整理客户步骤
  -> 检查输入和结果
  -> 选择需要的能力
  -> 预览每种能力的执行方式
  -> 小范围试跑
  -> 发布给指定租户
  -> 观察并按需回退
```

### 2.1 整理客户步骤

运营人员只配置客户能理解的内容：步骤名称、需要提交的资料、客户要做的确认、完成后能看到的结果。SOP、Stage、Gate 等内部名称可以在高级信息中显示，但不能成为客户的必填配置语言。

### 2.2 检查输入和结果

系统自动检查：

- 每个步骤是否说明需要什么资料。
- 是否存在没有结果呈现的步骤。
- 是否存在客户无法完成的决定。
- 是否引用了已经停用的能力。
- 是否超过租户、资料等级、成本或时长限制。

检查不通过时，页面要告诉运营人员“哪一步、为什么、怎么改”，不能只显示一串错误码。

### 2.3 预览执行方式

系统根据绑定规则给出候选组合，例如：云端 Worker、本地 Codex、Claude Code 或人工。运营人员确认的是“允许哪些方式”，不是把某个客户任务手工指向某台机器。

### 2.4 小范围试跑

Canary 只使用指定租户、指定比例或内部样例。试跑报告至少包括：完成率、失败类型、资料披露、平均耗时、费用、结果质量和人工介入次数。任何高风险资料和外部副作用都必须使用隔离环境或明确的测试额度。

### 2.5 发布与回退

发布前显示版本差异、影响租户、当前运行数量、回退版本和审计人。回退只影响新任务，已经开始的任务继续使用当时的运行快照，除非走单独的恢复流程。

## 3. 注册和发布一个技能包

```text
提出能力需求
  -> 提交技能包
  -> 自动检查输入/输出、工具和资料限制
  -> 固定样例测试
  -> 运营审核说明和支持手册
  -> 小范围 Canary
  -> 进入可选列表
  -> 被绑定规则引用
```

审核清单：

- 它解决的是哪个 Capability，不能只写“万能 Agent”。
- 输入和输出是否有明确格式，失败是否可识别。
- 能访问哪些资料、工具和网络，是否超过能力要求。
- 是否会产生外部副作用，unknown 如何对账。
- 费用、超时、并发和重试是否有上限。
- Codex、Claude Code、本地客户端或 Provider 断开后如何恢复。
- 是否有负责人、支持手册、版本摘要和回退版本。

技能包被暂停时，不删除历史记录；系统停止新任务使用，并显示受影响的 Experience 和租户。

## 4. 修改绑定规则

绑定规则的修改可能影响大量新任务，必须经过模拟和审批：

1. 复制当前规则生成草稿。
2. 指定租户、项目、资料等级和时间范围进行模拟。
3. 查看命中规则、被排除候选、预计成本和没有候选的情况。
4. 对比旧规则和新规则，确认是否扩大权限、资料范围、副作用或预算。
5. 通过审批后发布新版本。
6. 观察新任务的命中率、失败率和成本；异常时停用新版本。

模拟器不得偷偷启动真实任务。它只读取目录、健康和策略数据，输出可复现的选择结果。

## 5. 运行异常处理

### 5.1 普通失败

运行运营打开任务详情后，先看客户任务、创作产品版本、运行快照和失败步骤，再决定：等待、暂停、取消未开始步骤、创建新的尝试或联系支持。恢复动作必须保留失败记录和原始输入摘要。

### 5.2 本地执行者离线

如果 Codex 或 Claude Code 客户端断开：

- 客户看到“创作工具暂时离线，已保留进度”。
- 运营后台看到最近心跳、受影响步骤和租约过期时间。
- 如果有预先批准且不扩大权限的回退方式，可以让新尝试使用回退；否则等待重新连接或人工处理。
- 不能把一个正在运行的本地任务直接改成另一种执行方式。

Daemon 的同步不依赖页面打开：启动/重连先建立 WSS 并发送完整 current-state；心跳或状态变化发送新的序列；收到 `runtime.available` 后本地 worker 再通过 HTTPS `prepare_next` 领取。HTTPS 的 `activate`、`heartbeat`、`event`、`finalize` 是唯一执行事实，MCP Gateway 只在 running Attempt 的同源短期 token 和 fence 有效时工作。Plugin、Skill、MCP 或 Environment generation 变化会冻结旧会话并要求新会话，不能在运行中静默切换。

执行端接入和维护单独走“登记、客户确认、健康检查、暂停/恢复”流程。运营后台可以撤销平台侧允许，但不能替客户完成本地授权，也不能通过后台读取本地文件。客户侧只看到“创作工具已连接、需要重新连接或暂时离线”，不显示租约、心跳和工具白名单。

### 5.3 外部结果不明

外部服务已发出请求但没有明确结果时，状态标记为“结果待核对”：

```text
请求记录 -> 等待服务商查询/回调 -> 对账成功
                                -> 对账失败，创建补偿或人工处理
```

在核对完成前，页面不能提供“再次提交”按钮。对账失败也不能删除原记录或把任务强行标为成功。

## 6. 资产治理工作流

### 6.1 权利或来源失效

```text
收到失效信号
  -> 找到受影响创作结果
  -> 阻止新的不安全引用
  -> 通知责任人和租户
  -> 选择替换、撤下或保留历史
  -> 记录处理结果
```

治理后台只能处理目录投影、影响关系和待办；真正的来源、权利、批准和交付状态由拥有它们的业务模块变更。

### 6.2 重复候选

系统只给出候选，不自动合并。运营人员看到相似依据、使用情况、权利状态和可能影响后，选择保留主项、建立关联或忽略候选。合并不会删除历史结果，只改变目录关系。

### 6.3 投影重建

重建前显示范围、预计耗时、失败分片和读模型差异。重建使用历史事实重新计算目录，不调用搜索、模型、Provider 或其他外部副作用。完成后需要摘要对账和审计记录。

## 7. 租户启用工作流

租户启用不是打开一个总开关，而是确认：

- 使用哪个已发布的创作产品版本。
- 允许哪些资料等级和地区。
- 是否允许本地 Codex/Claude Code 执行。
- 预算、并发和通知策略。
- 默认审批人和支持联系人。

启用前显示能力覆盖和风险；暂停后停止新任务，保留历史结果和运行记录。租户管理员只能管理自己的成员、项目和偏好，不能修改平台能力或服务商凭据。

## 8. 分阶段迁移计划

迁移不是一次性重写。每一阶段都有可验证产物和退出条件。

### O0：统一说法，停止继续堆旧页面

产物：术语表、产品面边界、对象所有权、旧入口清单、负责人。

退出条件：团队不再把客户面板、运营后台和 Runtime Explorer 当成一个页面；新需求必须注明属于哪个产品面。

### O1：运营后台外壳与总览

产物：独立 `/admin` Shell、中文“平台运营后台”标题、运营总览、我的待办、数据新鲜度提示。旧 `AdminWorkOSPage` 及其独立路由已经删除。

退出条件：运营人员能从总览找到发布风险、运行异常和资产待办；旧“运行基础设施”标题和 `AdminWorkOSPage` 不再作为默认首页，不承载新模块。

### O2：创作产品发布中心

产物：Experience 草稿、验证、发布、回退和客户开通；当前前端已落地产品/版本深链、草稿编辑、发布检查、只读发布预览、目标客户环境执行绑定预览、版本治理、服务端事实驱动的发布结果页、客户开通列表/筛选/详情和四步开通向导，SOP、Gate 和 Environment 写操作继续复用已有 BFF。预览接口只读取版本、Lint、能力登记、执行端登记和环境配置，不选择 Provider、不创建运行快照；Canary 仍需独立试跑契约后再接入，不在前端伪造状态。

退出条件：不改代码即可发布一个由已批准原语组成的创作产品；客户只看到简单步骤；旧混合配置页不再增加新写操作。

### O3：能力、执行方式和技能包目录

产物：Capability、Executor、Skill 分开管理；技能包有版本和验证证据。当前已落地由真实 BFF 字段驱动的能力列表、能力版本详情、产品版本和客户环境反向引用；执行端已建立独立 Operations BFF，并落地列表/详情深链、DaemonInstance 三轴健康、45 秒 freshness、设备版本、能力声明和项目授权；技能包已建立独立 Operations BFF，以服务端已验证插件 Registry 的 `skill_pack` 条目提供列表/版本深链、供应链摘要、签名状态、评测证据、权限、数据流、费用、输出契约和撤销事实。WSS/HTTPS/Attempt Gateway 的安全边界、旧连接 fencing 和 Agent 凭据隔离已进入当前实现。页面明确区分“已登记”“已批准”和“健康可用”，客户 Environment 不再代替执行端，Registry 发布也不代替业务审批。Connector、Provider 及完整 SkillManifest 字段仍等待独立事实契约，因此当前不注册对应页面。

退出条件：一个客户产品只引用能力，不直接绑定 Codex、Claude Code 或供应商；历史绑定可追溯。

### O4：绑定规则和模拟器

产物：按租户、资料等级、区域、预算和健康状态选择执行方式；发布前可模拟和审批。

退出条件：新任务命中结果可复现；规则变化不会悄悄改变进行中的任务。

### O5：Runtime Explorer 产品化

产物：从客户任务反查运行、步骤、尝试、租约、外部结果和审计；失败恢复、Effect 对账和支持编号可用。当前 `/admin/jobs` 已读取真实 Runtime BFF，展示准入冻结身份、节点、脱敏 Agent/ContextView、事件、检查点和 Effect；页面动作由服务端返回。事件回放会校验持久化事件并重建投影，安全检查点可以创建继承不可变输出的新分支，`unknown` Effect 只能进入对账，不会重新提交外部请求。

退出条件：运营人员不查数据库也能完成常见故障处理；任何恢复都不会删除历史或重复外部请求。当前已完成恢复闭环首切片；完整执行图、Attempt/租约、共享状态、费用和支持案例仍未达到本阶段完整退出条件。

### O6：资产治理

产物：创作结果目录、权利/来源失效、重复候选、投影重建和影响范围。

退出条件：结果可安全复用；失效资料能阻止新引用；投影重建不触发外部副作用。

### O7：兼容清理

产物：旧入口、旧宽接口、重复配置和临时页面的退场清单与删除记录。当前已删除 `/admin/environments`、`/admin/sops`、`/admin/gates`、`/admin/usage`、`/admin/runtime` 和旧后台聚合页；同时删除没有事实契约的 `/admin/connectors`、`/admin/providers`、`/admin/policies`、`/admin/effects`、`/admin/results`、`/admin/rights`、`/admin/duplicates`、`/admin/projections`、`/admin/users`、`/admin/support` 占位路由。任务记录统一使用 `/admin/jobs`，Runtime BFF 统一使用 `/api/bff/runtime`。

退出条件：旧路径没有活跃调用、历史可读、回退演练通过、代码搜索没有新依赖。当前无活跃用户，首轮前端与 Runtime BFF 兼容清理已经完成；后续新增重复入口由架构检查阻止。

## 9. 产品、工程、运营验收指标

| 方向 | 试点目标 |
| --- | --- |
| 发布效率 | 运营人员从草稿到 Canary 不超过 7 个主要步骤 |
| 问题定位 | 从告警到对应客户任务不超过 3 次跳转 |
| 绑定透明 | 任一新任务都能说明为什么选择该执行方式 |
| 安全恢复 | unknown 结果没有重复提交；回退不丢历史 |
| 客户隔离 | 客户页面不出现 Skill、Provider、租约、Runtime 事件等术语 |
| 资产治理 | 失效权利能阻止新引用，目录重建可复现 |
| 运行质量 | 运行快照、费用、外部请求和结果可关联 |
| 清理效果 | 每阶段关闭至少一个旧入口或重复配置来源 |

指标先用于试点观察，不把未验证的数字写成产品承诺。

## 10. 明确不做的事情

- 不建设让运营人员随意画流程、粘贴脚本、编辑任意 Prompt 的低代码平台。
- 不把所有后台能力塞进一个“系统设置”页面。
- 不要求所有客户安装 Codex 或 Claude Code；它们只是执行方式之一。
- 不把客户上传资料、任务输入、创作结果和平台配置混成一个资产表。
- 不用“强制成功”“删除事件”“重新提交未知请求”代替真正的恢复流程。
- 不在没有使用数据、负责人和退场条件的情况下保留旧页面。

## 11. 每阶段的回退规则

每个阶段发布前必须记录：开关范围、旧权威路径、数据对账方式、回退负责人和不可逆影响。回退只切换新入口或新写入方，不删除已经生成的版本、运行、审计和资产历史。任何需要删除历史或生产数据的动作另行评审，不属于普通迁移步骤。
