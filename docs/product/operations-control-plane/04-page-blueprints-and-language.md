# 运营后台页面蓝图与中文语言规范

状态：`目标产品设计；用于后续原型、接口和页面开发`。

更新时间：2026-08-08。

这份文档直接回答三个问题：运营人员登录后先看什么，每个页面可以做什么，页面应该说什么中文。业务人员先看本文；工程字段和接口另见 [02-domain-model-and-contracts.md](./02-domain-model-and-contracts.md)。

## 1. 谁使用这个后台

| 使用者 | 每天最关心的事 | 默认首页重点 |
| --- | --- | --- |
| 内容运营 | 创作产品是否可以发布、客户步骤是否正确 | 待发布版本、试跑结果、客户开通待办 |
| 能力运营 | 能力和技能包是否可用、执行方式是否健康 | 无可用实现、待审核技能包、执行端离线 |
| 运行运营 | 哪些任务卡住、是否需要恢复或核对 | 阻断任务、等待过久、外部结果待核对 |
| 结果治理 | 创作结果能否继续使用、权利是否有效 | 权利待办、来源失效、重复候选、目录延迟 |
| 客户支持 | 某个客户为什么无法继续、如何给出准确答复 | 我的支持案例、关联任务、可对外说明 |
| 平台管理员 | 客户、权限、费用和高风险操作是否正常 | 风险汇总、异常费用、待审批操作 |

同一个人可以拥有多个角色，但页面按工作任务组织，不为每个角色复制一套后台。

│
├── 运行保障

## 3. 所有页面的固定结构

```text
面包屑：创作运营 / 创作产品 / IP 人设视频

页面标题                  [主要操作]
一句话说明                [更多操作]
状态、当前版本、负责人、更新时间

页内标签或筛选
--------------------------------------------------
主要内容：表格、详情或处理工作区
--------------------------------------------------
关联记录、操作历史、支持编号
```

规则：

- 页面标题必须是业务名称，例如“IP 人设视频”，不能是对象类型或内部 ID。
- 页面只设置一个高权重主按钮，例如“创建新版本”或“开始试跑”。
- “删除、停用、回退、取消任务”放入更多操作，并显示影响范围。
- 保存成功后在当前页面反馈，不跳回列表；发布成功后进入发布结果页。
- 列表使用表格，单个对象使用独立详情页；不使用卡片套卡片。
- 页面标题下只说明当前工作目的，不写功能介绍、操作教程或技术原理。

## 4. 运营总览

### 4.1 首屏

```text
运营总览                                      [刷新]
今天有 12 项需要处理                         数据更新于 10:32

待发布 3    运行异常 5    结果风险 2    费用异常 2

我的待办
类型       事项                  影响客户      等待时间    操作
发布审批   IP 人设视频 v2.1      3 家          2 小时      去处理
结果核对   图片生成请求无结果     果木食品      18 分钟     去核对
权利待办   参考视频授权已到期     新茶饮项目    1 天        查看影响

平台动态
最近发布 / 执行端健康变化 / 客户开通 / 高风险操作
```

### 4.2 设计要求

- 首页首先回答“现在最该处理什么”，不把全部指标做成大卡片。
- 四个摘要数字必须可点击，进入带同样筛选条件的列表。
- “我的待办”按风险、等待时长和客户影响排序。
- 没有待办时显示“当前没有需要你处理的事项”，同时保留最近发布和平台健康。
- 数据延迟时，在标题旁显示“数据可能延迟”，不能继续显示虚假的实时数字。

## 5. 创作产品

### 5.1 产品列表

默认标签：`全部`、`草稿`、`试跑中`、`已发布`、`已停用`。

| 列 | 内容 |
| --- | --- |
| 创作产品 | 名称、封面缩略图、适用内容类型 |
| 当前版本 | 对客户生效的版本；没有发布时显示“尚未发布” |
| 使用客户 | 已开通客户数量 |
| 运行情况 | 近 7 天任务量、完成率和异常数 |
| 最近更新 | 时间和负责人 |
| 操作 | 查看；不在表格里堆发布、停用等高风险按钮 |

页面主按钮为“新建创作产品”。新建时只填写名称、用途和客户最终得到什么，创建后进入产品详情继续完善。

### 5.2 产品详情

产品详情不是一张超长表单，使用稳定标签：

```text
概览 | 客户流程 | 所需资料 | 结果设置 | 所需能力 | 版本与发布 | 客户开通
```

“概览”首屏显示：

- 客户最终得到什么。
- 当前发布版本和正在编辑的版本。
- 客户会经历的步骤摘要。
- 需要的能力是否都有可用执行方式。
- 近 7 天任务完成、阻断和平均费用。
- 唯一主操作：“继续编辑”“提交检查”或“创建新版本”。

### 5.3 客户流程编辑

流程编辑使用纵向步骤列表，不默认展示自由画布：

```text
1  灵感采集        客户提供主题和参考       产出：灵感候选
2  人物原型        系统生成，客户确认       产出：人物原型
3  剧本创作        基于已确认人物原型       产出：剧本
4  分镜设计        客户确认关键画面         产出：分镜
5  视频制作        生成并检查               产出：视频
6  交付            客户确认和下载           产出：交付包
```

点开一步后，右侧抽屉只编辑：客户看到的名称、需要的资料、结果展示、是否需要客户确认和所需平台能力。内部流程编号、节点图和执行规则进入“技术信息”，默认收起。

### 5.4 版本发布

发布页固定五步：

```text
检查内容 -> 检查能力 -> 内部预览 -> 小范围试跑 -> 正式发布
```

每一步显示通过、待处理或未开始。正式发布前必须展示：版本变化、开通客户、是否影响进行中任务、预计费用变化、回退版本和审批人。

发布完成页使用明确结论：

```text
IP 人设视频 v2.1 已发布
3 家客户的新任务将使用该版本
进行中的 18 个任务继续使用原版本
[查看发布记录] [返回产品]
```

## 6. 客户开通

客户开通是独立工作面，不藏在租户设置深处。

列表按客户显示：已开通创作产品、固定版本、数据范围、本地执行许可、预算、状态和负责人。开通向导固定四步：

1. 选择客户和已发布产品。
2. 确认资料范围、地区和是否允许本地执行端。
3. 设置预算、并发、默认审批人和通知联系人。
4. 查看能力覆盖与风险后启用。

暂停开通只阻止新任务，不隐藏历史任务和创作结果。页面必须写清楚影响，不能只显示“确定停用吗”。

## 7. 能力目录

能力目录回答“平台能够可靠完成哪些工作”。能力列表按创作阶段分类：资料与洞察、策略、人设、剧本、分镜、媒体制作、审核和交付。

| 列 | 内容 |
| --- | --- |
| 能力 | 中文名称和一句话结果 |
| 可用做法 | 已批准技能包数量 |
| 执行方式 | 云端、本地、外部服务或人工 |
| 健康情况 | 正常、部分可用、不可用 |
| 使用范围 | 被多少创作产品使用 |
| 负责人 | 业务负责人和技术负责人 |

能力详情首先展示“输入什么、得到什么、哪些产品在使用、当前是否可用”。输入输出格式、资料等级和超时等放入“技术信息”。

## 8. 技能包

技能包页面回答“某项能力具体怎么做、是否经过验证”。它必须与能力目录分开管理。

### 8.1 列表与详情

默认标签：`待审核`、`试跑中`、`可用`、`已暂停`、`已退役`。

详情页顺序：

1. 实现什么能力。
2. 当前版本、负责人和可用状态。
3. 可以使用哪些工具和资料。
4. 测试结果、试跑证据和最近失败。
5. 被哪些选择规则和创作产品间接使用。
6. 费用上限、支持手册和技术信息。

运营人员不能在网页里直接粘贴任意 Skill 文件、脚本或 Prompt。技能包通过受控仓库、插件包或已批准的登记流程进入后台，页面负责审核、启用、暂停和查看影响。

### 8.2 审核页

审核页使用“检查清单 + 证据”，而不是一个“通过”开关：能力匹配、输入输出、工具范围、资料范围、网络访问、外部影响、费用、测试、负责人和回退办法必须逐项有结论。

## 9. 执行端、数据连接和生成服务

三者必须独立显示，避免“环境”成为所有技术配置的杂物箱。

### 9.1 执行端

显示云端程序、本地 Codex、本地 Claude Code 和人工执行端。列表重点为：连接状态、最近在线、可运行能力、并发占用、所属客户或区域、近 24 小时失败率。

页面名称使用“执行端”，不使用“Environment”“运行环境”或“本地能力”。

### 9.1.1 执行端接入流程

运营后台管理的是“允许什么、属于谁、是否健康”，不是让运营人员代替客户完成本地授权。接入流程分为四步：

```text
登记执行端 -> 指定客户和资料范围 -> 客户确认连接 -> 健康检查
```

运营页面显示：接入编号、执行端类型、所属客户、允许的能力、资料范围、最近在线、版本和当前状态。客户页面只显示：

```text
创作工具
已连接 / 需要重新连接 / 暂时离线
可用于：灵感采集、资料整理
[重新连接]
```

客户不需要理解“租约、心跳、工具白名单、ContextView”等词。运营后台发现执行端离线时，先判断是否有安全的云端或人工备选，再决定等待、通知客户或暂停新任务。不能在后台直接读取客户本地文件，也不能未经客户确认扩大资料范围。

### 9.2 数据连接

显示搜索接口、网页采集、企业知识库、网盘或其他资料来源。重点为：连接用途、授权客户、授权状态、资料范围、最近同步和失败记录。

凭据只显示“有效、即将到期、已失效”，不显示密钥正文。

### 9.3 生成服务

显示图片、视频、语音和其他外部生成服务。重点为：可提供能力、地区、健康、配额、费用和外部结果核对方式。

供应商名称只能作为具体实现出现，不能代替能力名称。例如列表显示“图片生成 / 服务商 A”，而不是只显示服务商 Logo。

## 10. 选择规则

“选择规则”是页面中文名，技术文档中称 `Binding Policy`。它回答“什么客户、什么资料、什么预算下，优先选择哪种已批准的做法”。

规则详情使用四段式：

```text
适用范围 -> 首选方式 -> 安全备选 -> 费用和权限限制
```

页面主操作为“试算规则”。试算只填写客户、创作产品、资料等级和预计数量，输出：最终选择、选择原因、未选择原因、预计费用、能否安全切换。试算不能创建真实任务或调用外部服务。

发布规则前显示受影响的新任务范围，并明确“进行中的任务不会改变”。

## 11. 任务记录

页面中文名使用“任务记录”，不把 `Runtime` 或 `JobRun` 放在标题上。

### 11.1 列表

默认快速筛选：`进行中`、`等待客户`、`需要处理`、`已完成`、`已取消`。

| 列 | 内容 |
| --- | --- |
| 任务 | 客户能识别的任务名称、运行编号 |
| 客户与项目 | 客户名称、项目名称 |
| 创作产品 | 产品名和固定版本 |
| 当前步骤 | 中文步骤和进度 |
| 状态 | 中文业务状态 |
| 等待时间 | 当前状态持续时间 |
| 费用 | 估算或已结算标记 |
| 更新时间 | 最后变化时间 |

### 11.2 任务详情

```text
任务概况 | 执行步骤 | 外部请求 | 客户确认 | 费用 | 操作记录 | 技术信息
```

“任务概况”先显示客户现在看到什么、任务为什么停在这里、已经保留了什么结果、推荐下一步和支持编号。节点、尝试、心跳、租约、内部事件进入“技术信息”，默认不展开。

可执行按钮必须来自服务端。常见动作翻译为：暂停后续处理、恢复处理、取消未开始步骤、重新安排一次处理、发起外部结果核对、联系客户、创建支持案例。

## 12. 异常处理与外部结果核对

### 12.1 异常处理

异常队列按客户影响优先，而不是按错误发生时间简单倒序。每条异常显示：客户影响、已完成结果、原因分类、系统已经做了什么、建议动作、负责人和等待时间。

处理页采用三栏：左侧异常摘要，中间证据和时间线，右侧当前允许动作。原始日志和内部事件在“技术信息”中按需加载。

### 12.2 外部结果核对

列表状态使用：`等待回执`、`正在核对`、`已找到结果`、`需要人工处理`、`已补偿`。页面主操作为“开始核对”或“继续处理”，绝不提供“再次提交相同请求”。

核对完成后必须说明结果最终去了哪里、费用是否确认、客户任务是否可以继续。

## 13. 创作结果治理

### 13.1 创作结果

这是平台治理视图，不是客户资产库。列表显示人物原型、剧本、分镜、图片和视频，重点为客户、来源任务、确认状态、权利状态、复用次数、交付状态和目录更新时间。

点击结果打开独立详情页，并使用与客户资产详情一致的内容渲染器：人物原型为结构化信息，剧本为文档阅读器，分镜为镜头列表和画面，图片为大图，视频为播放器。治理信息位于内容下方或侧栏，不遮挡结果本身。

### 13.2 权利待办

每条待办显示哪项权利或来源失效、影响多少结果和新任务、是否已经阻止复用、需要谁处理。主要动作是“查看影响”和“提交处理结果”，不是直接改结果状态。

### 13.3 重复候选

使用双栏对比内容、来源、权利和使用情况。允许“保留两项”“建立关联”“选择主项”，不允许直接删除历史结果。

### 13.4 目录状态

显示各目录的更新时间、延迟、失败数量和最近重建。重建前必须预览范围；重建中显示进度；失败后保留失败分片；完成后显示前后数量和摘要是否一致。

## 14. 客户管理

客户列表重点为：状态、已开通产品、活跃任务、近 30 天费用、资料策略、负责人和支持状态。点击客户后进入：

```text
概览 | 创作产品 | 项目与成员 | 资料策略 | 执行端 | 用量费用 | 支持记录 | 操作历史
```

平台运营不能替客户批准内容，也不能查看超出支持范围的资料。临时支持授权需要范围、原因和到期时间。

## 15. 用户与角色、费用、审计和支持

### 15.1 用户与角色

角色使用中文业务名，不让管理员直接编辑散乱权限字符串。自定义角色只能从经过批准的权限组组合，高风险权限显示影响并要求二次审批。

### 15.2 用量与费用

默认按客户汇总，可切换到创作产品、能力、执行端和生成服务。费用明确标注“预估”“待结算”“已结算”；人民币使用 `¥1,234.56`，其他币种显示原币种和换算时间。

### 15.3 操作审计

页面字段使用“谁、什么时候、对什么、做了什么、为什么、结果如何”。内部 ID 和前后摘要放在展开信息。审计记录不可编辑和删除。

### 15.4 支持案例

支持案例关联客户、项目、任务、创作产品版本、异常和处理人。对外说明与内部说明分开，避免把错误码、服务商或受限资料发给客户。

## 16. 中文名称规范

页面主标题、按钮和状态使用下表中文。英文只在“技术信息”、API 或日志检索中出现。

| 内部或旧名称 | 页面中文 | 使用说明 |
| --- | --- | --- |
| Admin / Operations Control Plane | 平台运营后台 | 顶部品牌副标题 |

## 17. 状态和按钮用语

### 17.1 状态

状态必须说明业务含义：`草稿`、`等待检查`、`可以试跑`、`试跑中`、`等待发布`、`已发布`、`已暂停`、`已退役`；任务状态使用 `处理中`、`等待客户`、`需要运营处理`、`正在核对外部结果`、`已完成`、`已取消`。

禁止只显示 `ready`、`failed`、`unknown`、`paused` 等英文状态码。必要时在技术信息中附带原始状态。

### 17.2 按钮

按钮使用明确动词：`创建新版本`、`提交检查`、`开始试跑`、`发布给客户`、`查看影响`、`暂停新任务`、`发起核对`、`重新安排处理`。避免 `初始化`、`配置`、`执行`、`处理`、`确认` 这类没有对象的泛化按钮。

高风险确认文案必须包含对象和影响，例如：

```text
暂停“IP 人设视频 v2.1”后，3 家客户不能再创建新任务。
正在进行的 18 个任务和已有创作结果不会受到影响。
请输入“暂停新任务”继续。
```

## 18. 时间、数字、搜索和筛选

- 默认时区使用当前运营组织时区，显示 `2026-08-08 10:32`；跨地区详情补充时区。
- 相对时间用于列表辅助，例如“18 分钟前”，悬停或详情显示完整时间。
- 数量使用千位分隔；百分比保留一位小数；费用标明预估或结算状态。
- 搜索框按页面写“搜索产品名称”“搜索客户或任务编号”，不使用泛化的“请输入关键词”。
- 常用筛选放在列表上方，更多筛选进入弹层；有筛选时显示条件数量和“清除筛选”。
- 空列表先说明原因，再提供一个可执行入口；筛选无结果时优先提供“清除筛选”。

## 19. 加载、空白、异常和部分完成

| 状态 | 页面表现 | 禁止做法 |
| --- | --- | --- |
| 加载 | 保持表格、标签和筛选位置稳定，显示骨架 | 整页白屏或只有“Loading” |
| 首次空白 | 说明为什么为空，提供唯一开始入口 | 放一大段教程或装饰插画 |
| 筛选为空 | 保留条件，显示清除筛选 | 误导为系统没有任何数据 |
| 读取失败 | 保留已加载内容，显示重试和支持编号 | 清空整页或显示原始错误 |
| 无权限 | 说明缺少哪类权限和联系谁 | 静默隐藏导致用户怀疑数据丢失 |
| 数据延迟 | 显示最后更新时间和影响 | 把旧数据继续显示成正常实时状态 |
| 部分完成 | 分别显示成功项、失败项和下一步 | 把一项失败写成全部失败 |
| 保存冲突 | 保留用户输入，展示新版本差异 | 静默覆盖他人修改 |

## 21. 设计系统约束

- 严格遵循根目录 `DESIGN.md`：深松绿侧栏、冷白内容区、中性边框和多组业务对象色。
- 后台是高频工作面，不使用营销页大标题、装饰渐变、插画首屏或卡片瀑布。
- 页面内容最大宽度 `1440px`；主表格保持稳定列宽；详情内容和操作栏不能互相遮挡。
- 状态标签只用于状态，不能把所有字段都做成胶囊标签。
- 图标使用 Lucide；常见操作优先使用熟悉图标并配中文 tooltip。
- 桌面基准 `1440 x 1000`，移动基准 `390 x 844`，最低 `320px`；移动端保留查看和紧急处理，高密度配置允许提示使用桌面端完成。
- 键盘焦点、读屏名称、颜色对比和 `44 x 44px` 触控目标必须通过验收。

## 22. 页面蓝图验收

1. 第一次进入后台的运营人员能在 30 秒内说出今天最需要处理的三件事。
2. 内容运营无需理解 SOP、Skill、JobRun 或 Effect，也能发布一个已批准的创作产品版本。
3. 运行运营从异常队列到客户任务、失败步骤和允许动作不超过三次跳转。
4. 任一能力、技能包或执行端都能在两次跳转内查看受影响的创作产品和客户。
5. 任务详情先显示客户影响和恢复建议，原始事件默认收起。
6. 创作结果详情按人物原型、剧本、分镜、图片和视频正确渲染，不退化成 JSON 或元数据卡片。
7. 页面主标题、主按钮和状态均使用本规范中文；英文术语只出现在技术信息。
8. 旧“环境、本地能力、Work OS、运行基础设施”页面和路由已经删除，代码搜索没有活跃引用。
