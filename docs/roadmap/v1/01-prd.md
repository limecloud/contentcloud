# ContentCloud V1 产品需求文档

## 1. 文档信息

| 字段 | 值 |
| --- | --- |
| 产品版本 | V1 Pilot |
| 目标周期 | 8 周 |
| 目标客户 | AI 内容营销服务公司 |
| 首个案例 | 金陵古都香 |
| 首版渠道 | 抖音短视频，导出可供国内 AI 视频工具人工使用 |
| 文档受众 | Goodvision 产品、设计、工程、QA 和交付团队 |

## 2. 背景与问题

当前营销公司服务传统品牌时，资料、事实、创意和审批通常散落在网盘、微信、飞书文档和个人经验中。团队使用通用 AI 生成内容，但存在五类结构性问题：

1. **事实风险**：模型无法区分已验证事实、候选说法、禁用功效和过期价格。
2. **素材风险**：产品图、品牌图形和对标内容的权利、真实性与适用范围不清。
3. **剧本不可执行**：交付常停在文案，没有镜头功能、画面证据、连续性和 AI 视频生成约束。
4. **经验不可复用**：有效框架、镜头和失败原因留在个人或会议中，下一项目仍从零开始。
5. **审批不可追溯**：客户通过聊天确认，无法证明批准的是哪一版、用了哪些依据、后来为何失效。

真正竞品不是另一套 Agent 平台，而是“网盘 + 群聊 + 文档 + 通用 AI + 人工记忆”的项目制工作方式。

## 3. 目标用户与 JTBD

### 3.1 营销公司负责人

当公司同时服务多个传统品牌时，希望把建档、生产和审批标准化，以降低交付对少数资深人员的依赖，并清楚知道每个项目的风险、进度和产能。

### 3.2 项目负责人

当启动一个单品内容项目时，希望在一个工作台确认资料、卖点、内容方向、负责人和审批状态，避免产品、内容、投放各自脑补。

### 3.3 内容策略与编导

当准备 AI 视频剧本时，希望同时获得可用品牌事实、市场框架、镜头模式和卖点可视化方案，并能批量生成受约束的内容变体。

### 3.4 知识/合规审核员

当 Agent 提取事实或剧本使用营销主张时，希望看到精确证据位置、冲突、风险与影响范围，再作出可审计决策。

### 3.5 品牌客户审批人

当营销公司提交 Brief 或剧本时，希望无需学习系统即可查看内容、引用依据和修改点，并明确批准或退回当前版本。

## 4. 产品目标

### 4.1 V1 目标

- 把一个传统品牌从资料接收到 AI 视频剧本批准的过程产品化。
- 建立品牌事实与市场内容双上下文。
- 让本地 Codex/Claude Code 成为可替换执行器，而不是业务事实源。
- 让每个正式剧本同时具备叙事、画面、引用、生成约束和验收标准。
- 建立最小结果回流，使框架和镜头评级来自实际观察而非主观点赞量。

### 4.2 非目标

- 不生成图片、关键帧、视频或成片。
- 不自动发布、投放、控制账号或操作评论区。
- 不抓取或批量下载第三方平台内容；参考素材由授权用户上传或登记链接。
- 不提供通用聊天机器人、通用工作流市场或自修改 Agent。
- 不为品牌客户提供完整自助创作能力。
- 不自动批准事实、主张、素材权利、Brief 或剧本。
- 不承诺投放 ROI 或将培训经验数字作为效果保证。

## 5. 核心业务流程

1. 营销公司管理员创建租户并邀请团队成员。
2. 项目负责人创建品牌/单品项目，指定内部负责人和品牌审批人。
3. 项目页生成短期一次性连接码，引导用户在自己的电脑安装并连接 Creative Runtime；已有设备可显式授权给该项目。
4. 团队上传品牌、产品、合规和素材资料。
5. 系统确定性解析文件，本地 Agent 提取候选知识，人工完成审核。
6. 内容策略登记有依据的对标案例，拆解画面框架、文案框架和镜头模式。
7. 项目组排序产品卖点，为主卖点建立可视化方案。
8. 项目负责人锁定营销 Brief 和唯一主要测试变量。
9. 服务端按版本和关系确定性构建 Task Contract；本地 Creative Runtime 选择已安装的 Skill/Agent/Renderer 执行创作。
10. 系统校验引用、时长、镜头结构、权利、画面证据和变体规则。
11. 营销公司内审，通过后向品牌客户发送安全审批链接。
12. 客户批准后锁定版本，导出 Markdown、XLSX 和 JSON。
13. 视频在外部工具生产和投放后，团队手工导入最小结果，更新内容资产评级。

## 6. 功能需求

### FR-01 租户、团队与权限

- 团队成员使用已验证邮箱和密码登录；支持邮件验证、忘记密码和强制 session 失效。
- 支持一个用户加入多个租户并切换当前租户。
- 角色固定为 `tenant_admin`、`project_manager`、`strategist`、`editor`、`reviewer`、`viewer`。
- 品牌客户不加入营销公司租户，通过绑定单一对象版本和指定邮箱的安全审批链接访问；最终决策前输入一次性邮件验证码。
- 每个业务对象必须属于一个租户；品牌知识必须进一步属于一个项目。
- 管理员可撤销成员、设备和审批链接，撤销立即生效。

### FR-02 品牌项目

- 创建项目时记录品牌、单品、目标渠道、项目负责人、内部审核人和客户审批人。
- V1 一个项目只允许一个主攻单品和一个阶段性主目标。
- 项目可从模板创建，但模板不能携带其他客户的事实或素材。
- 项目归档后只读；恢复需管理员权限并写审计事件。
- 项目创建成功后进入首次接入引导：连接一台新电脑或选择租户内已有设备；跳过后项目仍可维护资料，但所有本地 Agent 动作保持 blocked。
- 新电脑连接码绑定当前租户、项目和邀请人，10 分钟有效且只能成功消费一次；页面显示等待、验证、已连接、过期和失败状态。
- 同一 Creative Runtime 只安装一次；复用于其他项目时创建可撤销的项目设备授权，不重新分发 device token。

### FR-03 来源摄取

- 支持 PDF、DOCX、XLSX、PPTX、PNG 和 JPEG。
- 上传使用预签名 URL；服务端校验文件大小、MIME、扩展名和 SHA-256。
- 同一逻辑来源允许多个不可变修订版；不得覆盖原始字节。
- 确定性 Worker 提取文字、页码、段落、Sheet/单元格和图像区域定位。
- 扫描 PDF/图片启用中文 OCR；低置信度内容标记为待复核。
- 每个来源显示处理状态、错误、版本、上传人和影响范围。

### FR-04 品牌知识治理

- Agent 可生成候选事实、主张、规则、受众、场景和冲突，不得直接批准。
- 每个知识项必须链接至少一个精确 EvidenceSpan，除非类型明确允许人工规则。
- 事实支持类型化值、单位、有效期和适用范围。
- 主张记录风险等级、允许渠道、禁止扩展表达和所依赖事实。
- 权利记录主体、权利类型、地域、渠道、期限、证明来源和限制。
- 审核人可批准、拒绝、退回、标记冲突或设置过期时间。
- 上游来源、事实或权利变化时，影响对象自动进入 `review_required`。

### FR-05 市场确定性素材库

- 用户可登记自有或外部 Benchmark Content，保存链接、上传片段、来源、授权和验证依据。
- 每个案例可拆成独立的画面框架与文案框架。
- 镜头模式按 `hook`、`pain`、`product_intro`、`usage`、`proof`、`cta` 分类。
- 每个案例必须区分验证对象：框架、镜头、话术、达人/人效、账号或承接方式。
- 点赞和播放量不能单独构成“销售已验证”；缺少销售依据时状态为 `observed`。
- 支持正例、反例和失败原因，不只保存爆款。
- 参考内容权利不明时只能用于结构分析，不能作为生成素材下发。

### FR-06 产品分析与可视化方案

- 项目组为产品建立卖点列表和优先级。
- 正式剧本固定一个主卖点，最多两个次卖点。
- 主卖点进入 Brief 前至少有一个已批准 Visualization Plan；团队目标数量可配置。
- 可视化方案必须声明证据类型、所需主体/场景/道具、实现方式、风险和验收条件。
- 事实依据不足、画面不可实现或权利不足的方案不得进入正式 Brief。

### FR-07 营销 Brief

- Brief 包含目标、渠道、受众、需求时刻、场景、冲突、表达视角、卖点、证据、CTA、时长、画幅和约束。
- 每个 Brief 只能有一个主要营销目标和一个主要测试变量。
- Brief 必须引用批准知识、可用框架和可视化方案。
- Brief 通过内部批准后锁定；修改创建新版本并使下游剧本进入影响复核。

### FR-08 客户端创作任务

- V1 客户端为 Go 单二进制 `contentcloud`，通过 npm 安装器降低 macOS/Linux 首次安装门槛；安装与运行发生在用户自己的电脑，云端只生成连接码并观察设备心跳。
- 用户选择在线设备、业务目标、产出数量和交付形态；云端只匹配设备声明的业务 capability，不显示或选择 Codex、Claude、模型、Skill 或 Renderer。
- 服务端确定性构建不可变 Task Contract，记录输入版本、capability ID 和 Schema 版本；不得生成或下发 prompt、工具调用或 Agent 实现。
- Creative Runtime 领取任务后提供心跳、进度、取消、capability 版本和结构化失败信息。
- 服务端不调用、不代理、不保存任何 LLM 或视频生成供应商凭据；客户端自行管理本机认证和工具选择。
- 客户端可安装新 Skill/Renderer 来支持新内容形态或视频工具；这些私有插件不进入服务端目录，客户端只聚合声明稳定的业务 capability。
- 核心业务对象必须返回标准 Script Package；任意扩展格式只需返回 Artifact Envelope，可选附带 Review Projection 和安全预览件。
- 同一幂等键不得创建重复业务产物。
- Agent 运行成功只代表技术成功；Script Package 仍需策略校验和人工审核。

### FR-09 AI 视频剧本包

- Script Package 契约以 [05-agent-protocol-and-api.md](05-agent-protocol-and-api.md) 为准。
- 每个镜头包含时码、功能、画面、主体动作、相机运动、口播、字幕、声音、引用、生成约束和验收条件。
- 系统校验镜头总时长、必要叙事功能、主卖点一致性、引用状态和素材权利。
- 每个变体记录基准版本、保留项、变化项和测试假设。
- 无法满足门禁时允许返回 `blocked` 包，但必须列出原因、缺失输入和建议动作。

### FR-10 审核与审批

- 内部审核支持镜头级批注、整版结论和指派修改人。
- 退回修改必须填写原因；新版本保留旧批注并标识已解决/未解决。
- 客户审批链接绑定 `tenant + project + subject type + subject version`，默认 7 天有效且单独撤销。
- 客户可查看内容、引用依据的安全摘要和版本变化，不可浏览项目其他资料。
- 批准写入不可变 ApprovalDecision；批准版本不得原地编辑。

### FR-11 导出

- Markdown 面向人类阅读，保留镜头表、引用和阻断说明。
- XLSX 面向国内 AI 视频人工工作流，每行一个镜头，列顺序固定并冻结表头。
- canonical JSON 符合版本化 JSON Schema，可供后续模型适配器消费。
- 每个导出携带版本 ID、生成时间、校验结果和内容摘要哈希。
- 云端对 Script Package 使用原生结构化视图；V1 扩展产物按 `cloud_native -> safe_rendition -> local_open -> metadata_only` 展示，V1.1/P3 在原生视图之后增加 `hosted_preview`。
- 图片、H.264 MP4、PDF、纯文本等允许类型可作为客户端生成的安全预览件；未知或主动内容默认不内嵌执行。
- 扩展产物没有 Review Projection 时不能成为客户审批主对象，但不影响其关联 Script Package 的审核与导出。

### FR-12 最小结果回流

- 支持单条录入和 XLSX/CSV 导入结果。
- 最小字段为平台、账号别名、发布时间、剧本版本、观察窗口和样本状态。
- 可选指标包括曝光、3 秒留存、完播、点击、成交、GMV、消耗和 ROI。
- 结果必须区分素材问题、账号问题、投放问题和承接问题的人工判断。
- 系统只聚合和展示观察，不自动宣称因果或自动批准框架。

### FR-13 审计与影响分析

- 所有审批、状态变化、权限、设备、任务、导出和结果导入写入 append-only AuditEvent。
- 支持从来源、知识、Brief、剧本、镜头、导出和结果双向追踪。
- 影响分析必须给出受影响对象、原因、当前状态和建议动作。

### FR-14 V1.1 云端交互演示（P3）

- 客户端可把 ScriptVersion 构建为不依赖网络的静态 HTML/CSS/JS bundle，再由 `contentcloud preview publish` 发布。
- 服务端只校验 manifest、存储内容寻址 blob，并托管到独立 preview origin；不安装依赖、不构建源码、不运行 LLM 或用户代码。
- 客户可在审批链接内查看通过校验的 Hosted Preview；批准仍绑定 ScriptVersion hash，Preview 失败不阻断审批。
- 本能力属于 V1.1 最后一个 P3，不进入 V1 八周交付和总体验收，完整规格见 [09-hosted-preview-and-cli-gateway.md](09-hosted-preview-and-cli-gateway.md)。

## 8. 产品规则

1. 培训材料是候选方法论，需租户管理员批准模板版本后才能进入 Task Contract。
2. “500 条素材”“每周 3-5 个框架”等是可配置目标，不是系统门禁。
3. 外部案例只能提供结构证据，不能支持本品牌事实或权利。
4. 医疗、功效、历史、价格和认证主张必须通过专门规则检查。
5. 同一剧本的画面不得与口播表达互相矛盾。
6. 产品包装、Logo 和可读文字不能依赖不受控视频模型保持精确，应标记真实素材合成策略。
7. 审批对象必须是不可变版本，不能审批“最新版本”指针。
8. 结果数据不足时只能标记 `insufficient_sample`，不能升级为 verified。
9. BrandProject 必须先于 ConnectSession；未绑定项目的设备不能领取业务任务。
10. Web 是人工操作界面，CLI 是唯一公开程序化界面；二者复用领域服务，但不互相模拟。

## 9. 成功指标

### 9.1 产品采用

- 试点团队至少 5 名内部用户完成真实角色分工。
- 至少 1 名品牌客户通过受限链接完成独立审批。
- 80% 以上试点任务不需要 Goodvision 直接修改数据库或文件救场。

### 9.2 生产效率

- 从资料就绪到首版 Brief 的人工耗时相对现状下降 30%。
- 批准 Brief 到 10 条结构化剧本变体的总周期小于 1 个工作日。
- 90% 以上 Script Package 首次通过结构和引用校验。

### 9.3 治理质量

- 100% 确定性主张存在批准依据。
- 100% 使用素材存在可用权利状态或明确仅分析标记。
- 100% 客户审批可定位到唯一版本和审计事件。
- 跨租户访问和数据泄漏为 0。

### 9.4 内容学习

- 每个正式剧本声明测试变量和假设。
- 结果导入后可追溯到剧本、框架和镜头模式。
- 框架评级的每次变化都能定位到人工决策或 PerformanceObservation。

## 10. V1 总体验收

V1 只有在以下端到端场景全部通过后才可进入客户试点：

1. 创建两个租户并验证完整隔离。
2. 创建金陵古都香项目，从项目页在本地安装/连接 Creative Runtime，并验证连接码过期与重放被阻断。
