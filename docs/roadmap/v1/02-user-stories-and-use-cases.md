# 用户故事、用例与体验规格

## 1. 角色与权限

| 角色 | 主要职责 | 可批准对象 | 不允许 |
| --- | --- | --- | --- |
| Tenant Admin | 成员、租户策略、设备和模板 | 方法论模板、成员邀请 | 代替品牌客户批准交付物 |
| Project Manager | 项目、负责人、Brief、进度和客户交付 | Brief、提交客户审批 | 自动批准事实和权利 |
| Strategist | 对标、框架、卖点、需求时刻和测试设计 | 市场内容资产的内部评级 | 修改租户与设备安全策略 |
| Editor | 剧本生成、编辑、变体和导出准备 | 无最终批准权 | 使用被阻断知识绕过校验 |
| Reviewer | 知识、合规、权利和内部剧本审核 | 知识项、内部剧本版本 | 修改来源原件 |
| Viewer | 查看项目与已授权产物 | 无 | 写入业务数据 |
| Client Approver | 查看并批准/退回指定 Brief 或剧本版本 | 仅链接绑定的版本 | 浏览租户、其他项目或内部笔记 |
| Platform Operator | 运行状态、告警和租户支持 | 无业务批准权 | 查看无授权客户内容或模型凭据 |

## 2. 用户故事

### 2.1 租户和项目

- `US-001` 作为管理员，我要邀请团队成员并分配最小权限，以便多人协作而不扩大数据暴露。
- `US-002` 作为项目负责人，我要以单品为单位创建项目并指定审批关系，以便团队围绕同一目标工作。
- `US-003` 作为负责人，我要看到所有项目的知识风险、任务状态和待审批数，以便及时处理阻断。
- `US-004` 作为项目负责人，我要在项目创建后获得一条可复制的本机安装/连接命令，并看到电脑何时连接成功，以便不理解 Daemon 或 API 也能开始使用 Agent。
- `US-005` 作为已有设备的用户，我要把同一台电脑授权给新项目而无需重新安装，以便多项目使用保持低摩擦且授权可撤销。

### 2.2 来源和知识

- `US-101` 作为审核员，我要从候选事实跳转到原文页码或表格单元格，以便独立判断是否可信。
- `US-102` 作为审核员，我要保留冲突值而不是覆盖旧值，以便向品牌方提出明确决策问题。
- `US-103` 作为项目负责人，我要在来源更新后看到受影响剧本，以便阻止过时版本继续交付。
- `US-104` 作为品牌客户，我要只确认系统无法自行决定的事实、主张和权利，以便降低审核负担。

### 2.3 市场内容方法

- `US-201` 作为策略人员，我要把对标内容拆成画面框架和文案框架，以便迁移结构而非复制内容。
- `US-202` 作为策略人员，我要标记案例究竟验证了框架、镜头还是账号，以免把播放量误当销售确定性。
- `US-203` 作为编导，我要检索某卖点对应的镜头模式和正反案例，以便设计能被看见的证据。
- `US-204` 作为审核员，我要限制无权素材只用于分析，以免它进入生成任务或正式导出。

### 2.4 Brief 和剧本

- `US-301` 作为项目负责人，我要锁定一个主目标、主卖点和测试变量，以便团队知道这轮到底验证什么。
- `US-302` 作为编导，我要选择在线设备和业务产出生成剧本，以便客户端自行使用本地 Agent 授权，云端不知道具体模型与 Renderer。
- `US-303` 作为审核人，我要在云端看到统一剧本与可审阅投影，并在未知格式时安全地回到来源设备打开，而不是等待云端适配每种工具。
- `US-306` 作为编导，我要收到结构化镜头包而不是自由文本，以便直接交给 AI 视频工具执行。
- `US-304` 作为策略人员，我要从基准剧本生成单变量变体，以便测试结果可以解释。
- `US-305` 作为审核员，我要看到剧本使用了哪些事实、主张、画面证据和素材，以便一次完成内容与合规审核。

### 2.5 客户审批和结果

- `US-401` 作为品牌审批人，我要通过简单、安全的链接查看唯一版本，以便无需创建完整账号也能批准或退回。
- `US-402` 作为项目负责人，我要看到客户退回的镜头级意见，以便精确修订而不是重新沟通整篇文档。
- `US-403` 作为交付人员，我要导出人用和机器用格式，以便兼容当前国内 AI 视频人工流程。
- `US-404` 作为投放运营，我要导入最小结果数据并关联剧本变量，以便复盘能够沉淀成资产。
- `US-405` 作为品牌审批人，我要直接在审批链接内查看隔离的交互式演示，以便无需安装 Node.js、CLI 或启动本地服务；该能力属于 V1.1/P3。

## 4. 核心用例

### UC-01 创建租户与品牌项目

**参与者**：Tenant Admin、Project Manager  
**前置条件**：管理员已完成登录。  
**主流程**：

1. 管理员创建租户，系统建立默认角色策略和对象存储前缀。
2. 管理员邀请内部成员并分配角色。
3. 项目负责人创建项目，选择品牌、主攻单品、渠道和阶段目标。
4. 指定项目负责人、知识审核人、内部剧本审核人和品牌客户联系人。
5. 系统生成空的 Gate 0-5 状态和审计记录。
6. 项目进入“连接创作电脑”步骤，服务端生成绑定项目、10 分钟有效、单次消费的 `connect-key`。
7. 页面展示“安装新电脑”和“使用已有设备”两条路径；前者提供 `npx ... contentcloud up` 命令与可复制给 Codex/Claude Code 的提示。
8. 用户在自己的电脑运行命令；本机安装器下载并校验 Go 单二进制，CLI 消费连接码、将设备凭据写入平台安全存储、启动用户级 Daemon 并上报 capability。
9. Web 从 `waiting_for_computer` 变为 `verifying`，收到首个有效心跳后变为 `connected`，引导用户进入资料上传。

**异常**：重复租户 slug 自动建议新值；无审核人时允许保存草稿但禁止进入知识审批；连接码过期可重新生成；安装失败保留手工下载与 Doctor 指引；连接码重放不创建第二个设备。  
**后置条件**：项目状态为 `draft`，只能由租户成员访问；设备授权状态独立为 `not_connected|connected`。  
**验收**：任何其他租户用户使用 ID、URL、连接码或对象存储路径均无法读取项目；用户只需在项目页和自己的电脑完成首次连接。

### UC-02 上传并解析资料

**参与者**：Project Manager、Reviewer  
**前置条件**：项目存在且用户有写权限。  
**主流程**：

1. 用户选择来源类型并上传一个或多个文件。
2. 浏览器通过同源 BFF 获得受限上传许可后直传对象存储；这是 Web 内部协议，不是公共集成接口。
3. 领域服务完成哈希、MIME、大小和重复检查，创建 SourceRevision。
4. 摄取 Worker 扫描、解析或 OCR，生成可定位的 EvidenceSpan。
5. 用户预览解析结果并确认来源可进入 Agent 提取。

**异常**：恶意文件隔离；密码保护文件提示重新提交；OCR 低置信度区域进入待复核。  
**后置条件**：来源为 `ready` 或 `needs_review`，原始字节不可修改。  
**验收**：随机抽取页码、段落和单元格定位，必须能回到正确原文。

### UC-03 提取和审核品牌知识

**参与者**：Reviewer、本地 Agent、品牌联系人  
**前置条件**：至少一个 SourceRevision 为 `ready`。  
**主流程**：

1. 用户创建“知识提取”任务。
2. 服务端 Task Contract Builder 确定性生成只包含指定来源、capability 要求和 Schema 的 Task Contract，不生成 prompt。
3. 客户端 Daemon 使用本机 Skill/Agent 返回候选 KnowledgeItem、EvidenceLink 和 Conflict。
4. 系统确定性校验引用、类型和值格式。
5. 审核员逐项批准、拒绝或退回，并在冲突时创建决策请求。
6. 品牌联系人通过受限链接确认指定问题；审核员据此完成状态决策。

**异常**：Agent 引用不存在的位置时整项拒收；同一 subject/predicate 出现不同有效值时不得静默覆盖。  
**后置条件**：批准知识可进入后续 Context Snapshot；候选知识仅供审核。  
**验收**：任何 approved 项都能定位证据、审核人、决策时间和适用范围。

### UC-04 登记并拆解市场案例

**参与者**：Strategist、Reviewer  
**前置条件**：用户合法获得案例链接或文件。  
**主流程**：

1. 登记来源、平台、发布时间、内容类型、权利状态和验证依据。
2. 拆分画面框架与文案框架。
3. 把时间段标记为 Hook、Pain、Product Intro、Usage、Proof 或 CTA。
4. 抽象可复用 Shot Pattern，记录主体、动作、场景、道具和结果证据。
5. 审核员确认该资产可用于结构分析、生成参考或两者。

**异常**：无权下载的内容仅保存链接和人工笔记；无销售依据的高播放案例不能标记 verified。  
**后置条件**：批准框架可被 Brief 引用。  
**验收**：用户能明确回答案例有效的是哪个模块，而非只看到“爆款”标签。

### UC-05 锁定卖点和 Brief

**参与者**：Project Manager、Strategist、Reviewer  
**前置条件**：存在批准品牌知识和至少一个可用内容框架。  
**主流程**：

1. 策略人员排序卖点，选择一个主卖点和最多两个次卖点。
2. 为主卖点选择或创建 Visualization Plan。
3. 定义人群、需求时刻、场景、冲突、视角、CTA 和唯一主要测试变量。
4. 系统检查事实、主张、权利、画面可实现性和渠道规则。
5. 项目负责人提交内审；Reviewer 批准后创建不可变 BriefVersion。

**异常**：没有批准可视化方案时只能保存草稿；多个主要变量时阻止批准。  
**后置条件**：Brief 状态为 `approved`，可创建 Agent 任务。  
**验收**：Brief 能回答“对谁、何时、为何、证明什么、如何表现、测试什么”。

### UC-06 生成剧本和变体

**参与者**：Editor、Creative Runtime  
**前置条件**：Brief 已批准，项目已授权至少一台兼容设备且设备在线。  
**主流程**：

1. Editor 选择设备、业务 capability、产出数量和需要的交付形态；Web 不展示客户端内部 Agent、模型、Skill 或 Renderer。
2. 服务端创建 TaskRun，确定性构建并冻结 Task Contract；不调用任何 LLM。
3. 客户端 Daemon long-poll 领取租约，下载资料并校验所有哈希，再按本机策略决定实际 Skill/Agent/Renderer。
4. Agent 在只读临时目录中生成符合 JSON Schema 的结果。
5. Daemon 本地校验后上传核心 JSON、扩展 Artifact Envelope、可选 Review Projection/安全预览件、日志摘要和使用量。
6. 服务端再次校验业务规则，创建 ScriptVersion 和 Shot。
7. 变体记录基准、保留项、变化项和假设。

**异常**：设备离线保持 queued；租约过期可重领；无效 JSON 允许有限次数重试；业务阻断生成 blocked Deliverable。  
**后置条件**：Run 可为 succeeded，而 Deliverable 为 blocked 或 review_ready。  
**验收**：重复 report 不会创建第二个 ScriptVersion。

### UC-07 内部审核与修订

**参与者**：Reviewer、Editor  
**前置条件**：ScriptVersion 为 `review_ready`。  
**主流程**：

1. Reviewer 检查剧本总览、引用和策略校验报告。
2. 按镜头批注叙事、画面、事实、权利或生成可行性问题。
3. 选择批准或退回；退回必须指定责任人和原因。
4. Editor 基于批注创建新版本，不修改原版本。
5. 系统显示版本差异和批注解决状态。

**异常**：审核期间上游知识失效时立即撤回审批资格并标记 review_required。  
**后置条件**：内部批准版本可发送客户审批。  
**验收**：批准动作绑定唯一内容摘要哈希。

### UC-08 品牌客户审批

**参与者**：Project Manager、Client Approver  
**前置条件**：版本已通过内部审核。  
**主流程**：

1. 项目负责人输入客户姓名和验证方式，生成 7 天有效审批链接。
2. 客户验证后只看到指定版本、依据摘要、版本差异和公开批注；V1.1 若存在 `ready` Hosted Preview，则在隔离 iframe 中内嵌查看。
3. 客户选择批准或退回；退回需填写原因，可定位镜头。
4. 系统记录审批主体、时间、IP/设备摘要、版本和内容哈希。
5. 批准后 ScriptVersion 锁定为 `approved`。

**异常**：链接过期、撤销、已使用或版本失效时拒绝操作并提示联系项目负责人；Hosted Preview 处于 `planned|uploading|validating|rejected|expired` 时稳定回退标准剧本或 safe rendition。  
**后置条件**：批准版本可导出；退回版本进入 revision_requested。  
**验收**：客户无法通过修改 URL 查看其他版本或项目。

### UC-09 导出剧本包

**参与者**：Editor、Project Manager  
**前置条件**：ScriptVersion 已批准。  
**主流程**：

1. 用户选择 Markdown、XLSX 或 JSON。
2. Export Renderer 从 canonical Script Package 生成目标格式。
3. 系统写入版本、Schema、摘要哈希和引用附录。
4. 用户下载带有效期的预签名文件。
5. 对客户端私有扩展产物，系统优先显示 Review Projection 或安全预览件；不支持的格式提供“在来源设备打开”或 attachment 下载，最差显示完整元数据和校验状态。

**异常**：若知识在导出前失效，阻止新导出并触发影响复核；若扩展产物没有安全预览，只降级展示，不尝试在云端执行插件。  
**后置条件**：Artifact 与导出事件可审计。  
**验收**：三种格式内容语义一致，XLSX 一行一个镜头且无字段丢失。

### UC-10 导入结果并复盘

**参与者**：Strategist、投放运营  
**前置条件**：存在已批准或已导出的 ScriptVersion。  
**主流程**：

1. 用户下载结果导入模板或手工录入。
2. 系统校验剧本版本、指标单位、观察窗口和重复数据。
3. 用户标记样本是否充分，以及主要问题分类。
4. 系统聚合展示相关框架、镜头和变体，不自动改变批准状态。
5. Strategist 创建评级决策，记录依据和下一轮动作。

**异常**：未知剧本、负数指标、混合币种或窗口冲突进入隔离队列。  
**后置条件**：PerformanceObservation 可被后续 Brief 检索。  
**验收**：每次评级变化都能回到具体观察和人工决策。

## 5. 页面状态要求

每个核心页面必须覆盖：

- `loading`：保持稳定布局，不用文本撑开控件。
- `empty`：提供唯一明确的下一步操作。
- `partial`：明确已完成与待补资料，不把部分成功显示为完成。
- `blocked`：显示阻断原因、影响对象、责任人和解除动作。
- `error`：保留用户输入，提供 trace ID 和安全重试。
- `offline`：任务创建可排队，但明确设备未在线和最后心跳时间。
- `permission_denied`：不泄漏对象是否存在。
- `superseded`：跳转当前版本，但保留历史只读访问。
- `waiting_for_computer`：显示短期安装命令、复制、取消和等待状态，不伪装成后台任务成功。
- `verifying`：连接码已消费，正在校验版本、设备身份和 capability；不得提前允许创建 Run。
- `connected`：显示设备名、平台、CLI 版本、能力摘要和最后心跳，并给出下一步上传资料。
- `expired`：连接码已失效且无法再消费，保留项目并允许生成新码。
- `planned|uploading|validating|ready|rejected|expired`：Hosted Preview 状态；非 `ready` 时不得创建空白 iframe。

## 6. 体验约束

- 工作台优先服务高频扫描和比较，不使用营销落地页式大卡片布局。
- 事实、主张、素材、Brief 和剧本使用统一的状态颜色与图标语义。
- 所有陌生图标提供 tooltip；审批、撤销和删除使用文字加图标。
- 桌面端主工作区采用列表/编辑区/引用侧栏；移动端只优化客户审批和轻量查看。
- 长 ID 默认缩写但可复制完整值；用户名称、标题和中文长词不得溢出容器。
- 客户审批页面不显示内部风险备注、成本、Agent transcript 或其他客户信息。
