# ContentCloud V8 实施台账

> 阅读对象：参与 V8 实施和评审的研发负责人。普通读者可先看 README；本文件只记录工作包、依赖、里程碑和风险。

状态：`方案完成；Runtime 第一批内核、ContextView/AgentInstance 存储、脱敏 BFF 与 Explorer 首版已实现；真实执行适配、服务商闭环、动态执行图和生产验证仍未完成。V8.1 基础设施升级按 09-runtime-infra-v2.md 执行`。

更新时间：2026-08-07。

本台账按以下顺序实施：先验证 Codex、Claude Code 等智能体宿主的实际能力，并兼容现有线性流程；再建设共享状态和故障恢复；最后开放动态执行图。不能先演示大规模创建智能体，再补权限、费用和恢复机制。

现有的业务任务、流程阶段、人工审批节点、本地执行、租约、心跳、正式产物和交付对象继续复用。V8 新增的是执行实例、执行图、共享状态、检查点、外部操作台账和统一调度，不重新建设一套内容业务对象。

本期不做通用工作流市场、任意代码执行、无限智能体派生、对等智能体聊天网络，也不承诺外部操作一定只发生一次。完整边界见 [README.md](./README.md) 的“明确不做”。

本台账的工作包仍然有效，但执行顺序增加一条硬前置：先完成 [Runtime Infra V2](./09-runtime-infra-v2.md) 的 I0～I3（权威事务命令、事件/outbox、fence token、资源账本、类型化状态、Effect 对账和分支恢复），再开放 W8-10 动态执行图。当前 I0 已冻结、I1 命令和 outbox 消费协议已实现；I1 仍需提交后进程终止注入、投影消费和并发验证。I4～I5 与 W8-11～W8-16 合并验收；在此之前，FakeHarness 只能作为 CI 和预览能力，不能作为真实宿主恢复证据。

本台账服从 [ContentCloud 平台基线](../../foundation/README.md)：V8 只交付 Runtime 内核和 Runtime Explorer，不承担客户创作台与运营流水线产品层。客户首个“灵感采集”线性切片可以使用现有执行内核与兼容投影提前交付，不以 W8-10 动态执行图或 W8-12 完整诊断 Web 为前置条件。

V8 对客户工作区资料、任务输入、项目参考、生成结果和交付事实只保存固定引用与执行血缘。客户资产入口组合“我的资产”和“创作结果”，但 Runtime 不拥有文件夹、上传/导入、文件处理、结果确认或复用状态；边界由 [ADR-0013](../../foundation/decisions/ADR-0013-customer-result-asset-boundary.md) 与 [ADR-0014](../../foundation/decisions/ADR-0014-customer-asset-surface.md) 共同拥有。

## 5. 实施任务

### T1：基线收敛（P0）

- 更新根 README 的版本和真实能力边界。
- 把 V7 路线图标记为历史方案，并附上实际完成/未完成矩阵。
- 建立由变更记录、数据库迁移、领域模型和测试共同校验的能力登记表。
- 验证文档链接和版本漂移，并运行 `go test ./...`。

### T2：执行适配层可行性原型（P0）

- Codex：App Server/SDK 线程、事件流、MCP、中断、恢复/分支（`thread`、`event stream`、`interrupt`、`resume/fork`）。
- Claude：Agent SDK/CLI、MCP、SessionStore、会话恢复/分支（`resume/fork`）。
- FakeHarness：确定性成功、启动失败、空事件流、重复终态、未知事件、无终态关闭、延迟心跳、租约过期和迟到终态拒绝脚本。
- 记录版本、认证、许可、隔离能力、事件顺序和崩溃行为。
- 退出条件：至少一个执行适配层达到生产候选标准；另一个明确标注为预览或阻塞状态，不夸大能力。

### T3：JobRun 与事件内核（P0）

- 新增增量迁移、领域模型、内存/PostgreSQL 存储、RLS 和服务层。
- 实现状态机、事件序号、幂等命令和运行中 `WorkTask` 约束。
- 验证状态转移、事务、RLS、并发竞争和数据库迁移集成。

### T4：执行图编译器与旁路验证（P0）

- 将现有 SOP 的 `Order/InputRefs` 编译为不可变的 `JobPlanRevision`。
- 实现有向无环图、Schema 可达性、能力和审批条件的静态校验。
- 对内置 SOP 比较旧的下一阶段判断和新的就绪判断。
- 验证：基准摘要、属性测试和完整 SOP 旁路报告。

### T5：线性调度器（P0）

- 使用独立 `runtime_node_runs/runtime_attempts` 作为 V8 权威模型；V7 `TaskRun/RunAttempt` 只保留兼容路径，通过业务投影关联，不双写状态机。
- 实现依赖就绪判断、租户/执行实例的运行中配额、等待时间越长优先级越高的规则，以及资源预留事务。
- 验证：V7 基准流程、并发领取、租约过期、取消，以及小任务不会长期得不到执行的稳定性测试。

### T6：状态、上下文与网关（P0）

- 类型化集合、状态变更、CAS/追加/归并、ContextView 构建器。
- 本次执行专用的 MCP 工具和短期凭据。
- 大值使用 ArtifactRef，支持分页、来源标签和 Token 预算。
- 验证并发冲突、越权、提示词注入、上下文摘要和日志脱敏。

### T7：AgentInstance 与让出资源/恢复执行（P0）

- 逻辑智能体层级、宿主会话引用、启动和等待条件。
- 主控智能体结束本次执行并释放名额，子节点完成后由新的 `Attempt` 恢复。
- 校验子智能体的权限、预算、工具和上下文都是父级允许范围的子集。
- 验证进程终止、会话丢失后的降级恢复、取消级联和子节点权限范围。

### T8：资源与外部操作台账（P0）

- 预留智能体、服务商并发、Token、费用和媒体处理资源。
- 工具调用、外部操作的结果不明/对账/补偿流程。
- 将 ProviderAttempt、Delivery 等外部动作统一关联到操作台账。
- 验证重复提交、超时、回调乱序、账单差异和补偿失败。

### T9：服务商生产能力补齐（P0）

- 接入一个真实服务商的测试环境适配器，并实现真正异步的轮询/回调。
- 补齐中间状态的租约恢复、受限流式下载和完整媒体校验。
- 确定性渲染字幕、品牌、行动号召和商品信息，不再直接透传。
- 在低预算测试环境中验证基本链路、SSRF、内存耗尽、取消、费用和数据披露。

### T10：检查点、重放与执行分支（P0）

- 节点边界检查点清单和摘要。
- 重建读模型，不调用任何执行器。
- 从检查点创建新的 JobRun，并重新进行准入和审批有效性校验。
- 验证源执行实例保持不变、写时复制、未知外部操作阻断和数据损坏检测。

### T11：动态执行图（P1）

- 只允许追加的 GraphPatch、预期版本和规模上限。
- FanoutSet 封闭、确定性子节点、汇聚策略和归并节点专写。
- 对节点数、深度、并行数量、后代数和费用设置硬上限。
- 验证 50/100 个子节点、重复变更申请、中途终止、迟到子节点、构造环攻击和失败处理策略。

### T12：运行诊断视图（P1）

- 图、智能体、状态、事件、外部操作和费用的 BFF、SSE 游标及允许操作。
- URL 子路由、桌面执行图、移动端大纲和详情面板。
- 遵循 DESIGN.md，不做卡片嵌套或基础设施式一色主题。
- 验证端到端流程、响应式布局、可访问性、读模型延迟、两标签页并发和会话过期。

### T13：标杆任务（P1）

- 营销活动：受众、脚本、分镜、媒体、审核和批量交付。
- 文章复盘：多渠道分析、结果汇聚、学习审批和下一轮需求简报。
- 验证两种任务流程只增加内容业务包、Schema 和人工审批节点，不增加专用调度表。

### T14：生产验证（P0）

- 故障注入、RLS/安全测试、100 节点/20 并发稳定性压测。
- 补齐指标、告警、运维手册、Canary 和回退演练。
- 开展真实租户的受控试点，记录任务周期、人工干预、恢复成功率、成本和交付质量基线。

## 6. 每阶段进入条件

| 阶段 | 出现以下情况时，禁止进入下一阶段 |
| --- | --- |
| 执行适配层 | 官方接口证据、真实原型、认证条款、隔离能力和故障行为未确认 |
| 运行时内核 | 终态仍可原地回到非终态、缺少 RLS、事件与状态不能原子提交，或 V7 出现回归 |
| 状态 | 存在后写覆盖、原始 SQL/DDL、跨范围读写或把大正文写入 JSONB |
| 外部操作 | 结果不明仍可盲目重试、没有稳定幂等键或费用预留 |
| 检查点 | 包含进程/密钥/租约，或重放会触发外部调用 |
| 动态执行图 | 可以修改运行中节点、创建环、无限派生或绕过执行配置/审批 |
| 服务商 | 只有 `FakeProvider`、整文件加载到内存或直接透传渲染 |
| 生产准备 | 故障/安全/稳定性/回退/运维手册任一未通过 |

## 7. 风险台账

| 风险 | 级别 | 缓解 |
| --- | --- | --- |
| 把宿主团队/工作流误当作可恢复运行时 | P0 | 官方能力矩阵、ContentCloud 权威状态、适配器兼容性验证 |
| WorkTask、JobRun、TaskRun 形成第三套混乱状态 | P0 | 固定聚合边界，V8 使用独立 NodeRun/RuntimeAttempt，StageRun 只做单向投影 |
| 当前高权限一次性适配器被直接放大 | P0 | 旧配置禁止派生子节点；新执行适配层和隔离配置单独上线 |
| 动态图无限扩张 | P0 | 只允许追加的校验、节点/深度/并行数量/费用硬上限 |
| 并发写共享状态导致更新丢失 | P0 | CAS、单写入方、只追加/归并专写，禁止任意合并 |
| 外部任务重复扣费 | P0 | 外部操作台账、稳定幂等键、结果不明先对账 |
| 检查点被误解为全系统回滚 | P0 | 逻辑状态清单、创建新 JobRun 分支、用补偿而不是删除历史 |
| 服务商生产能力仍停留在模拟实现 | P0 | W8-08 设置独立发布门槛，营销活动任务不得绕过 |
| 智能体会话格式或版本变化 | P1 | 不透明会话引用、能力探测、用新上下文创建会话、版本矩阵 |
| 完整对话记录、来源或密钥泄露 | P0 | 上下文范围、受限 Artifact、脱敏、保留策略、扫描 |
| 大型营销活动长期占满资源，小任务一直得不到执行 | P1 | 租户/执行实例配额、等待时间越长优先级越高、恢复名额、稳定性测试 |
| 事件或读模型延迟导致误操作 | P1 | 分离权威状态、游标/延迟指标、由服务端计算允许操作 |
| 方案过大，长期无法形成价值 | P1 | 先交付线性切片、用最小营销活动场景验证、设置阶段门槛 |
| Runtime 输出、工作区资料、客户结果和交付包再次混成一个 Asset | P0 | 引用 ADR-0013/0014，分开资料引用、输入快照、输出绑定、两个资产投影和交付视图，用 OpenAPI/投影回归测试锁定 |

## 8. M8-0 未决策项

以下问题必须由 POC/评审决定，本文不预设答案：

- 首个可用于生产候选的执行方案，需要在 Codex App Server/SDK、Claude Agent SDK 和“受限确定性执行+本地交接”三者之间通过原型验证确定。
- 两个宿主面向第三方产品的认证、分发、数据保留和商业条款。
- `workspace_restricted` 在 macOS/Linux/Windows 的最低可证明隔离能力。
- 首个真实媒体服务商、区域、模型、计费、回调和数据保留配置。
- 状态 Schema 的发布流程和向后兼容规则。
- 试点租户的真实配额、Token/费用上限和人工审批责任人。

这些问题不阻断 W8-02/W8-03 的运行时领域实现，但会阻断 W8-06、W8-08 和生产发布。

## 9. 完成标准

V8 只有同时满足以下条件才完成：

- 定位、代码、API、UI 和运维文档都使用同一 JobRun/NodeRun/AgentInstance 语义。
- V7 线性流程在关闭功能开关和启用 V8 线性模式时都通过回归。
- 动态执行图、共享状态、检查点、外部操作和执行适配层都有故障注入证据。
- 营销活动任务和第二种任务流程复用运行时内核，并产出规范的业务结果引用和可交付对象。
- 工作区资料、任务输入/项目参考、五类创作结果和交付视图在代码、OpenAPI 和回归测试中保持分离；Runtime 不写文件处理或结果复用状态。
- 至少一个真实执行适配层和一个真实媒体服务商通过受控环境验收。
- 运行诊断视图可以帮助操作员定位、暂停、恢复、对账和创建执行分支。
- 安全、服务条款、容量、Canary 和回退均由对应负责人签字。
- 尚未完成的能力必须在能力登记表和界面中标为“预览”或“未启用”，不得写成“具备生产使用条件”。
