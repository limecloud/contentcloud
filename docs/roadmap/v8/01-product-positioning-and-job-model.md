# 01：产品定位与核心模型

> 阅读对象：产品经理、架构师和领域模型研发人员。普通用户先阅读 [README](./README.md)。

状态：V8 目标设计，RuntimeAttempt 与 FakeHarness 调度内核已部分实现。本文仍包含后续目标，不代表全部能力已经达到生产条件；当前基线以 README 的“当前已经有什么，V8 还要增加什么”和仓库代码为准。

## 1. 产品定位与边界

V8 在 ContentCloud 内部定位为 **ContentCloud Agentic Job Runtime（智能体任务运行时）**。它不是另一套产品，而是现有内容工作台背后的任务执行能力。用户仍然在 ContentCloud 中提交业务任务、完成人工审批和接收交付。

这套运行时只管理一项有边界的内容任务，负责：

1. 根据已批准的输入和执行方案安排后续工作。
2. 协调智能体、普通程序、外部服务商和人工完成各自适合的执行步骤。
3. 保存执行进度、共享状态、审批决定、费用和外部操作记录，并关联正式产物。
4. 在权限、并发、预算和规模上限内调整后续执行图。
5. 在进程或模型会话中断后，根据已持久化的业务记录继续执行。

Codex 和 Claude Code 等工具负责完成适合由智能体处理的具体步骤，不能代替 ContentCloud 保存业务状态、审批、费用和外部操作记录。格式校验、确定性汇总、渲染和交付等结果可预测的工作，仍优先由普通程序完成。

V8 也不是传统意义上的 Agent OS。它不管理整台机器的进程、内存、磁盘和设备，不提供无限创建智能体、任意循环或运行中自行修改规则的能力。

## 2. 固定术语

V8 的产品、代码、接口和运维文档统一使用以下名称，避免同一个对象出现多套中文称呼。

| 中文名称 | 代码名称 | 回答的问题 |
| --- | --- | --- |
| 业务任务 | `WorkTask` | 用户想完成什么，以及采用哪些输入、流程和业务治理规则 |
| 执行实例 | `JobRun` | 这项业务任务本次怎样执行、现在运行到哪里 |
| 执行步骤 | `NodeRun` | 执行图中的某一项具体工作处于什么状态 |
| 执行尝试 | `RuntimeAttempt` | 某个执行步骤本次由谁执行、是否取得执行许可、结果如何 |
| 人工审批节点 | `Gate` | 哪个关键决定必须由人作出，以及决定基于哪个输入版本 |
| 执行图 | DAG | 哪些执行步骤可以开始、可以并行或必须等待前置结果 |
| 共享状态 | `StateCollection`、`StateRecord`、`StateMutation` | 多个执行步骤共同使用哪些结构化数据，以及这些数据如何变更 |
| 输出绑定 | `JobOutputBinding` | 执行步骤产生了哪个经过验证的业务对象或底层文件引用 |
| 底层产物 | `Artifact` | 哪些文件或媒体已经被系统登记；它不等于客户产品中的“创作资产” |

客户产品面的业务术语另外固定为：

| 客户名称 | 对应事实 | 边界 |
| --- | --- | --- |
| 我的资产 | 客户明确上传或导入的资料与文件夹组织关系 | Runtime 只读取固定资料引用，不拥有文件处理或组织状态 |
| 任务输入 / 项目参考 | 搜索候选、`SourceRevision`、`KnowledgeObject` 和灵感等引用 | 只作为当前或后续任务的输入，不自动进入客户资产 |
| 创作结果 | 人物原型、剧本、分镜、图片和视频生成结果的目录投影 | Runtime 只保存输出引用；只有 `confirmed` 和 `delivered` 可复用 |
| 交付作品 | `DeliveryPackage` 及其文件引用 | 使用独立交付视图，不复制成新的资产事实 |

详细决策由 [ADR-0013](../../foundation/decisions/ADR-0013-customer-result-asset-boundary.md) 与 [ADR-0014](../../foundation/decisions/ADR-0014-customer-asset-surface.md) 拥有；V8 只定义 Runtime 如何引用这些事实，不复制客户资产分类或状态机。

以下对象用于支撑上述核心模型：

| 内部对象 | 用途 |
| --- | --- |
| `JobPlanRevision` | 保存不可变的执行方案版本和执行图定义 |
| `AgentInstance` | 记录参与执行的逻辑智能体身份，不等同于一直运行的进程 |
| `ContextView` | 固定某次执行尝试允许读取的最小资料范围 |
| `Checkpoint` | 记录可以安全继续执行的逻辑位置 |
| `SideEffectRecord` | 记录发给服务商、发布系统等外部系统的操作及核对结果 |
| `JobEvent` | 按顺序记录执行过程中发生的状态变化 |
| `StageRun` | 向现有页面投影业务阶段进度，不作为 V8 调度依据 |

## 3. 业务任务、执行实例、执行步骤与执行尝试

四层对象的关系如下：

```text
业务任务 WorkTask
└── 执行实例 JobRun [1..n]
    ├── 执行方案版本 JobPlanRevision
    │   └── 执行图 DAG
    │       └── 执行步骤 NodeRun [1..n]
    │           └── 执行尝试 RuntimeAttempt [1..n]
    ├── 共享状态
    ├── 上下文视图、检查点和事件
    └── 输入快照、输出引用、人工审批节点和外部操作记录
```

### 3.1 业务任务（`WorkTask`）

业务任务保存用户意图、标题、内容类型、输入资料、期望产物、所属项目、团队空间、标准作业流程和风险配置。它回答“用户要完成什么”，不记录某个执行实例的运行状态。

同一项业务任务可以先后产生多个执行实例。V8 首版的每个执行实例都必须关联一项业务任务，暂不提供脱离业务任务的通用执行接口。

### 3.2 执行实例（`JobRun`）

执行实例保存一轮执行采用的输入快照、执行方案、运行环境、权限、预算、状态和事件位置。它回答“这一次具体怎样执行、当前运行到哪里”。

进程短暂中断、等待结束或执行步骤重试时，原执行实例继续运行。只有整次执行结束后重新发起，或者需要从已确认位置尝试另一条路线时，才创建新的执行实例。新实例可以引用允许继承的不可变数据，但不能覆盖原实例的历史。

执行实例进入终态后不能原地回退。创建重试、分支或重放实例时，仍要重新检查权限、审批有效性、资源和预算。具体字段、状态机和创建幂等规则见 [03：运行时领域模型与执行图](./03-runtime-domain-and-execution-graph.md)。

### 3.3 执行步骤（`NodeRun`）与执行尝试（`RuntimeAttempt`）

执行步骤对应执行图中的一项具体工作，可以由智能体、普通程序、外部服务商、人工审批节点或确定性汇总逻辑完成。每个执行步骤固定自己创建时采用的执行方案版本、输入输出要求和依赖关系，后续调整不能悄悄改写已经开始或完成的步骤。

执行尝试记录执行步骤的一次实际运行。同一执行步骤因为等待后恢复、执行许可过期或符合策略的重试，可以产生多个执行尝试；增加执行尝试不等于创建新的执行步骤。

## 4. 执行方案与执行图（DAG）

`JobPlanRevision` 保存一版完整且不可修改的执行方案，包括执行步骤、先后关系、人工审批节点、输入输出格式、执行方式、资源和失败策略。执行开始后的调整必须形成新的方案版本和执行图版本，旧版本继续保留。

V8 允许在运行中提出受限的执行图调整，但调整必须由服务端校验并作为一个整体提交：

- 只能新增执行步骤或依赖，或者取消尚未取得执行许可的待执行步骤。
- 不能修改已经开始或完成的执行步骤、输入输出格式、权限和预算。
- 调整后的执行图仍必须无环，不能跨业务任务引用。
- 步骤数量、层级、并行数量、可用工具、服务商和预算不能超过预先设定的上限。

因此，“动态”表示系统可以根据已确认结果调整后续工作，不表示智能体可以任意改流程。首版不支持图内循环、无限递归、任意条件脚本或用户自定义代码。详细规则见 [03：运行时领域模型与执行图](./03-runtime-domain-and-execution-graph.md)。

## 5. 共享状态、上下文与输出引用

### 5.1 共享状态

共享状态用于保存执行实例内多个执行步骤需要共同读取或更新的结构化数据，例如已批准的受众方向、各方向进度和候选质检结果。它不能是一篇由智能体自由改写的 Markdown 文档，也不向智能体提供通用 SQL 或数据表结构修改权限。

每组共享状态都要绑定固定的数据格式、读写权限、写入规则、容量上限和修改历史。并发更新时，服务端根据版本执行原子检查；版本不一致就拒绝写入，执行步骤必须重新读取后再处理，不能让后提交的数据静默覆盖先提交的数据。

共享状态的实现对象包括 `StateCollection`、`StateRecord` 和不可修改的 `StateMutation`。大段正文、媒体文件和其他大对象不直接写入共享状态，只保存受控引用。详细设计见 [05：共享状态、上下文与故障恢复](./05-state-context-and-durability.md)。

### 5.2 上下文视图（`ContextView`）

上下文视图记录某次执行尝试当时允许读取的输入、共享状态版本、相关事件、工具和预算。每个智能体只读取完成当前执行步骤所需的最小资料，不自动获得整项业务任务的全部对话和数据。

Codex 线程和 Claude 会话可以用于恢复智能体对话，但对话记录只用于观察执行过程，不能代替共享状态、输出引用或业务审计记录。即使原会话无法恢复，也要能够根据已持久化的上下文视图和业务记录创建新会话继续工作。

### 5.3 输出绑定与底层产物

执行步骤通过 `JobOutputBinding` 引用经过格式、摘要、归属和权限校验的业务结果。媒体或文件使用 `ArtifactRef`，人物、剧本和分镜等结构化结果使用对应业务对象的固定 `subject_ref + version + digest`。Runtime 不把大段正文或未经验证的 URL 塞进运行状态。

执行步骤成功只表示它满足了自己的输出要求，不表示结果已确认、可复用或可交付。生成结果是否进入客户“创作结果”，由业务事实生成的结果投影决定；是否可复用只由 `confirmed` 或 `delivered` 推导。客户“我的资产”中的文件处理状态由资料拥有域决定。正式交付仍以底层产物、审核记录、人工审批节点和 `DeliveryPackage` 为准。

项目参考使用输入快照和上下文引用，不创建输出绑定；`DeliveryPackage` 使用交付关联，不伪装成第六种结果资产。

## 6. 人工审批、外部操作与继续执行

人工审批节点（`Gate`）必须记录负责人、输入版本、审批决定、理由、时间和过期规则。上游输入发生变化后，旧审批不能自动批准新的内容。智能体不能替人批准事实、素材权利、费用、脚本、分镜或最终成片。

发给视频服务商、发布系统或邮件系统的请求会在 ContentCloud 之外产生实际影响。`SideEffectRecord` 记录操作意图、请求、结果和核对状态。网络超时只说明系统没有收到明确结果，不能据此认定对方没有执行并直接重试。

检查点（`Checkpoint`）记录已经完成的执行步骤、共享状态版本、事件位置和输出引用，用于中断后继续或创建新的执行实例。它不是进程内存备份，不能撤销已经产生的费用、已经发送的请求或已经发布的内容。

## 7. 哪条记录说了算

同一项执行会同时产生业务状态、运行状态、内容结果和外部操作。每类事实必须有唯一的权威来源：

| 要回答的问题 | 权威来源 | 其他对象的边界 |
| --- | --- | --- |
| 用户想完成什么 | 业务任务（`WorkTask`）和已批准输入 | 执行实例只引用，不复制用户意图正文 |
| 本次采用哪套执行方案 | `JobPlanRevision` | 执行步骤记录自己采用的方案版本 |
| 某个步骤是否成功 | 执行步骤（`NodeRun`）、执行尝试（`RuntimeAttempt`）和 `JobEvent` | `StageRun` 只展示对应的业务阶段 |
| 哪些资料属于我的资产 | 工作区资料拥有域、文件版本和组织关系 | Runtime 只保存固定资料引用，不修改文件夹或处理状态 |
| 哪些内容是任务输入或项目参考 | 来源、知识、素材等拥有域和 `WorkTask` 输入快照 | Runtime 只保存固定引用，不自动将其转换为客户资产 |
| 生成结果能否进入创作结果并被复用 | 人物、剧本、分镜、媒体等业务事实及 `CreativeAssetCatalogItem` 投影 | `JobRun` 和 `NodeRun` 只提供输出引用与执行血缘，不写可复用状态 |
| 内容能否进入交付 | 底层产物（`Artifact`）、审核记录、人工审批节点（`Gate`）和 `DeliveryPackage` | 业务任务和执行实例只展示结果状态 |
| 智能体当时看到了什么 | 对应版本的 `ContextView` 和摘要 | 完整对话记录不是权威业务数据 |
| 外部调用是否已经发生 | `SideEffectRecord` 和服务商核对结果 | 是否重试不能只看执行进程的退出状态 |

以下做法明确禁止：

- 把智能体维护的进度文档或完整对话当作共享状态。
- 在执行步骤的输出引用中保存任意正文或未经验证的 URL。
- 因为一次智能体会话成功，就直接认定执行实例成功或内容可以交付。
- 因为某个步骤读取了搜索结果、灵感或参考素材，就把这些输入自动投影为“我的资产”或“创作结果”。
- 由 Runtime 状态直接写入 `reusable=true`，或把 `DeliveryPackage` 复制成新的资产正文。
- 在原执行实例上覆盖旧执行方案来实现所谓“回滚”。

## 8. 与现有模型的兼容关系

V8 保留业务对象，但执行模型只保留 Runtime 权威表：

- 业务任务（`WorkTask`）继续作为用户侧业务对象；兼容期内现有状态和当前阶段字段继续可读，但 V8 不再只靠这两个字段调度执行图。
- 执行实例（`JobRun`）是 V8 新增的运行时聚合根。
- 执行步骤（`NodeRun`）使用独立 `runtime_node_runs`；公开 API 使用从 JobRun/NodeRun 生成的 `RuntimeRun` 只读模型，不对应独立执行表。
- 执行尝试（`RuntimeAttempt`）使用独立 `runtime_attempts`，记录执行许可、心跳、执行器和单次运行结果；旧 `RunAttempt` 已删除。
- `StageRun` 继续服务现有页面，由执行步骤、人工审批节点和输出结果生成业务阶段投影，不直接负责调度。

具体迁移和双写限制见 [08：迁移、测试与验收](./08-migration-testing-and-acceptance.md)。

## 9. 首版门槛与明确边界

一项营销活动的执行实例只有同时满足以下条件，才能进入交付：

1. 服务端完成资料来源、证据、知识和已批准快照的摘要及团队空间边界校验。
2. 每个执行步骤的输出都符合已发布的数据格式，并绑定系统认可的正式产物；无法识别的对象只能进入候选区。
3. 人工审批节点完整记录负责人、输入版本、审批理由和过期处理方式。
4. 可以沿执行图查清服务商任务、费用、视频版本、质检结果和最终产物之间的关系。
5. 失败、暂停、外部结果未知和恢复动作都能在运行诊断页面中找到原因和当前位置。

首版明确不做：

- 不做面向所有行业的流程市场，先验证营销视频和文章两种结构不同的内容流程。
- 不提供通用 SQL、任意数据表结构修改、任意条件脚本或修改团队权限的能力。
- 不把所有模型服务商密钥统一交给运行时；认证仍通过版本化配置、`SecretRef` 或受控的本地执行器完成。
- 不取消人工审批，也不让智能体自行发布共享状态的数据格式或执行配置。
- 不承诺外部操作一定只发生一次，也不承诺已经发生的外部操作可以原地撤销；首版提供重复提交保护、核对、补偿和创建新执行实例。

为证明运行时没有为视频流程写死，V8 还必须让文章复盘流程复用同一套执行实例、执行图、共享状态、上下文视图、检查点和外部操作机制：

```text
导入结果 -> 按渠道并行分析指标 -> 汇总归因结果
         -> 人工审批学习候选 -> 生成下一轮需求说明
```

文章流程只替换内容业务规则、数据格式和人工审批节点，不增加文章专用的调度表。
