# 07：运行诊断、可观测性与运维

> 阅读对象：平台运营、支持、设计、前端和运维人员。本文件描述授权人员怎样诊断执行进度，以及发生异常时可以做什么。

> 阅读路线：产品和设计重点阅读第 1-6、10 节；前端重点阅读第 2-7、10 节；运维重点阅读第 8-9 节。

当前实现：运营入口统一为 `/admin/jobs`，提供 JobRun 列表、准入冻结身份、节点概览、脱敏 AgentInstance/ContextView 摘要、事件时间线、外部副作用、检查点和服务端授权动作；列表和 nodes/effects/checkpoints 子资源提供服务端 `after/limit` 分页，events 提供单次上限和带 `Last-Event-ID` 的 SSE 增量游标；支持事件完整性校验与投影重建、从安全检查点创建新分支、`unknown` Effect 发起对账。重放与分支不调用 Harness 或 Provider，Agent 诊断不返回原始会话引用或上下文正文。完整执行图操作、Attempt/租约操作和支持案例仍按 V8 工作包逐步交付。

## 1. Runtime Explorer

Runtime Explorer 是平台运营控制台中的独立诊断产品，服从 [ContentCloud 平台基线](../../foundation/README.md) 的产品面分离规则。客户创作台只显示业务进度、客户可理解的阻断原因和支持编号；平台运营或支持人员在获得明确权限后，才从运营控制台关联到具体执行实例（`JobRun`）。

```text
平台运营控制台
  └── Runtime Explorer
      └── JobRun
          ├── 业务关联
          ├── 概览
          ├── 执行图
          ├── 智能体
          ├── 共享状态
          ├── 事件
          ├── 外部操作
          └── 费用
```

## 2. URL 与导航

目标态使用真实子路由，不再把页签只保存在 React 组件的本地状态中。当前入口：

```text
/admin/jobs
```

后续详情深链继续展开为：

```text
/admin/jobs/:jobRunId/overview
/admin/jobs/:jobRunId/graph
/admin/jobs/:jobRunId/agents
/admin/jobs/:jobRunId/state
/admin/jobs/:jobRunId/events
/admin/jobs/:jobRunId/effects
/admin/jobs/:jobRunId/cost
```

这样页面刷新、复制链接、浏览器前进后退和事故交接都能回到同一个视图状态。遇到未知或历史对象时使用安全的降级展示；前端不认识新的事件类型，也不能导致整个详情页失败。

## 3. 桌面布局

遵循 [DESIGN.md](../../../DESIGN.md)：采用冷白界面、深松绿侧栏和主要命令、对象分类色、中性边框、严格网格，并避免卡片嵌套。

```text
┌──────────────┬─────────────────────────────────────────────────────────┐
│ Content Work │ 活动 / 夏季新品短视频                    [暂停] [...] │

│              ├─────────────────────────────────────────────────────────┤
│ 任务         │ 概览 执行图 智能体 共享状态 事件 外部操作 费用          │
│ 审核         ├─────────────────────────────────────────────────────────┤
│ 交付         │ [筛选] [搜索]          等待 4  失败 1  未知 1           │
│              │                                                         │
│              │ 来源 ─┬─ 受众-1 ─ 脚本-1 ─┐                           │
│              │       ├─ 受众-2 ─ 脚本-2 ─┼─ 审核 ─ 人工审批           │
│              │       └─ 受众-3 ─ 脚本-3 ─┘                           │
│              │                                                         │
│              ├──────────────────────────────┬──────────────────────────┤
│              │ 当前节点                    │ 最近事件                 │
│              │ 负责人 / 尝试 / 上下文       │ 按时间排序的时间线       │
└──────────────┴──────────────────────────────┴──────────────────────────┘
```

页面分区使用全宽区块或网格，不把执行图工具套进概览卡片。执行图、表格、事件时间线和详情面板各自独立组织。

### 3.1 视觉语义

- Source `#007f78`、Knowledge `#397860`、Strategy `#3b6f8f`、Production `#b45b3c`、Review `#c24f5f` 只表示对象或阶段类别。
- Success、Warning、Danger 使用设计系统规定的语义色，不能靠阶段颜色猜测执行状态。
- 执行图节点使用固定的最小尺寸和轨道，状态、进度或长名称变化不能推动整张图重新排版。
- 主按钮只用于当前明确的动作；重试、取消、分支执行、对账等操作使用 Lucide 图标，并提供提示文字和可访问名称。
- 数据、ID、Token 和费用使用等宽数字显示，便于对齐和比较。

## 4. 移动端与 320px 下限

在 `390 x 844` 以及最低 `320px` 宽度下，不强行展示完整的二维执行图（DAG）：

```text
┌─────────────────────────────┐
│ 活动 / 夏季新品          [...]│
│ 运行中 · 34/92 · ¥128        │
├─────────────────────────────┤
│ [概览][执行图][事件] >       │
├─────────────────────────────┤
│ 执行图大纲                  │
│ ▾ 来源 · 已完成             │
│ ▾ 策略 · 3/3                │
│ ▾ 脚本 · 2/3 · 等待         │
│   脚本-3 · 服务商配额       │
│ ▾ 审核 · 已阻断             │
├─────────────────────────────┤
│ 当前节点详情面板            │
└─────────────────────────────┘
```

- 默认用分层大纲或列表表达依赖关系；可以提供“横向图”模式，但不能造成整页横向溢出。
- 页签可以横向滚动，同时保留可见焦点；标题和状态自然换行。
- 移动端的详情面板放在列表下方，或以全屏方式打开，不能遮住关键动作和下一条内容。
- 所有固定格式的控件都使用明确的 `minmax`、`aspect-ratio` 或固定轨道，动态文本不能改变工具栏高度。

## 5. 各视图职责

### 5.1 概览

只显示用户首先需要判断的信息：

- `JobRun` 状态、持续时间、执行图版本，以及运行中、等待中、失败节点的数量。
- 当前阻断原因、责任人、截止时间和唯一推荐动作。
- Token、费用，以及服务商和智能体并发量的已用、已预留和上限。
- 最近的检查点、最后一次成功进展，以及数据和事件延迟。
- 交付就绪度和业务侧人工审批节点；不能用执行实例的 `succeeded` 代替业务任务的 `delivered`。

### 5.2 执行图

- 执行图（DAG）节点及其必需或可选依赖。
- 业务阶段（`Stage`）分组、并行拆分集合、汇聚策略和执行图版本差异。
- 节点状态、执行器、尝试次数、资源等待原因和输出数量。
- 选中节点后显示输入摘要、`ContextView`、执行尝试（`Attempt`）、输出、子节点、外部操作和当前可执行动作。
- 大图先由服务端分页或分区；不能一次把 500 个节点的全部事件和完整执行记录加载到浏览器。

### 5.3 智能体

- `AgentInstance` 父子树、角色、执行适配器、模型和隔离配置、状态及激活次数。
- 只展示安全摘要和工具统计；完整执行记录需要额外权限，并且必须由用户明确打开。
- 展示 `ContextView` 摘要、可读取的状态集合和子节点预算，帮助定位权限或上下文不足。
- 宿主会话引用默认截断并脱敏，不能作为用户可编辑字段。

### 5.4 共享状态

- 按 `StateCollection` 展示数据结构版本、一致性模式、写入负责人、记录数和水位线。
- `StateRecord` 支持安全详情、版本历史和变更操作人查看。
- 比较并交换（CAS）冲突显示两个执行尝试（`Attempt`）、期望版本和当前版本，并提供重新读取动作。
- 大字段只显示产物元数据和经过授权的预览，不在表格中展开正文或媒体。
- 生产界面不提供自由 SQL、任意 JSON 覆盖或数据结构编辑器。

### 5.5 事件

- 按同一项执行内的序列号排序，支持按事件类型、节点、智能体、执行尝试、外部操作和时间筛选。
- 标出因果关联和请求关联，能够从错误跳转到导致错误的租约、工具调用或策略决定。
- 显示投影游标和延迟；事件到达不代表业务状态已经提交。
- 默认只显示脱敏后的事件内容；受限的原始产物必须通过单独权限查看。

### 5.6 外部操作

- 展示“已计划、已授权、执行中、结果不明、对账中、已确认、失败、补偿中”（`planned/authorized/executing/unknown/reconciling/committed/failed/compensating`）等状态。
- 展示请求摘要、重复提交保护键、服务商外部编号、费用和数据披露摘要。
- `unknown` 状态只提供“开始对账”，不提供“一键再次提交”。
- `committed` 只有在该外部操作类型支持补偿，且相应的人工审批节点已经通过时，才显示“请求补偿”。
- 补偿失败时必须显示人工运维手册和审计要求。

### 5.7 费用

- 按模型、服务商、节点、分支和时间汇总预估、预留、上报和对账后的费用。
- 预算接近阈值时，显示下一个将被阻断的节点，以及需要通过的人工审批节点。
- 不能把服务商预估费用和最终账单混成一个数字。

## 6. 当前可执行动作

页面上的操作按钮全部由服务端根据当前状态返回的“当前可执行动作”决定：

| 状态 | 可见动作 |
| --- | --- |
| `waiting(resource)` | 调整已获准的配额、切换到已批准的隔离配置、继续等待或取消 |
| `waiting(human_gate)` | 打开人工审批节点、批准、驳回或要求修改 |
| 可重试的节点失败 | 按原策略重试；必要时从检查点创建分支执行 |
| 不可重试的节点失败 | 查看证据；仅对可选节点允许跳过；也可创建分支执行或取消 |
| 外部操作 `unknown` | 开始对账、登记人工结果或升级处理 |
| 执行实例为 `paused` | 恢复或取消 |
| 执行实例已结束 | 查看、导出诊断，或从检查点创建分支执行 |

界面不存在“强制成功”（`force success`）、直接改状态、删除事件或清空外部操作记录的按钮。

高风险动作需要显示精确对象和影响：

- 取消是否会传播到正在运行的服务商作业。
- 分支执行从哪个检查点开始、复用哪些数据、哪些审批会失效。
- 补偿针对哪个外部对象，以及该操作是否确实可逆。
- 修改配额只影响当前执行实例，还是会影响租户策略。

## 7. SSE 与读模型

现有服务端推送事件（SSE）/进度机制演进为执行实例级增量通知：

```text
job_event_committed
node_projection_changed
resource_projection_changed
effect_projection_changed
gate_projection_changed
```

SSE 只用于提示页面刷新，不能作为状态依据。断线重连时，客户端携带最后一个游标，服务端补发有限窗口内的事件；如果窗口已经丢失，则重新获取 REST 读模型。页面必须显示数据对应的 `as_of_event_cursor`，避免把落后的投影误认为实时状态。

## 8. 指标、链路追踪与日志

### 8.1 指标

```text
job_runs_total{state,content_pack}
job_duration_seconds{result,content_pack}
node_wait_seconds{reason,executor_kind}
node_attempts_total{result,failure_class}
lease_expirations_total{executor_kind}
graph_patch_total{result,reason}
state_cas_conflicts_total{collection}
context_tokens{profile,node_kind}
resource_utilization{resource_key}
side_effect_unknown_total{effect_kind,provider}
side_effect_reconcile_seconds{effect_kind}
projection_lag_events{projection}
daemon_journal_backlog{device}
```

高基数字段（执行实例编号、执行步骤编号、提示词摘要、外部编号）不能放在指标标签中，应写入链路追踪或事件。

### 8.2 链路关联

每条日志和链路追踪都使用 `correlation_id` 关联：

```text
WorkTask -> JobRun -> NodeRun -> RuntimeAttempt -> Agent session/tool call
                                   |
                                   +-> SideEffectRecord -> ProviderAttempt
```

服务商原生链路只作为外部引用；ContentCloud 不假设 Codex 或 Claude 的链路与 `JobEvent` 具有相同的持久化能力和访问控制。

### 8.3 日志

- 记录结构化错误码、状态、耗时、对象 ID 和摘要。
- 不记录提示词正文、来源全文、密钥、运行令牌、签名 URL 或服务商原始凭据。
- 适配器的 stdout/stderr 必须限制大小并脱敏；完整诊断按租户策略作为受限产物保存。

## 9. 告警与运维手册

| 告警 | 条件 | 首个动作 |
| --- | --- | --- |
| 执行实例无进展 | 运行中的执行实例超过阈值没有新事件 | 检查等待原因、租约和投影延迟 |
| 租约频繁过期 | 同一节点多次过期 | 隔离执行器，停止领取新任务，保留本地日志 |
| 外部操作未知 | 超过对账截止时间 | 阻断重试，查询服务商并发起人工对账 |
| CAS 冲突激增 | 某状态集合冲突率异常 | 检查写入策略是否应改为只追加或指定汇总写入者 |
| 服务商资源饱和 | 配额长时间用满且队列持续增长 | 检查预算和公平性，不能绕过租户上限 |
| 事件投影延迟 | 游标差距超过阈值 | 降低事件发放速度，修复投影器，不修改权威状态 |
| 本地日志积压 | 守护进程 outbox 超过上限 | 只允许重新上报和恢复，暂停领取新任务 |
| 预算不一致 | 上报费用超过预留或预估阈值 | 停止该隔离配置的新外部操作，进入账单对账 |

## 10. 体验验收

- 在 `1440 x 1000` 和 `390 x 844` 视口完整走通主要流程；最低 `320px` 宽度不能出现页面横向溢出。
- 授权运营或支持人员最多经过两次主要操作，就能从支持编号或 WorkTask 定位到失败节点、最近错误或未知外部操作。
- 执行图包含 100 个节点时仍可筛选、选择和定位；动态事件不能造成布局跳动。
- 页面刷新和复制子路由后，仍保留当前视图、筛选条件和选中对象。
- 键盘可以完成页签切换、执行图大纲导航、打开详情面板和主要安全动作。
- 所有图标按钮都有可访问名称和提示文字；状态不能只靠颜色区分。
- SSE 断线、会话过期、两标签页并发操作和投影延迟都显示明确状态，不能显示虚假的成功结果。
- 未授权用户不能看到完整执行记录、共享状态值、服务商外部 ID 或费用详情。
