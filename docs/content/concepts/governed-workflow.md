# 内容审核与交付流程

Content Work OS 把“创作”和“确认”分开：项目文件夹里保存草稿和继续工作所需的内容，网页工作台保存提交版本、审核决定、已确认版本和操作记录。这样每个人都能看清当前版本，确认过的内容也不会被悄悄改掉。

下面括号中的英文是系统内部记录名，日常使用时不需要记住。

## 核心对象

| 对象 | 所在位置 | 含义 |
| --- | --- | --- |
| 草稿（`Local candidate`） | 项目文件夹 | 尚未提交的内容，可以继续修改 |
| 工作记录（`LocalRun`） | 项目文件夹 | 一次创作的输入、检查和输出 |
| 继续工作入口（`Handoff`） | 项目文件夹 | 换设备或换人后继续工作的入口 |
| 提交版本（`SubmissionRevision`） | 网页工作台 | 你明确提交、不会被悄悄改动的版本 |
| 审核决定（`Decision`） | 网页工作台 | 审核人的确认或退回决定 |
| 已确认版本（`ApprovedSnapshot`） | 网页工作台 | 经过审核、可以用于交付的固定版本 |
| 交付文件（`DeliveryPackage`） | 项目文件夹和网页工作台 | 根据已确认版本生成并检查过的文件 |

## 标准流程

```text
读取项目文件夹状态
  -> 选择或创建工作记录
  -> 固定本次使用的资料
  -> 生成草稿并检查
  -> 提交前确认
  -> 提交一个不会被悄悄改动的版本
  -> 网页工作台人工审核
  -> 形成已确认版本或退回修改
  -> 下载明确版本
  -> 继续修改或生成交付文件
```

## 四条不能混淆的边界

1. **保存在电脑里不等于提交到网页。** 只有明确点击提交（`publish`）才会产生提交版本。
2. **提交不等于审核通过。** 只有网页工作台的人工确认才会产生已确认版本。
3. **审核通过不等于交付完成。** 交付文件还要从准确版本生成并通过检查。
4. **交付完成不等于外部发布。** 外部平台的草稿、预览、提交和发布成功仍是不同状态。

## 为什么每次新对话都读取项目文件夹

聊天记录不是唯一准确信息来源。`workspace_context` 会读取保存的项目状态、当前内容版本、工作记录、继续工作状态和待修复问题。安装连接工具或换电脑后，应在同一个项目文件夹中新建对话并重新读取上下文。

## 记忆与事实的边界

Content Work OS 会帮你记住项目背景，但“记住”不等于“已经确认”。项目文件夹、工作记录、继续工作入口和知识页面共同保存可以继续使用的内容；它们都保留来源，方便你检查和更新。

- 记忆内容可以帮助开始下一次工作，但不会自动修改草稿、提交版本或审核结果。
- 原文件或已确认内容变化后，旧记忆会标记为过期，不能覆盖当前版本。
- 删除或重建本地记忆后，系统仍应能从项目文件夹和允许读取的网页版本恢复。
- 需要查找记忆时，默认只读取当前项目范围，不会把正文发送到远程服务。

需要手动维护记忆时，可使用 `workspace memory status` 查看状态、`workspace memory rebuild` 重新整理，或使用 `workspace memory clear --yes` 清除可重新生成的缓存。普通创作不需要了解这些命令。

## 平台能看到什么

Content Work OS 不会替你运行连接工具、制作工具或上传的代码，也不会扫描你的电脑。平台只能看到你明确提交的内容。
