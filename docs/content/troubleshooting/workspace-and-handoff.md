# 项目文件夹连接与继续工作故障排查

按页面显示的状态逐项排查，不要反复安装、猜测路径或复用旧聊天绕过错误。

## Web 一直显示未连接

检查以下条件是否全部完成：

1. 连接记录（`ConnectSession`）尚未过期或取消。
2. 浏览器中已确认电脑上显示的匹配短码。
3. 页面提供的工具名称、版本和检查结果均正常。
4. 项目文件夹诊断通过。
5. 电脑连接记录已成功登记（`workspace.register`）。

连接成功不代表已有文件被上传，也不代表后台程序已启动。

## 新对话看不到 Content Work OS 工具

- 确认安装或工具变更后已经新建对话。
- 确认新对话打开的是包含 `.contentcloud/workspace.yaml` 的同一个项目文件夹。
- 调用 `workspace_context`，不要从旧聊天复制项目状态。
- 只有结果明确为 `repair_required` 时才调用 `workspace_doctor`。

## `workspace_context` 找到多个项目或多次工作记录

不要猜测。选择唯一包含目标 `.contentcloud/workspace.yaml` 的项目文件夹；存在多次未完成的工作时，先查看每次工作的目的、阶段和更新时间，再选择准确的 `run_id` 后继续。

## “在连接工具中继续”不可用

- 确认项目至少连接了一台工作电脑。
- 确认所选连接工具的“在网页和电脑之间继续工作”状态为“可用”。
- 当前只有 Codex 支持从网页继续工作；其他工具显示“即将支持”是预留状态。
- 审核修订入口还要求目标内容版本存在评论或处于“待修改（`changes_requested`）”状态。

## 继续工作后内容不匹配

停止修订并核对：

- 项目 ID。
- 目标内容类型和编号。
- 完整版本摘要（`sha256:`）。
- 当前项目文件夹连接状态。

继续工作只会预填连接文字，不会自动发送或选择本机项目文件夹。记录不一致时不得把意见应用到其他版本。

## 提交（`publish`）出现冲突

重新读取项目文件夹和网页状态，保留当前草稿，不要覆盖最新内容版本。再次执行检查和 `publish_preflight`，并只对新的修改范围请求确认。

## 仍无法恢复

保留错误提示、问题编号、失败检查编号和脱敏诊断包。不要把密钥、Cookie、绝对路径、客户正文或电脑安全存储内容粘贴到问题描述中。
